# 终端转录

> 落地 [gaps.md](gaps.md)「三、终端转录：这本来就是终端的活」。
> 代码：`src/poltergeist/Transcript.zig`、`src/poltergeist/daylog.zig`、
> `src/termio/Termio.zig`（抽头点）、`src/config/Config.zig`
> （`poltergeist-terminal-log`）。

## 一句话

`chat.jsonl` 记的是 **agent 之间说了什么**；这一份记的是**终端里真正跑了
什么、输出了什么**。第二天早上要查「为什么这个 agent 半夜开始死循环」，
前者只有它自己的自述，后者才是证据。

## 为什么必须是 Polter 来记

Claude Code 有自己的 transcript，Codex 是另一套，而一个 `npm run build`、
一个 `cargo test`、一个手敲的 `ssh` **根本不存**。靠被托管的程序自己存，
等于记录只对「碰巧会存的那些程序」存在 —— 那不叫记录，叫运气。

Polter 是终端：每一个字节都从它手里过。它是这台机器上唯一能做出一份
**对下面跑的任何东西都成立**的统一记录的位置。

## 录哪一层：滚出去的行

三个候选层次的代价差几个数量级：

| 层 | 是什么 | 代价 |
| --- | --- | --- |
| 原始 pty 字节流 | 完整、可重放 | **量由被托管程序的刷新率决定**。一个 spinner 以 10fps 转八小时能写出几百 MB 的零信息，而刷新率不是 Polter 管得着的 |
| **滚出去的行** | committed 到 scrollback 的那些 | 人可读，**天然去掉了重绘**：spinner 转十万次最后只留下一行 |
| 按命令分段 | 用 shell integration 的语义信号做边界 | 需要被托管程序配合，不是所有终端都有 |

**录第二层。** 本仓刚被一个 263GB 的编译缓存咬过，不该再造一个「量由
别人决定」的写入源。第二层的语义也正好是对的：记录的是**「输出过什么」**，
不是「屏幕做过什么动画」。

## 两条已知代价（是设计，不是漏记）

1. **全屏 TUI 在转录里近乎空白。** `vim`、`htop`，任何用 alternate screen
   的程序都不往 scrollback 写东西，所以它们几乎不留痕。这是对的 —— 你不会
   想要 `htop` 的每一帧 —— 但看起来像漏了，所以写在这里。

2. **最后一屏是 pty 挂断的时候才落盘的，不是 Termio 拆除的时候。** 一行是
   滚出去之后才被记下的；活动屏上还没滚出去的内容由 `Transcript.finish`
   用更宽的 `.screen` 边界补写一次（`src/poltergeist/Transcript.zig:349-359`），
   触发点是 reader stage 退出，即 pty 挂断（`Termio.finishTranscript`，
   `src/termio/Termio.zig:762-779`）。因此正在跑的终端，它的最后一屏还不在
   文件里。

   **当初写的「Termio 拆除时」在真机上不成立，这一句是被实测改掉的**：
   `ghostty -e` 下窗口关闭和进程退出是同一瞬，什么都还没来得及 unwind，
   Cmd-Q、崩溃、被 kill 是同一个故事——**每个终端都在丢最后一屏**。
   `deinit` 仍然留着走这条路，是为了另一种顺序：子进程还活着而 surface 先被
   关掉，那时候没有挂断，拆除才真是最后一次机会。谁先到谁算数，靠一个
   `closed` 标志。

## 布局

和群聊记录完全一致，走的是同一份代码（`daylog.zig`）：

```
~/.local/state/polter/
  chat/
    kairos-15r/2026-08-28.jsonl        群聊
  terminals/
    0000000000007f3a-kairos/           一个终端一个目录
      2026-08-28.jsonl
```

一行一条 JSON，字段 `at_ms` / `text`。**同一种格式、同一套读法**，
`less` / `grep` / `jq` 直接能用。

**目录名 = `<16 位十六进制 surface id>-<标题>`。** id 在前，因为它才是身份：
标题是 shell 随时会改的东西（很多人的 shell 每 `cd` 一次就改一次），拿它
当目录键会把一个终端的一夜切成十几个目录。标题在后，是因为
`ls ~/.local/state/polter/terminals/` 全是十六进制的话，第二天早上没人用得了。

标题在**第一行落盘时**取一次就定死（`Transcript.rename`）：终端刚起来的那
一瞬间还没有标题，所以不能在 `init` 时取；取完之后再改也不认，否则目录会
在一夜工作的下面挪走。

跨重启是新的 id，也就是新的目录 —— 这是诚实的：那本来就是两个终端。

## 共用而不是各写一套

`encodeGroup`（→ `daylog.encodeSegment`）、`dayOf`、`Tree` 这三样原来住在
`ChatLog.zig` 里，做这一节时把它们提到了 `src/poltergeist/daylog.zig`。

**理由不是「别重复代码」。** 终端名和群名是同一类东西 —— 用户起的、可以
包含任何字节、要变成一个目录名。如果各写一套编码，那么**同一个状态目录里
就会并存两套规则，而它们对同一个名字给出不同的目录**。那不是重复，是两个
人对着同一个目录说不同的话。

提出来之后必须登记进 `src/poltergeist/main.zig` 的 `test {}` 块 —— 那是本仓
的既定约定（见该文件里的注释：曾有五个模块因为没登记而「测试一条不跑却
显示全绿」）。

## 密钥：不假装能洗干净

- 文件 `0600`，和 `chat.jsonl` 一样。
- **默认开，可以关**：`poltergeist-terminal-log`。
- **不做脱敏。** 一个能洗掉九成密钥的洗涤器比不洗更糟 —— 它制造「这份文件
  可以随便发」的错觉，而剩下那一成照样会被发出去。这是本机上的一份本机
  文件，就按本机文件对待（和你的 shell history 同一档）。
- 和群聊记录一样**不轮转、不裁剪**，所以它随终端的输出无限增长。

## 热路径

抽头点是 `Termio.processOutputLocked`，每个 pty 字节的必经之处，跑在 IO
线程上。**绝不为记录牺牲输入延迟**是本仓第一条红线，所以：

- 不够 `flush_ms`（250ms）的普通一次读只付**一次减法和一次分支**；
  比较用的时间戳是那个函数本来就已经取过的那一个。
- 真正做的活正比于**实际 committed 的输出**，而不是看见的字节数 ——
  一个永远在重绘自己的程序 commit 不出任何东西，因此在这里的开销是零。
  这正是「录滚出去的行而不是录字节」在性能上的第二个理由。
- 墙上时钟只在真的要落盘时读一次（至多每 250ms 一次），节流本身用的是
  调用方传进来的单调时钟。

## 还没做

- **插件实时事件通道对接。** 终端事件将来要送进 W2 正在做的那条通道；
  这一份是**核心功能，不依赖任何插件**，所以先独立做完。
- **按命令分段（第三层）。** `command_finished` 能给出起止、退出码和行数，
  可以当索引叠在这份记录上。
- ~~空闲时的定期 flush~~ —— **已做，而且没有用定时器。** 抽头挂在 pty 读事件上，
  所以「打完一屏然后干等着」这个终端最常见的形状下，再也没有一次读来触发它，
  已经 committed 的行会一直留在内存里。做法是由 reader stage 在「本轮没有 batch
  可解析」时叫一次 `Termio.flushTranscript`（`src/termio/Termio.zig:742-759`），
  那是这台机器上唯一知道「一段输出结束了」的地方。`Transcript.flush`
  （`src/poltergeist/Transcript.zig:320`）自己是节流的，所以一串连续的 batch
  不会变成一串写。

  这个洞有多大值得记一句：没有它的时候，一个只印过一屏就安静下来的终端，
  **整个转录目录根本不会被创建**。
