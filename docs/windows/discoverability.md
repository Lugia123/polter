# 可发现性：一个没见过它的人找不找得到

**这一篇和别的判据不是一类。** `status.md` 里那些问「这个功能对不对」，
这一篇问「**一个不知道它存在的人，会不会找到它**」。

写它的直接原因：**用户十分钟里发现了三处缺失，而我们内部的判据一条都没发现。**
不是判据不严——今天那批真机判据每一条都带着可复核的读数。是它们**全都在问功能**，
而三处缺失里没有一处是功能坏了。

## 零、⚠️ 测的人是仪器的一部分，而知情的测试者是一台坏仪器

**先立这条，因为它决定了后面每一条怎么写、由谁跑、以及为什么跑错一次就报废。**

功能判据可以由写它的人跑，跑一万次结果一样。**可发现性判据不行**：它测的是
「一个不知道答案的人会做什么」，而**跑它的人一旦知道了答案，这台仪器就永久失准**。

三条后果，都是流程要求，不是建议：

1. **每条判据必须写明「测试者必须不知道什么」**，而不只是「要观察什么」。
   不写这一栏的判据不算写完。
2. **一个人对一条判据只能跑一次。** 修完之后再让同一个人跑，他会直奔上次找到的
   地方——**你得到的是「修好了」，而实际测的是「他还记得」。**
3. **所以第一次的记录就是产物**：逐字记下他先做了什么、第几秒、试了几次才成功。
   **拿不到第二次第一印象。** 记录放在本文末尾。

**这是本仓库那条通用规矩的一个实例**——「如果被测的那个东西是错的，这条判据会
看见吗」。**如果跑判据的人本来就知道去哪点，答案是不会。**

> **由此得到一个此前没有过的性质：这批判据是消耗品。**
> 别的判据可以重复跑到天荒地老；**这五条每跑一次，可用的测试者就少一个。**
> 它改变的不只是判据怎么写，是**它们总共能被用几次**。

### 谁已经不合格

写过、读过、或者调试过这套界面的人**全部不合格**，包括发现那三处缺失的人自己——
**他现在知道右键没反应，所以他再也测不了 D2。**

## 一、判据

每条四栏：**测试者必须不知道什么** / 指令 / 观察什么 / 通过条件。
外加一栏**谁能判**，因为其中几条机器判不了，而那不是判据不合格。

### D1 · 开出第二个标签

| | |
| --- | --- |
| **必须不知道** | 任何快捷键；标签条上有没有可点的东西 |
| **起始状态** | 全新启动，一个标签，不给任何提示 |
| **指令（逐字念）** | 「再开一个终端标签。」 |
| **观察** | 他第一个动作是什么；多久；成功前试了几次 |
| **通过** | **30 秒内，只用鼠标，开出第二个标签** |
| **不通过** | 去翻菜单、键盘乱试、或者问「怎么开」 |

⚠️ **「`new_tab` action 可达」不是这条的通过条件。** 它今天可达，而这条不通过——
**两件事都为真，只有一件是用户的处境。**

**谁能判**：**人**。脚本能验「点那个位置会不会出新标签」，**而那预设了已经知道位置
在哪**——那是功能判据，不是这条。

### D2 · 选中文字之后想复制

| | |
| --- | --- |
| **必须不知道** | `Ctrl+Shift+C`；右键会不会有反应 |
| **起始状态** | 终端里已经有一段选中的文字 |
| **指令** | 「把这段文字复制走。」 |
| **观察** | **他的第一个动作** |
| **通过** | 第一个动作就得到反馈（菜单出现，或者选中即复制并有提示） |
| **不通过** | 第一个动作什么都没发生 |

⚠️ **`Ctrl+Shift+C` 通不通和这条无关。** 如果他先按右键而右键什么都不发生，
**那就是缺陷，哪怕键盘那条路是好的**——用户不会先按一个他不知道存在的组合键。

**谁能判**：**一半机器**。「右键之后有没有菜单窗口出现」脚本可验；
**「他会不会先按右键」只能靠人**，而那才是这条要问的。

### D3 · 找到一条不知道名字的命令

| | |
| --- | --- |
| **必须不知道** | 命令面板存在；它的快捷键 |
| **指令** | 「你想看看这个终端都能做什么，去找。」 |
| **观察** | 他找到了什么；有没有任何一条路通向一份可浏览的清单 |
| **通过** | **存在一条不需要预先知识的路**，通向那些命令 |
| **不通过** | 唯一的路是一个他无从得知的快捷键 |

⚠️ **这条要能区分两种不通过**，因为在用户那里它们一样、下一步完全不同：

- **有入口但打不开** → 缺陷，可修；
- **根本没有入口** → **缺失，要设计**。

**谁能判**：**人**，但有一个机器能先答的前置问题，见第三节。

### D4 · 关掉一个标签

| | |
| --- | --- |
| **必须不知道** | `Ctrl+Shift+W` |
| **指令** | 「把第二个标签关掉，别关掉整个窗口。」 |
| **通过** | 只用鼠标，30 秒内，**而且没有误关整个窗口** |
| **不通过** | 关掉了窗口，或者找不到 |

**为什么有这条**：它是 D1 的对偶，而且**它是五条里唯一一条失败会丢数据的**——
找不到关标签的人会去点右上角的 ×。

**谁能判**：人；「误关窗口」这个事件机器能记（进程退出）。

> ⚠️ **上一版这里写着「已知风险：标签一多关闭叉就会消失」。那句话是错的**，
> 而且它是一条没有算过就报出去的推论，经由主控转达、被忠实地记进了这份文档。
> 原文见 `556fee100`。**关闭叉不会消失**，理由如下，而理由不必被相信——
> 它下面那两条测试会替你跑。
>
> `strip.rs` 里是这两个常量，互相之间没有任何代码把它们联系起来：
>
> ```rust
> const TAB_MIN_W: i32 = 60;                      // strip.rs:42
> fn close_side_px(scale: f64) -> i32 { (14.0 * scale) as i32 }
> fn tab_shows_close(tw: i32, scale: f64) -> bool { tw > close_side_px(scale) * 4 }
> ```
>
> `layout()` 从不返回比 `TAB_MIN_W * scale` 更窄的标签，而阈值是 `56 * scale`：
>
> | DPI | scale | 最窄标签 | 关闭叉阈值 | 余量 |
> | --- | --- | --- | --- | --- |
> | 96 | 1.0 | 60 | 56 | **+4** |
> | 120 | 1.25 | 75 | 68 | **+7** |
> | 144 | 1.5 | 90 | 84 | **+6** |
> | 192 | 2.0 | 120 | 112 | **+8** |
> | 240 | 2.5 | 150 | 140 | **+10** |
> | 288 | 3.0 | 180 | 168 | **+12** |
> | 384 | 4.0 | 240 | 224 | **+16** |
>
> 取整最多在两边各吃 1 像素，翻不过这 7% 的余量。
>
> **这段话不需要被相信，因为它有会变红的东西**（`strip.rs` 的
> `mod close_affordance_tests`）：
>
> - `the_close_cross_survives_the_narrowest_tab_at_every_scale` —— 8 个 DPI 档，
>   400px 里塞 200 个标签；把 `TAB_MIN_W` 改成 `50` 它就红（量过：2 failed）。
> - `the_margin_between_the_two_constants_is_named` —— 钉住 `TAB_MIN_W > 56`；
>   把 `14.0` 改成 `16.0` 它就红（量过：1 failed）。
>
> **所以 D4 现在没有已知的触发条件。** 但 D4 的失败形状不变——找不到关标签的人
> 会去点右上角的 ×，**而那会带走其它所有标签**。**跑 D4 时仍然必须记下当时开了
> 几个标签**：否则「他关掉了整个窗口」这个读数，分不清是「没找到」还是「当时
> 根本没有可找的东西」。

### D5 · 回到刚才那件事

| | |
| --- | --- |
| **必须不知道** | 有没有历史、分屏、还是别的 |
| **指令** | 「你刚才在第一个标签里跑过一条命令，回到它那儿去。」 |
| **通过** | 能在标签之间切换，只用鼠标 |

**为什么有这条**：D1 只测「造得出来」，**没测「回得去」**——一个能开标签、但看不出
哪个是当前标签的界面，D1 会通过。

**谁能判**：人。

## 二、三条防止它们滑回功能判据的规矩

这类判据最容易滑回功能判据，**因为功能判据能被日志验证，而这些不能**。

**R1 · 判据的主语必须是人，不是功能。**
「右键菜单存在且包含 N 项」是功能；「他选中文字后的第一个动作能不能得到反馈」
是可发现性。**一条判据如果不提到人做了什么，它就不是这一类的。**

**R2 · 通过条件里不许出现只有内部人知道的名词。**
`new_tab`、`toggle_command_palette`、`Ctrl+Shift+T` 都不许出现在**通过条件**里
（可以出现在「必须不知道」里）。**用一个用户不知道的词来定义通过，测的就不是用户。**

**R3 · 「机器验不了」要写进判据，不是省略掉。**
每条都标了「谁能判」。先例是全局热键那条判据：它写不了，于是**在脚本里打一行说
自己覆盖不了**，把那一步交回给人。**那是正确处置，不是缺陷。**

> ⚠️ **硬把 D1 写成一行日志能验的东西，你会得到一个「通过」而用户照样找不到。**
> 那比没有判据糟，因为它看起来验过了。

## 三、不需要人的部分：先榨干

**这批判据里那个稀缺资源是「一个没见过它的人」。** 所以凡是静态就能定案的，
先定掉——**如果一条判据在任何测试者面前都必然不通过，这个结论不该花掉一个人。**

> ## ⚠️ 本节三条结论已于 **2026-09-01 全部翻转**，原文保留在下面
>
> 三条入口在几十分钟内被实现了。**保留原文而不是改写，因为「曾经必然不通过、
> 现在有了入口」正是那个稀缺测试者要看的背景**——他要判断的是这些入口能不能被
> 发现，而不是它们存不存在。
>
> **⚠️ 翻转不等于通过。** 静态原本答掉了「通不通过」；现在它连这个也答不了，
> **它只答了「入口存在」**。D1 问的是「不看文档的人 30 秒内能不能用鼠标开出第二个
> 标签」——**一个存在的「+」和一个能被发现的「+」不是一回事。**
>
> | | 2026-09-01 的结论 | 2026-09-01 复核 |
> | --- | --- | --- |
> | §3.1 | `Hit` 四项穷举，无「新建」→ D1 必然不通过 | **`Hit::New` 已存在**，结论作废 |
> | §3.2 | 一条右键消息都没有 → 右键不产生任何东西 | **`WM_CONTEXTMENU` ×4、`WM_RBUTTONUP` ×1**，结论作废 |
> | §3.3 | 通向命令面板只有两条路，都是键盘 | **第三条已存在**：`ctxmenu.rs:60` 的 «All commands…» |
>
> 三条都由重新读代码得到，不是转述。

### ⭐ 这次翻转本身是一条教训：**文档断言「代码现在是什么样」，没有任何东西会为它变红**

`strip.rs` 的 `Hit::New` 上有一句注释，指名说本文 §3.1 引用的那个枚举需要更新。
**那是对的做法，而且它自己就不够**——

> **它只提醒改代码的人，不提醒读文档的人。**

本仓库有一条「指名，不要指位置」的规矩，那是**文件内**的版本：一个引用应当指向
它所指的东西的名字，而不是它此刻的位置。**这里是跨文件的版本，而跨文件那一半
没有工具能覆盖**：

- 代码里指向文档的注释，**只有改代码的人会看见**；
- 文档里那句「代码现在是这样」，**没有任何东西会为它变红**——它不参与编译，
  不参与测试，`grep` 也查不出它已经过期。

这是那一族洞的第三个形态。前两个是注释断言「某处已经做了某事」、注释断言
「某事是因为某事」；**这个是文档断言「代码现在是什么样」。**

**暂时的对策只有一条，而且很弱**：凡是引用代码结构的段落，**标注日期并写明是
穷举还是抽样**——让读者至少能看出这段话有多旧。下面每一条都照做了。

## 四、这批判据自己的地板：**现在还没有**

按那条通用规矩自审——「如果那三处缺失还在，这五条会看见吗」：

| 用户发现的缺失 | 哪条会看见 |
| --- | --- |
| 右键菜单没有 | D2 ✅ |
| 标签条没有「+」 | D1、D4 ✅ |
| 那批命令没有入口 | D3 ✅（而且能区分「没入口」和「入口坏」） |

**三处全覆盖——但这既不是巧合也不是本事：判据是照着已知的三处缺失写的，
所以它们必然覆盖。**

> **真正的检验是它们能不能发现第四处。**
> 而那只有在一个没见过这套东西的人面前跑一次才知道。
> **所以这五条的地板，只有第一次真跑才有。在那之前，本节是一句声称。**

## 五、第一次真跑的记录

**还没有跑。** 跑完之后逐字记在这里：他先做了什么、第几秒、试了几次、
以及**他说过的原话**——尤其是他放弃之前的最后一句。

记录本身就是产物；**它不能被重跑，所以它不能被补录。**

## 六、那 13 条外观判据的 D 版本会问什么（2026-09-01）

R2 审查把现有 42 条判据分成三类：功能 24、**外观·行为 13**、可发现性 5。
中间那 13 条是最难看见的一类——**不含内部名词、人能判、看起来很像用户视角，
而它们全都预设了用户已经知道那个东西在哪。**

**这一节不改任何判据。** 它只给每一条并列一句「同一件事，主语换成一个不知道
答案的人」，**因为改不改由写它们的人定，而在决定之前他得先看见那个东西长什么样。**

⚠️ **标注规则**：标「**不过**」不需要证据——它只是一个待验的怀疑；
标「**过**」需要证据。**给不出本产品证据的一律标「未知」，哪怕惯例很强。**
（这条规则本身就在防今天那个错误：把「入口存在」读成「能被发现」。）

原文出处：`docs/windows/development.md` §5.4。

以及 `A12`（再按热键滑出）——**它从属于 A11**：能唤出的人已经知道那个热键了。

**这些是渲染正确性、布局正确性、输入法正确性和被动行为，没有「找到」这个动作。**
**而这件事本身有用**：它说明那 13 条**不是同一类东西**，
「外观·行为」是一个混装的桶，下次分类时应当拆开。

### 这一节要留下的那个数

> **13 条外观判据里，4 条的 D 版本今天大概率不通过，3 条未知，6 条不适用。**

**它说的是：我们有 4 条判据，在功能上是对的、在能不能被找到上是坏的——
而它们全都是绿的。** 加上标未知的 3 条，**13 条里有 7 条,可发现性是一个空格。**

**而我们已经知道这个空格不是零**：用户十分钟撞上三个。
