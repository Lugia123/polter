# 判据：`terminal_layout` —— 一次调用给出整份形状

这一族是 346：`terminal_layout(id, layout)` 把一棵树的形状**一次性**交给宿主，宿主
解析、校验、排队、**返回前排空队列**，再从出参把每一格的 id 读回来。实现在
`windows/host/src/layout.rs`（解析 / 校验 / 回执）、`windows/host/src/tabs.rs`
（`Op::ApplyLayout` 与 `drain_for_layout`）、`windows/split-tree/src/lib.rs`
（`Tree::with_root`）。

在它之前，摆出一个 2×2 只能靠反复 `terminal_action new_split`，而那样**只能得到一条
链**——这正是下面 ② 那一格要先做出来的东西。

## 六格（判据原文逐字，出处 log_seq 2322）

> **① 正对照**：一次调用给 1+1+2+2（后两组各再切一刀）⇒ 回执**逐格带 pane id**；
> `terminal_read` 四格**内容互不相同**；**截图上 2+2 是田字不是四条竖栏**。
>
> **② ⚠️ 负对照（必须做，且要在①之前）**：**用今天的老办法**（`terminal_action`
> 反复 `new_split`）搭同一份意图 ⇒ **应当得到一条链**。**没有这一格，「修好了」和
> 「本来就行」分不开。**
>
> **③ 不许减少**：给一份少了一个既有 pane 的布局 ⇒ **整份拒绝**，错误里点名那个
> pane，**而它还在**。
>
> **④ 原子性**：给一份中间一格 ratio=1.5 ⇒ **拒绝，且一个 pane 都没动**（包括没有
> 多出一个新 pane）。
>
> **⑤ 时序**：⚠️ 在调用前先排一个 `new_tab` 进队列，然后调布局 ⇒ **返回时那个 tab
> 已经建好了**。这条是把设计上的副作用变成读数。
>
> **⑥ mac**：同一条调用在 mac 上 ⇒ **`Unsupported`，且窗口一点没变**。

### ⑤ 和 ⑥ 逐字写成未检验

- **⑤ 时序 drain：未检验。** ⚠️ 造不出「op 还堆在队列里」的条件，**不拿顺序恰好对
  冒充**。「调用返回后那个 tab 在」这件事，在队列本来就空的情况下也会成立，所以它
  不能证明 `drain_for_layout` 排空了什么。要么造得出堆积，要么这一格继续空着。
- **⑥ mac：未检验，归用户。** 这台机器上跑不了它，Windows 上也测不到 mac 的回答。
  ⚠️ 未检验不是已排除。

### 每一格失败时长什么样

⚠️ **下面这一节是我（W2）按判据推的，不是谁在真机上测出来的**，和上面表格里的读数
不是一回事，别混读。

- **① 读不到时**：回执 `ok` 但某一格的 `pane` 拿去 `terminal_read` 取不到东西 ⇒ 回执
  里的 id 不是调用方能用的那种（这正是 406 修的东西，见下一节）。截图上是**四条竖栏**
  而不是田字 ⇒ 树对了而 `layout()` 摆错了，**`describe` 回的是树的形状不是屏幕，这条
  只有截图能抓到**。
- **② 读不到时**：老办法居然也摆出了田字 ⇒ 这一格作废，因为它证明不了新路径做了什么；
  停下来核你用的是不是老办法（`terminal_action new_split`，不是 `terminal_layout`）。
- **③ 读不到时**：拒绝了但那个 pane 没了 ⇒ 比不拒绝更坏，先记下来；或者拒绝话里点名
  的是**别的**东西（见下面「已知残余」）。
- **④ 读不到时**：拒绝了但多出一个新 pane ⇒ 原子性没做到，先建后校验；这一格要**数
  pane 的个数**，不能只看回执。

## 406：布局里的叶子该用哪种 id（WT 实测，全绿）

| 格 | 发什么 | 回执 |
|---|---|---|
| ① | 叶子用**真终端 id** | **ok**，田字，回执里每格的 `pane` 就是发进去的终端 id（`0x7c09e65171296e32` …），喂得回 `terminal_read` |
| ② | 叶子用**宿主 PaneId**（`0x1` / `0x16` / `0x17` / `0x18`） | `Refused: the layout names a terminal that does not exist. Use the ids terminal_list gives you -- the same ones terminal_read and terminal_send take.` |
| ③ | **语法合法但不存在**的终端 id（把真 id 末位改成 0） | **与②逐字相同的那一句** |

⇒ 拒绝落在「查不到」上，不是「格式不对」，**也没有按形状分流**——②③ 逐字相同正是这
一点的证据。⚠️ 但请重读上面那条地板：**逐字相同这件事，只有在 ① 已经绿了之后才有
意义。**

**这三格读不到时长什么样**：② 回的是「格式不对」一类的话（比如抱怨 id 的位数或前缀）
⇒ 说明它按形状分流了，那么一个**恰好像终端 id 的**宿主 PaneId 就会被放过去；②③ 两句
话**不同** ⇒ 同上；②③ 相同**而 ① 没跑或没绿** ⇒ 什么都没证明，回去先跑 ①。

## 这份判据不覆盖什么

- **一格都没在 mac 上验过**，⑥ 归用户。
- **`describe` 回的是树的形状，不是屏幕。** 树对了而 `layout()` 摆错了，回执看不出来
  ⇒ **① 里「截图上是田字」那一条不能省。**
- **`drain_for_layout` 真的排空了什么，没人证明过**（⑤）。它是设计选择，不是疏忽，但
  今天只有代码和注释在说这件事。
- **`polter-split-tree` 的两格 Rust 测试是真跑过的**（`cargo test -p polter-split-tree`
  在 mac 上就能跑，57 → 59 passed），其中
  `a_shape_given_at_once_is_the_shape_that_comes_back` 断言「一个在另一个上面，不是四条
  竖栏」。⚠️ 但那是**树**的测试，不是屏幕的：它和 ① 里那张截图证明的不是同一件事。
