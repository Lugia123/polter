# 设置窗口：角色、项目、插件合进一个窗口

> 状态：设计已定（2026-09-28），开发中。本文是 mac 与 Windows **共用的一份规格**，
> 两边实现都以这里为准；两边有出入时，先改这份文档，再改代码。

## 1. 为什么要做

现在有三个设置性质的界面，各开各的窗口，mac 与 Windows 还不一样：

| | 角色 | 项目 | 插件 |
|---|---|---|---|
| mac | `Features/Roles/RoleLibraryWindow.swift`，独立 NSWindow | `Features/Projects/ProjectPicker.swift`，存 / 取 / 管理三模式的独立窗口 | `Features/Plugins/PluginMenu.swift`，每个插件一个窗口；有插件自带网页（`PluginPage.swift`，WKWebView） |
| Windows | `windows/host/src/roles_ui.rs`，独立窗口，逐项移植自 mac | 只有「另存为」一行输入框（`prompt.rs`）和「加载」弹出菜单（`project_picker.rs`）；**没有管理、删除、恢复，关窗前不提示保存** | `settings_ui.rs`，一个无标题栏的 `WS_POPUP`，Esc 被子控件吞掉后关不掉；**不支持插件网页**；还兼放「关于」和快捷键页 |
| 公共设置窗 | mac「Preferences…」打开的是配置文件，`Features/Settings/SettingsView.swift` 是「Coming Soon」占位；Windows「Settings…」同样只打开配置文件 | | |

**判断：两边的差异几乎都是 Windows 缺功能，不是画法不同。** 所以两边继续各用原生技术
实现（mac：SwiftUI 放进 AppKit 窗口；Windows：Win32），统一的是**窗口结构、入口路由、
行为和功能清单**——也就是本文。不改成 WebView 重写（理由同 `chatui.md` 里那张表：问题
在数据和功能，不在渲染技术）。

GTK 本轮不做（三个界面 GTK 目前都没有）。

## 2. 窗口

### 2.1 单例

整个 app 只有一个设置窗口。已经开着时，任何入口都只是**把它拉到前台并跳到对应栏目**，
不再开第二个。它不属于任何终端窗口（Windows 上 owner 为空或为当前 frame 均可，但关掉
某个 frame 不能让它失效——`dev-docs/windows/status.md` 里角色库出过「句柄在 owner 关掉
后残留」的事故，不要重演）。

### 2.2 尺寸（用户明确要求：不要开得太小）

- **首次打开：** 1180 × 800（mac 为 pt，Windows 为 96 DPI 下的逻辑像素，按窗口所在
  显示器的 DPI 缩放）。若大于当前屏幕可用区域的 90%，则缩到 90%。居中。
- **最小尺寸：** 900 × 620。缩到这里时侧栏与内容都不能被裁掉按钮。
- **记住尺寸和位置**，下次按原样打开：mac 用 `setFrameAutosaveName("PolterSettings")`；
  Windows 存完整矩形（不是只存高度）到与 `roles_ui.rs` 现有 `height_path` 同目录的文件。
  恢复时若矩形已不在任何显示器内（换过屏），回退到首次打开的规则。
- 旧的角色库、项目、插件窗口各自记的尺寸作废，不迁移。

### 2.3 布局

```
┌ Polter 设置 ───────────────────────────────────────────────┐
│ [搜索]            │  角色 › 审查员                          │
│ ───────────────── │  ┌ 基本 │ Skills │ MCP ┐                │
│ 角色              │  │   （栏目内容）          │               │
│ 项目              │  └─────────────────────┘               │
│ 插件              │                                         │
│   ● 飞书    已开  │                                         │
│   ◐ Slack  缺配置 │                                         │
│   ○ xxx    已关   │                                         │
│ 通用              │         [其它动作]   [还原]  [保存]      │
└───────────────────┴─────────────────────────────────────────┘
```

- 左侧栏固定宽度约 220，四个栏目：**角色、项目、插件、通用**。插件栏目下展开列出每个
  插件，带状态点（见 §5.1）。
- 右侧顶部一行面包屑：`栏目 › 当前条目`。
- **对齐（用户点名）**：见 §2.3a 布局网格，那是这件事的规格。
- 右下角固定是 **还原 / 保存**（没有未保存概念的栏目不显示这两个）；「启动」「测试」
  这类栏目动作放在它们左边。两个平台位置一致。
- 搜索框只按条目名过滤（角色名、项目名、插件名），不做全文搜索。输入时跳到第一个有匹配的
  栏目，并过滤该栏目的条目列表。第 1 期只接角色；项目、插件在各自那一期接上。
- **角色和项目的条目列表在内容区里**（栏目自带左侧列表 + 列表下方的新建 / 复制 / 删除），
  不在设置窗口侧栏展开；只有插件在侧栏展开（因为每个插件是独立的一页设置）。
- **关窗**：标题栏关闭按钮、⌘W / Ctrl+W。**Esc 不关设置窗口**：窗口里有长文本编辑，输入法
  也用 Esc 取消组字，误关代价大。有未保存改动时关窗先问（§2.4）。
- **文字**（英文 msgid → 中文）：窗口标题 `Polter Settings` →「Polter 设置」；栏目
  `Roles / Projects / Plugins / General` →「角色 / 项目 / 插件 / 通用」；菜单
  `Role Library…` →「角色库…」；通用栏按钮 `Open config file…` →「打开配置文件…」；
  占位页 `Coming in a later update.` →「将在后续版本提供。」；未保存询问按钮
  `Save / Don't Save / Cancel`。面包屑分隔符「 › 」，栏目无条目时只显示栏目名。

### 2.3a 布局网格（第 1 期 mac 截图后用户点名重做）

第 1 期 mac 的实物有两处横线没对齐：顶部，左栏搜索框下沿与中栏面包屑下沿不在一条线；
底部，中栏列表的工具条（+ ⧉ −）上沿与右侧底栏（启动 / 还原 / 保存）上沿不在一条线。根因是
**每个区块各自决定自己的顶栏和底栏高度**。改法是先定网格，所有区块往网格上贴，而不是各自
居中再去凑。

**三条横带，贯穿整个窗口宽度：**

```
┌ Polter 设置（系统标题栏） ─────────────────────────────────────────────────┐
│ [搜索       ]  │ 角色 › Polter 总管                                         │ ← 顶带 TOP=52
├────────────────┼──────────────────┬────────────────────────────────────────┤ ← 一条线，全宽
│ 角色           │ Polter 总管      │ （编辑器，自己滚动）                   │
│ 项目           │ 开发 Worker      │                                        │
│ 插件           │ …                │                                        │ ← 主体
│ 通用           │                  │                                        │
├────────────────┼──────────────────┴────────────────────────────────────────┤ ← 一条线，全宽
│                │ [+][⧉][−]  先保存角色再启动。        [启动] [还原] [保存] │ ← 底带 BOTTOM=52
└────────────────┴─────────────────────────────────────────────────────────────┘
```

- **顶带**高 `TOP = 52`，从左到右一整条：侧栏部分放搜索框，内容部分放面包屑。搜索框高 28、
  在顶带里垂直居中；面包屑文字与搜索框文字**同一条基线**。顶带下沿是**一条全宽分隔线**，
  不是左右各画一段。
- **底带**高 `BOTTOM = 52`，同样一整条，上沿是一条全宽分隔线。侧栏那一段留空。内容那一段
  是**一条**底栏，不再分「列表的工具条」和「编辑器的按钮区」两个：列表的 + ⧉ − 放在底栏
  左端、与列表左缘对齐；状态文字（如「先保存角色再启动。」）接在它后面；启动 / 还原 / 保存
  靠右。按钮高 28，垂直居中。没有这些按钮的栏目（通用、占位页）底带照样占位、照样有线，
  不让主体区高度随栏目跳动。
- **竖线**只在顶带下沿到底带上沿之间的主体里画（侧栏 | 列表 | 编辑器），在顶带和底带里只画
  侧栏与内容之间那一条。每条竖线从上到下是一根，不断开。
- **列宽**：侧栏 `SIDEBAR = 220`；有条目列表的栏目，列表列 `LIST = 260`（现在实物约 490，
  一半是空的）；编辑器吃掉剩下的全部宽度。最小窗口 900 时编辑器还剩 420。
- **间距只用 4 的倍数**：外边距 `PAD = 16`，控件行距 8，分组之间 24。
- **编辑器内的左缘**：所有分组标题（指令、Polter、打开位置、Agent CLI）与所有控件起点，要么
  贴编辑器左边距 `PAD`，要么贴表单的「控件列」——只许这两条竖线。现在的实物里，名称 / Key /
  说明是右对齐标签 + 控件列，而下面的勾选框又从左边距起，控件列和勾选框各在一条竖线上，看
  起来是歪的。规定：**表单统一用「标签列 120 右对齐 + 控件列」**，勾选框、下拉框也放进控件
  列；分组标题贴左边距。
- 只读横幅（「这是 Polter 自带的角色…」+ 复制）与页签行属于编辑器内容，在主体区里、顶带之下，
  不参与顶带。

**这些常量两边同名同值**：mac 放在一个 `SettingsLayout` 枚举里，Windows 放在
`polter-settings-shell` 里，所有区块只从这里取，不许在区块里写字面量。

**判据**（每期截图核对都做，两个平台都做）：在同一张截图上量出
① 顶带下沿线的 y（侧栏段、列表段、编辑器段各取一点）、② 底带上沿线的 y（三段各取一点）、
③ 搜索框文字基线与面包屑文字基线的 y、④ 每条竖线在顶端与底端的 x。
①的三点相等、②的三点相等、③两者相等、④每条线上下相等，才算过。报的是像素读数，不是
「看起来齐了」。Windows 侧另外在 `polter-settings-shell` 里有断言这些相等的单元测试，而且
要做一次打坏（把某一段的高度改 1）看它红。

### 2.4 未保存改动的统一协议

每个栏目实现同一组接口（mac 为 protocol，Windows 为 trait）：

| 接口 | 含义 |
|---|---|
| `is_dirty()` | 当前条目有没有未保存改动 |
| `save() -> Result` | 保存；失败时栏目内显示原因，窗口不关、不切走 |
| `revert()` | 丢弃改动 |

以下时机先问「保存 / 不保存 / 取消」：切换栏目、切换同栏目内的条目、从别的入口跳进来
（路由指向别处时）、关闭窗口。角色库现有的 `confirmClose`（mac）与对应的 Windows 逻辑
推广成这一套，不再各栏目各写一份。

## 3. 路由与入口

### 3.1 路由

唯一入口函数：`openSettings(route)`，`route = { section, item? }`。

| section | item | 打开后选中 |
|---|---|---|
| `roles` | 角色 key，可空 | 该角色；空则上次选中的，再空则第一个 |
| `projects` | 项目名，可空 | 该项目；空则当前窗口绑定的项目，再空则第一个 |
| `plugins` | 插件 key，可空 | 该插件；空则第一个 |
| `general` | — | — |
| （无参） | — | 上次停留的栏目与条目 |

### 3.2 现有入口怎么改

菜单**不合并**，各自留在原来的位置；只有「管理 / 配置」类的行改为走路由。高频的一步
操作（另存为项目、加载项目、启动角色、插件开关）保持原样，不进设置窗口。

| 入口 | mac 现在 | Windows 现在 | 改成 |
|---|---|---|---|
| 角色子菜单「角色库…」（菜单栏 Agents ▸ Role、tab 右键、终端右键） | `RoleLibraryOpener` | `Pick::Editor`（`personas.rs`） | `roles/<发起终端当前的角色>`；从菜单栏进且无终端时 item 为空 |
| Windows 菜单行「Role Library (beta)…」 | — | `__polter_role_library` | `roles`。标签去掉 `(beta)`，两边都叫「角色库…」 |
| 「管理项目…」 | `manageProjects` | **没有** | `projects/<当前窗口的项目>`。Windows 项目菜单补上这一行 |
| 插件子菜单「设置…」 | 每插件一个窗口 | — | `plugins/<key>` |
| 「插件…」菜单行 | — | `__polter_plugin_page` | `plugins` |
| 「偏好设置…」/「Settings…」、⌘, / Ctrl+, | `open_config` 打开配置文件 | 同左 | 打开设置窗口（无参路由）。「打开配置文件」挪到「通用」 |

⌘, / Ctrl+, 在核心里绑的是 `open_config`（`src/config/Config.zig` 默认键位表）。
**不改核心键位**。`OpenConfig.default` 只是 `.os_open` 的别名（`src/input/Binding.zig`），
宿主分不出「默认的 ⌘,」和用户显式写的 `open_config:os_open`，所以规则按 mode 定：

- `os_open` → 打开设置窗口（无参路由）；
- `new_window` → 保持原来的行为（用 `$EDITOR` 开文件）；
- 菜单「偏好设置…」/「Settings…」直接调 `openSettings()`，不经 `open_config`。

「通用」里的「打开配置文件」按钮直接调宿主原来的打开文件逻辑，不再绕回 `open_config`
（否则会打开自己）。

## 4. 栏目：角色

内容即现有角色库编辑器（Basics / Skills / MCP 三个页签、New / Duplicate / Delete、
Save / Revert、Launch），**功能原样搬进来**，本轮不改功能；**摆放按 §2.3a 网格重排**（列表列
宽、合并底栏、表单的标签列 / 控件列）。除此之外只做三件事：

1. 去掉它自己的窗口外壳，改为设置窗口里的一个栏目；
2. 未保存协议接到 §2.4；
3. 两边残留的不一致对齐：Launch 不可用的原因，mac 是 tooltip、Windows 是底部文字
   ——统一为**底部文字**（tooltip 在 Windows 上不可靠，而且看不见就等于没有）。

## 5. 栏目：插件

### 5.1 列表状态点

| 点 | 含义 | 判据 |
|---|---|---|
| ● 绿 | 已开 | `enabled` 且必填参数齐 |
| ◐ 黄 | 缺配置 | 必填参数没填齐（此时开关不可打开） |
| ○ 灰 | 已关 | `enabled == false` |
| ▲ 红 | 出错 | 核心报告该插件在跑且 `failures > 0`，或有 `note` |
| ↻ | 改了未重启 | 保存后的设置与本次启动时读到的不同 |

数据与 MCP 的 `plugin_list` 同源（`src/poltergeist/Plugin.zig`），宿主不自己猜。

### 5.2 详情

自上而下：

1. **标题区**：名称、版本、作者、本地化说明。
2. **开关**。缺必填项时禁用，并在旁边说缺哪几项。
3. **页签**：「设置」＝按 schema 生成的表单（现有 `PluginSettingsView` / `settings_ui.rs`
   的表单）；插件 manifest 有 `pageURL` 时多一个「页面」页签（见 §5.3）。
4. **「测试」按钮**：走与 MCP `plugin_test` 相同的核心逻辑，结果显示在按钮旁。
5. **日志**：最近 20 行（`~/.local/state/polter/plugins/<key>.log`，Windows 为对应目录），
   以及「显示日志」「显示插件文件夹」。Windows 现在没有这两个入口，补上。
6. **需要重启**：改成详情区顶部一直显示的横幅，不再弹对话框；横幅上有「现在重启」。

### 5.3 插件自带网页

mac 用现有的 `PluginPage.swift`（WKWebView，`polter-plugin://` scheme，`polter` 消息桥），
嵌进「页面」页签而不是单开窗口。

Windows 用 **WebView2** 实现同样的 scheme 与消息桥，行为以 `PluginPage.swift` 为准（这是
本轮新增的依赖）。**运行时可能不存在**（Server 2022 默认没有 WebView2 Runtime，需核实）：
检测不到时「页面」页签仍显示，内容是一段说明（缺 WebView2 Runtime、去哪装），不隐藏页签
——隐藏会让两边界面不一样，而且用户不知道缺了什么。

## 6. 栏目：项目

### 6.1 列表

每行：名称、上次保存时间、tab 数 / pane 数。选中后详情区显示：

- **布局缩略图**：按项目文件里的 tab 与分屏树画出矩形示意（每个 pane 标它的目录末段与
  角色名）。
- 涉及的目录、用到的角色、scrollback 占用空间、自动保存状态（是否绑定到某个打开的窗口，
  上次自动保存时间）。

### 6.2 操作

| 操作 | 说明 |
|---|---|
| 打开 | 与「加载项目…」相同 |
| 重命名 | **新增**（两边都没有）。重名时拒绝并说明；已绑定到打开窗口的，绑定跟着改名 |
| 复制一份 | 新增，默认名「<原名> 副本」 |
| 用当前窗口覆盖 | 需确认 |
| 删除 | 需确认；删除后列表顶部出现「已删除 <名>　[撤销]」，直到关窗或下一次删除 |
| 版本历史 | 替代「恢复上一版」：列出可恢复的版本（按时间），选一个恢复。第一期可恢复的版本就是存储层现有保留的那些，不改存储层 |
| 在 Finder / 资源管理器中显示 | 新增 |

### 6.3 Windows 补齐

除上表外，Windows 还要补：项目菜单的「管理项目…」一行、关窗前「要存成项目吗？」的提示
（`project_ui.rs` 里 `should_offer_save_as_project` 目前只有测试在调）、tab 右键菜单里的
「另存为项目 / 加载项目」两行。

## 7. 栏目：通用

- 打开配置文件（原「偏好设置…」的行为）、重新加载配置、配置错误列表（Windows 现在在
  `settings_ui.rs` 里的那份，mac 需要新做同样的列表）。
- 快捷键：只读列表（Windows 现有的快捷键页搬过来；mac 新做同样的列表）。
- 关于：版本、构建、提交号。

## 8. 两边一致的保证

「做到一样」没有自动判据，所以靠三样东西：

1. **本文是唯一规格**。实现时发现规格没写到的地方，先在群里提出、改本文，再写代码。
2. **逐项对照清单**：`dev-docs/poltergeist/settings-checklist.md`，每一条是一个可观察的
   行为（「从 tab 右键进角色库，选中的是该终端的角色」），两列分别记 mac / Windows 的
   核对结果与证据（截图路径或日志行）。每个阶段交付时清单要更新。
3. **同一组截图**：每个栏目在两个平台各截一张同样状态的图，放进清单，由总管并排比对。

## 9. 分期

每一期两边都做完、清单核过，才进下一期。

1. **窗口外壳 + 路由 + 角色栏目**：单例窗口、尺寸规则、侧栏、未保存协议、`openSettings`、
   所有角色入口改走路由、`open_config` 改为打开设置窗口、通用栏目先只放「打开配置文件」。

   Windows `settings_ui.rs` 拆掉：插件页并入，关于 / 快捷键 / 配置错误移到通用。
