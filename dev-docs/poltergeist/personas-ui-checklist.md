# 角色界面：给人看的核对清单（macOS）

> 任务 570 的欠账凭证。**测试钉不住的三样东西在这里：布局、图标、一行太长被截断。**
> 对应代码 `macos/Sources/Features/Personas/`，自动化部分在
> `macos/Tests/Personas/PersonaMenuTests.swift`（15 条，结构 / 勾选 / 启用态 / 措辞选择）。
> 写给谁：坐在这台机器前、能看见屏幕的人。

## 为什么要有这张纸

「看看对不对」会换回一句「还行」，而那等于没验。下面每一条都是
**点哪里 → 该看到什么 → 什么样算不对**，逐条可判，答「对 / 不对 / 看不到」即可。
不对的那条把屏幕拍下来。

## 先说清楚今天能看见什么

核心侧现在**已经真的会读 `personas.json` 了**，所以：

- **没写过那个文件的机器**（默认情况）：角色清单是空的，而且界面会说
  「还没有定义任何角色」还是「还没有人报上来有哪些角色」——**这两句不一样**，
  第一部分就是验它们没串。
- **`host_class` 现在恒为 `unknown`**（认 agent 是哪一家那条还没接），
  所以第 2 条里那句提示应该是「可能要 agent 重启之后才生效」。
  **这是真状态，不是占位符**——不要因为「看起来像没做完」就记成缺陷。
- **每个槽位现在恒为 `withheld`**（还没有槽位进程去起上游）。同样是真状态。

**第一部分检查的是「基本没有数据时长什么样」**——那恰恰是真机上第一眼
看见的画面，也是最容易被做成撒谎的地方。要看有数据的样子，写一份
`$XDG_CONFIG_HOME/polter/personas.json`（没设 `XDG_CONFIG_HOME` 就是
`~/.config/polter/personas.json`）再做第二部分。

# 第一部分：今天就能做

**0a / 0b 是起实例，约一分钟；1–10 是看屏幕，约两分钟。**

## 0a. ⚠️ 必须用 `open -n` 起一个**新实例**，不能直接 `open`

**为什么这条排在最前面**：你此刻正开着一个 Polter 在用，而**那个实例里没有角色菜单**
（它是旧的构建）。直接 `open` 多半只是把它切到前台，于是第 1 条会报回一个
**不存在的缺陷**——菜单确实没有，但不是因为代码错了。

**做**（拷这三行）：

```sh
# 在这个仓库的根目录里跑（下面那个相对路径要这个前提）
APP=$(ls -dt ~/Library/Developer/Xcode/DerivedData/Ghostty-*/Build/Products/Debug/Polter.app macos/build/Debug/Polter.app 2>/dev/null | head -1)
echo "$APP"; ls -ld "$APP"; open -n "$APP"
```

**该看到**：`echo` 出来的路径**不是** `/Applications/Polter.app`；`ls -ld` 的时间戳是
**今天刚构建的**；然后新开一个窗口。
**算不对**：路径是 `/Applications/...`（那是你在用的那个，别在它上面验）；
时间戳是几天前（构建没出来，先别往下做）；`open -n` 报错。

> 这台机器上同时存在至少三个 `Polter.app`：`/Applications` 里你在用的那个、
> `macos/build/Debug/` 里的、以及 Xcode DerivedData 里的（还不止一份）。
> **它们长得一模一样。** 上面那行 `ls -dt … | head -1` 取的是最新的那个。

## 0b. 确认眼前这个窗口来自新实例

**别用「有没有角色菜单」来判断**——那正是要验的东西，拿它当前提就是循环。

**做**（在**另一个**终端里，或在旧实例里跑）：

```sh
lsappinfo info -only bundlepath "$(lsappinfo front)"
```

**该看到**：打印出来的路径和第 0a 步 `echo` 的那个**逐字相同**。
**算不对**：打印的是 `/Applications/Polter.app`（你在看的是旧实例，回到 0a），
或者是别的应用（先点一下新窗口让它到前台再跑一次）。

**再确认一次两个实例都在**：

```sh
ps -Ao pid,comm | grep 'Polter.app/Contents/MacOS/polter$' | grep -v ' +mcp'
```

**该看到**：至少两行不同的路径 —— 一行 `/Applications/...`（你原来那个），
一行是新构建的那个。
**算不对**：只有 `/Applications/...` 一行 —— `open -n` 没起来新实例。

**做完这份清单之后**：新实例自己关掉，**别关你原来那个**。

## 1. tab 右键菜单里有没有这一项

**做**：在任意一个标签页的**标签**上点右键。
**该看到**：菜单底部一组里有一行 **「角色」**，右边有子菜单箭头 `>`。
**算不对**：没有这一行 / 有字但没有箭头。

> ⚠️ **菜单图标只在 macOS 26 以上才有**（`NSMenuItem.setImageIfDesired` 里
> `if #available(macOS 26, *)`），所以更老的系统上**菜单里一个图标都没有是正确的**，
> 不要记成缺陷。这台机器是 26.5.1，所以这里应该有图标。

## 2. 子菜单的内容和顺序

**做**：鼠标移到「角色」上，等子菜单弹出。
**该看到**，**从上到下正好是这六样**：

1. 灰色不可点：**「可能要 agent 重启之后才生效」**
2. 分隔线
3. 灰色不可点：**「还没有人报上来有哪些角色」**
4. 分隔线
5. **「不设角色」**，**前面有对勾**
6. 分隔线 + **「角色编辑器…」**，左边一个推杆图标

**算不对**（任何一条）：
- 有**英文**出现 —— 说明中文没命中，这是个真缺陷，不是语言设置问题。
- 第 3 行写的是**「还没有定义任何角色」** —— 这两句意思不同，串了就是缺陷。
- 「不设角色」**没有对勾**。
- 灰的那两行**鼠标移上去会变蓝 / 能点** —— 它们必须是死的。
- 第 1 行写的是**「下次启动 agent 时生效」** —— 那是另一句，今天不该出现。

> 第 1 行和第 3 行是这个功能最要紧的两句：它们的职责就是**不许让「还没生效」
> 看起来像「已经生效」**。它们出错的样子是「看起来很正常」。

## 3. 长句有没有把菜单撑坏

**做**：就看上一步那个子菜单。
**该看到**：两条长中文各占**一行**，完整，没有 `…`；菜单整体宽度还算正常。
**算不对**：句子被截断成 `还没有人报上来…`；或者菜单宽得跨过半个屏幕。

## 4. 终端里右键，同一套东西

**做**：在终端**内容区域**（不是标签）点右键。
**该看到**：菜单**最下面**同样有「角色」，展开后和第 2 步**逐行相同**。
**算不对**：没有 / 有但内容和第 2 步不一样（两处菜单是同一份代码建的，不一样就是接错了）。

## 5. 编辑器窗口

**做**：点「角色编辑器…」。
**该看到**：一个独立窗口，标题栏写 **「角色编辑器」**；右下角一个**「完成」**按钮；窗口可以拖大拖小。
再点一次「角色编辑器…」**不该**再开出第二个窗口，而是把已经开着的那个提到最前。
**算不对**：没弹出来 / 标题是英文或是文件名 / 没有「完成」按钮 / 尺寸拖不动。

## 6. 编辑器里的分区，从上往下

**该看到**：
1. 顶部：这个终端的标题，下面一行小字 **「不设角色」**，再下面一行带时钟图标的小字 **「可能要 agent 重启之后才生效」**
2. **「选一个角色」** —— 下面是「还没有人报上来有哪些角色」，再下面 **「不设角色」带一个实心对勾圆圈**
3. **「这个终端交出去的东西」** —— 下面一句 **「还没有人报上来这个终端交出去了什么」**
4. **「这台机器上已经装了的」** —— **紧跟一句小字**：
   **「列在这里，是为了让你看见角色没有覆盖到哪里。Polter 不会动这些。」**
   再下面「还没有人报上来这台机器装了什么」

**算不对**：
- 第 4 区**少了那句小字** —— 那句必须在，没有它用户会去找开关，而这一区是故意只读的。
- 任何一区标题是英文。
- 第 4 区显示成一个**空列表**（什么都不写） —— 空列表会被读成「这台机器什么都没装」。
- 第 2、3、4 区那三句**「还没有人报上来…」用了同一句话** —— 它们说的是三件不同的事
  （有哪些角色 / 这个终端交出去了什么 / 这台机器装了什么），串成一句就是缺陷。

## 7. 图标不是空白方块

**做**：把**编辑器窗口里**出现的图标扫一眼 —— 时钟、圆圈 / 实心对勾圆圈。
再看**菜单里**的人像、推杆、省略号、托盘（**仅当系统是 macOS 26 以上**，见第 1 条的提醒）。
**算不对**：其中任何一个是**空白**、方框、或者位置空着。

> 图标名拼错在代码里不报错，只在屏幕上少一个东西。这台机器上这 11 个名字我
> 用 `NSImage(systemSymbolName:)` 逐个查过都能取到，**但那是在 26.5.1 上查的**
> —— 一个 macOS 14 才加的符号在这里查得到、在 13 上是空的，所以这一条在**旧系统**
> 上仍然要人看。

## 8. 把编辑器窗口拖到最窄

**做**：拖窗口左右边缘，缩到拖不动为止。
**该看到**：文字自动换行，上下不重叠，右边不被裁掉。
**算不对**：句子被右边缘切断 / 两行字叠在一起 / 出现横向滚动条。

## 9. 深色浅色各看一眼

**做**：系统设置切一次外观（或本来是哪个就切到另一个）。
**该看到**：灰色小字在两种模式下都读得清。
**算不对**：某一种模式下小字几乎看不见。

## 10. 护盾把开关关掉

**做**：同一个 tab 右键 →「不让 agent 碰此终端」；再右键 → 展开「角色」。
**该看到**：子菜单**顶部多一条**灰色的 **「不让 agent 碰此终端，所以它的角色也不能改」**；**「不设角色」变成灰的、点不动**；而**「角色编辑器…」仍然可以点**（看不是改）。
**做完**：再点一次「不让 agent 碰此终端」关掉护盾。
**算不对**：没有那句话 /「不设角色」还能点 /「角色编辑器…」也被禁用了。

# 已经不用人看的（自动化钉住了）

这些跑 `xcodebuild … test -only-testing:GhosttyTests/PersonaMenuTests` 就有答案，
**别再用眼睛验一遍**：子菜单的项数与顺序、勾选落在哪一项、每行带的是不是自己的
key、护盾时哪些行禁用哪些不禁用、冷 / unknown / 热三句各自出现与不出现、
「没有 agent 连着时父项不声称角色」、「已改的名字处处不同于没改的」、
以及「还没有人报上来有哪些角色」和「还没有定义任何角色」不许是同一句。

**这些断言证明过自己会红**：把 `agentPresent` 那个分支故意写反，红的是
`withNoAgentConnectedTheParentDoesNotClaimThePersona`、
`theParentNamesThePersonaWithoutBeingOpened`、
`aDeviatedPersonaReadsDifferentlyEverywhereItIsNamed` 三条。
