# 截图：全局快捷键、框选与标注、粘进 AI CLI

> 状态：设计已定（2026-10-06），开发中。本文是 mac 与 Windows **共用的一份规格**，
> 两边实现都以这里为准；两边有出入时，先改这份文档，再改代码。GTK 本轮不做。

## 1. 要做成什么

开着 Polter 就能截图，体验参考微信截图：按全局快捷键 → 屏幕定格 → 鼠标悬停时自动框住
光标下的窗口，点一下选窗口，拖动则自由框选 → 在选区上标注（框、箭头、画笔、写字、编号）
→ 完成。结果可以粘进 Polter 里正在跑的 AI CLI，也可以粘进别的应用（微信等）。

与微信截图的一处关键不同：**标注是可读的数据，不只是画在图上的像素。** 用户写的字、
框住的位置，以文本形式随图片一起交给 AI，不需要它再从图里认字。

分两步交付，第 1 步不依赖第 2 步。

## 2. 第 1 步：图片粘贴（零权限）

现状：剪贴板里只有图片时两边都粘不进来（核心的普通粘贴只向宿主要 `text/plain`；
mac `getOpinionatedStringContents` 返回 nil，Windows `read_clipboard_text` 只认
`CF_UNICODETEXT`）。

改成：宿主在回答普通粘贴的 `text/plain` 请求时，若剪贴板**没有文本、没有文件、但有图片**，
就把图片存成 PNG（§5），把**路径**当作粘贴文本交回核心。之后与拖一个文件进终端同路：
走 `completeClipboardPaste`，终端开了 2004 就带 bracketed 帧。

- 全在宿主里做，核心的粘贴路径不改。
- 优先级：文本 > 文件 URL > 图片。剪贴板同时有文本和图片（从网页复制）时仍粘文本。
- 路径转义沿用各自拖放的现成规则（mac `Ghostty.Shell.escape`，Windows `polter_droppath`）。
  整段粘贴只含这一条路径，不加尾随空格或换行——Codex 要求整段恰好是一条路径。
- 同一张图连粘两次不重复存盘：记下剪贴板的变更序号（mac `changeCount`，Windows
  `GetClipboardSequenceNumber`）与上次存出的路径，序号没变就复用。
- 开关：配置项 `clipboard-paste-image`，默认 `true`。关掉后行为与今天逐字节相同
  （Windows 上 `ctrl+v` 继续穿透给 pty，由 CLI 自己读剪贴板）。
- Windows 顺带补上：剪贴板是 `CF_HDROP`（资源管理器里复制的文件）时粘出路径，mac 已有。

## 3. 第 2 步：截图

### 3.1 触发

两套触发，互不依赖，各自可改可关。

**纯键盘。** 新键位动作 `screenshot`（无参数）。默认绑定是**全局**的：
mac `global:cmd+shift+0`，Windows `global:ctrl+shift+0`。用户在配置里用普通的
`keybind = …=screenshot` 改；设置窗口的快捷键页目前只读，本轮不改它。
⚠️ Windows 上 `ctrl+shift+0` 历史上会被「切换输入语言」的系统热键吃掉（装了多个输入法
时），是否注册得上、按了有没有反应是真机验收的一格；不通就换默认值，不许留一个按不出来
的默认键。

**键盘 + 鼠标。** 按住修饰键**单击**左键：mac `cmd+shift`，Windows `ctrl+shift`。一只手
在键盘、一只手在鼠标，都不用挪。配置项 `screenshot-mouse-trigger`，值是修饰键组合
（如 `cmd+shift`）或 `none`（关掉），默认开。语义是「这几个修饰键 + 单击」。

- **进入后与快捷键触发完全一样，不预选光标下的窗口。** 进入定格界面后本来就是「悬停到的
  窗口清晰、单击选中它」（§3.2、§9.8.7），所以紧跟着的第二下点击落在定格界面上、选中光标下
  的窗口——等于原来「双击」的效果，而且不用等系统的双击间隔。**不再有单独的双击触发逻辑**，
  也不再读系统的双击间隔和距离。
- 按下时修饰键要按着，且**只有**这几个修饰键（多按一个不算）。触发发生在**按下**那一下。
- mac：用全局鼠标事件监听，**不许因此要辅助功能或输入监控权限**（预期鼠标事件的全局监听
  不需要授权——没实测，开工先量；若量出来要授权，mac 这一套改为默认关并在群里报）。
  监听吃不掉事件，所以这一下点击会照常落到下面的应用上。
- Windows：低级鼠标钩子放在**独立线程**上（钩子过程慢了会拖住全系统的鼠标，主线程不许
  挂它），**这一下按下吃掉**，下面的应用收不到。
- 已知代价（mac）：这一下会同时落到下面的应用上——浏览器里 `cmd+shift+单击` 是在新标签页
  打开链接，列表里是扩展选择，点在标题栏上可能缩放窗口。文档里写明「点在空白处」。
  Windows 没有这个代价（钩子吃掉了）。
- 已知代价（Windows）：钩子吃掉的是所有「恰好这几个修饰键 + 左键按下」，不看点在哪个程序上。所以 Polter 运行期间，
  别的程序里的 ctrl+shift+单击 手势用不了——资源管理器和表格里的扩展选择、浏览器里「在新标签页打开并切过去」都会变成截图。
  想用回这些手势只能改 screenshot-mouse-trigger（换一组修饰键，或 none）。吃不吃是宿主里的一处开关
  （windows/host/src/shot.rs 的 EAT_TRIGGER_CLICK）：关掉以后这一下会同时落到下面的应用上，代价变成与 mac 相同的那一条。
  这一条是读代码得出的，没有在真机上逐个程序试过。
- （2026-10-07 之前是「按住修饰键双击」，出来时光标下的窗口已选中；用户改成单击。）
- 2026-10-07 总管提过改回双击（不预选）或换修饰键，用户未定，早上再问。
- ⚠️ mac 现有的 `global:` 键位走事件监听，要「辅助功能」权限。**默认的截图快捷键不许
  因此在启动时弹辅助功能授权**——用不需要该权限的系统热键注册实现（Carbon
  `RegisterEventHotKey`）。Windows 已有 `RegisterHotKey`（`quick.rs`）。
- 热键被别的程序占了、注册失败时要出声（日志 + 一次性提示），不许沉默。
- 菜单和命令面板各有一项「截图」，显示当前绑定的键。

### 3.2 选区界面

- 触发瞬间把所有显示器截下来定格，每个显示器一个全屏覆盖窗口显示定格画面。
  之后的选择、标注都在定格画面上做（菜单、悬停态不会跑掉）。
- **窗口自适应**：鼠标移动时高亮光标下最上层窗口的边界（不含 Polter 自己的覆盖窗口）。
  单击 = 选这个窗口；按下拖动超过 4 px = 自由框选。本轮只到窗口一级，不识别窗口内控件。
  高亮的画法（§9.8.7）：那个窗口清晰、其余是毛玻璃；没有窗口可吸附时整屏清晰。
  两种触发（快捷键、修饰键 + 单击，§3.1）进入后都是这个状态，**都不预选窗口**。
- 选区定下后：八个手柄可调大小、可整体拖动；旁边显示尺寸（像素）。
- **进入定格的第一帧就按指针此刻的位置算「吸附到哪个窗口」**（#1196-6）：宿主在显示覆盖窗口前先把
  `NSEvent.mouseLocation` / `GetCursorPos` 喂给编辑器，当作指针刚刚移到那里；不等第一次鼠标移动。
  之前编辑器在第一次 `mouseMoved` 之前不知道有指针，蓝框和清晰区要等用户挪一下鼠标才出现（mac 上是这个根因；
  窗口列表不是晚到）。
- **实时尺寸标签**（#1196-8）：拖出选区、拖手柄、整体移动的**每一帧**都在选区左上角上方（上方放不下时贴内侧）
  显示「宽 × 高」（物理像素），随指针逐帧更新；不是松手后才出现。之前 mac 的拖出阶段（还没有选区、
  只有「正在拖的矩形」）整段不画标签，拖手柄和移动本来就在画。
- **放大镜**跟着指针（§9.9）：没有选区的悬停阶段、拖出选区、拖手柄、整体移动的全程显示，选区定下进入标注后不显示。
- **选区以外是毛玻璃，不是压暗**（§9.8.6）：选区内是原图，选区外是模糊 3 pt + 压暗 6% 的同一张画面；
  拖出选区、移动、改大小时逐帧如此（§9.8.8）。系统开了「减少透明度」时退回压暗 43%。
- `Esc` 取消（无任何副作用：不动剪贴板、不留文件）；右键 = 退一步（有选区则清选区，
  没有则取消）。
- 多显示器、各显示器缩放不同的情况都要对：存出的图是**物理像素**，选区不跨显示器
  （跨了就夹到起点所在的那个）。
- **键盘归定格界面（mac，#1110）。** 覆盖窗口是不激活 app 的面板，能当 key、不能当 main。
  定格界面在的时候，本 app 里它后面的窗口一旦成为 key（agent 开了新 tab、辅助功能把终端
  窗口提到前面），会话立刻把 key 拿回来，文字输入框仍是 first responder——否则画面不变、
  打的字却进了后面的终端并被回车提交。不拿回的两种：app 正在等的模态警告框、层级不低于
  覆盖窗口的窗口（`ShotKeyHold`）。不抢别的 app 的前台。Windows 侧没有这条（覆盖窗口不处理
  失去激活；文字输入框失去焦点即提交）。

### 3.3 标注工具

选区下方一条工具栏（放不下就放上方或选区内）：

| 工具 | 说明 |
|---|---|
| 矩形 | 空心框 |
| 箭头 | 起点到终点 |
| 画笔 | 自由线 |
| 文字 | 点一下出输入框，支持中文输入法 |
| 编号 | 点一下放一个圆形序号 ①②③…，可紧跟着输入一句说明 |
| 颜色 | 至少红、黄、蓝、白四色，默认红 |
| 撤销 | 逐步撤销，`cmd/ctrl+z` |
| 取消 | 同 `Esc` |
| 完成 | 同 `Enter` / 双击选区 |

本轮不做：马赛克、椭圆、钉在屏幕上、长截图、录屏。

### 3.4 完成后去哪

完成时固定做两件事：

1. 把**合成图**（截图 + 全部标注画上去）写进系统剪贴板 → 可粘进任何应用。
2. 把合成图存成文件，并写旁路文件（§4）。

**完成时只做这两件事，不往任何窗格里送东西**——触发那一刻 Polter 在不在前台都一样。
用户自己在某个窗格里按粘贴键时，第 1 步的图片粘贴认出「剪贴板里这张就是刚才那张」
（按变更序号），复用已存的文件，把原来完成时自动送的东西原样送进**被粘贴的那个窗格**：
路径，然后标注文本（§4.2）；长截图是分片逐片（§9.6）。

> 曾经是「若触发那一刻 Polter 是前台应用，就直接送进当时聚焦的窗格」。用户定为不要
> （#1114）：要粘的未必是那个输入框，送错了还得自己删一次。不设配置开关。原则是把自动送的
> 内容和节奏原样挪到用户自己的粘贴键上，只换触发点。
> 「触发那一刻聚焦的是哪个窗格」仍然记着，只用来写旁路文件的 `terminal`（§11）。

## 4. 可读的标注

### 4.1 旁路文件

每张截图 `<name>.png` 旁边写 `<name>.json`（UTF-8）：

```json
{
  "version": 1,
  "image": "20261006-153012-123.png",
  "taken_at": "2026-10-06T15:30:12+08:00",
  "size": [1280, 800],
  "scale": 2.0,
  "source": {"kind": "window", "app": "Google Chrome", "title": "…"},
  "annotations": [
    {"n": 1, "type": "number", "at": [412, 96], "text": "这个按钮没对齐"},
    {"type": "rect", "rect": [380, 80, 240, 44], "text": ""},
    {"type": "arrow", "from": [100, 300], "to": [220, 340]},
    {"type": "text", "at": [60, 500], "text": "间距太大"},
    {"type": "pen", "bbox": [10, 10, 80, 40]}
  ]
}
```

- 坐标全部是**图片像素**，原点左上，`rect`/`bbox` 是 `[x, y, w, h]`。
- `source.kind` 是 `window`（单击选的窗口）或 `region`（自由框选）；`app`/`title`
  只在 `window` 时写，取不到就省略该键，不写空串。
- 其余元信息（URL、git、归属、文字识别等）本轮不做，`version` 留着给以后加字段。

### 4.2 粘贴进终端的文本

用户在 Polter 窗格里粘贴一张本机刚截的图时（§3.4），**分两次粘贴**：

1. 第一次：只有图片路径（规则同 §2）。AI CLI 把它识别成图片附件。
2. 第二次：仅当有带文字的标注时发，一段单行文本，例如：

   `[截图标注 1280×800] ① (412,96) 这个按钮没对齐；文字 (60,500) 间距太大；框 (380,80,240,44)；箭头 (100,300)→(220,340)。详见 <json 路径>`

   没有任何标注时不发第二次。只有图形、没有文字时也发（位置本身就是信息）。
   文案走两个宿主各自的本地化，键名在核心定一份。

后续的每一次粘贴（标注文本、长截图的后几片）都发往**按下粘贴键那一刻的那个窗格**，
按身份认（Windows 是 pane id，mac 是那个 surface），不是「到时候谁有焦点」：

- 用户中途切到别的窗格 / 别的 tab：照旧发完，还是进原来那个窗格。
- 那个窗格中途关了：剩下的全部丢掉，不落到任何别的窗格里（Windows 日志
  `… for pane=N not pasted: that pane was closed while it waited`）。
- 同一个窗格里还没发完又按了一次粘贴：前一遍没发完的丢掉，从头再来一遍（否则两遍的
  分片会交错）。别的窗格里的粘贴各发各的，互不影响。
- 再粘一次（同一个或另一个窗格，剪贴板没变）：同一个文件、同一行，不另存。
- 要粘的文件里有被删掉的（图本身，或要发的前 8 片里任何一片）：不复用，按普通图片粘贴
  处理——把剪贴板里的图另存一张、粘它的路径、后面什么都不跟（「指向不存在文件的路径」
  比多存一张更糟）。

⚠️ 「连续两次粘贴」在各家 CLI 里的表现没实测过，是真机验收的一格（§7）。若某家把第二次
吞掉或并进路径导致图片不识别，退路是两次之间等到第一次被回显之后再发；不许改成一次
粘贴里塞两样。

## 5. 文件放哪、怎么清

- 目录：`$XDG_STATE_HOME/polter/shots/`（Windows 回退 `%LOCALAPPDATA%\polter\shots\`），
  与项目、会话等既有状态目录同一规则。配置项 `screenshot-directory` 可改（应对 Gemini CLI
  对工作区外路径的限制）。
- 文件名：`YYYYMMDD-HHMMSS-mmm.png`，本地时间，纯 ASCII、小写扩展名、无空格。
- 清理：宿主启动时删掉该目录里**修改时间早于 7 天**、且文件名匹配上面模式的 `.png` 与
  同名 `.json`。只认这个模式——用户把目录指到别处时，不许删掉不是我们写的文件。
- 文件权限：POSIX 下 `0600`，目录 `0700`。

| | 第 1 步 | 第 2 步 |
|---|---|---|
| mac | 无 | 「屏幕录制」。首次触发时走系统授权；没授权时给一句话说明并指到系统设置，不许截出一张只有桌面背景的图当成功。需要在工程里补 usage description |
| Windows | 无 | 无 |

## 7. 验收（真机，两平台各一轮）

1. 系统截图到剪贴板 → 在 Claude Code / Codex 里按粘贴键 → 出现图片附件。
2. `clipboard-paste-image = false` 时行为与改动前一致。
3. Polter 在后台、别的应用在前台时按热键能截；`Esc` 后剪贴板没变、目录里没多文件。
4. 悬停高亮跟着窗口走；单击选窗口得到的图边界与窗口一致（报像素读数）。
5. 标注五种工具各用一次 → 合成图里都有；`.json` 里条目与位置对得上。
6. 完成后粘进另一个应用得到合成图。
7. 从 Polter 前台触发、完成 → 聚焦的窗格里**什么都没多**；随后在某个窗格里按粘贴键 →
   图片附件 + 标注文本都到了 CLI（两次粘贴那一格）。Polter 在后台时触发，读数相同。
   长截图：粘贴出的是分片，逐片到达（§9.6）。
8. 两个显示器、缩放不同时各截一张，尺寸是物理像素。
9. 目录里放一个 8 天前的截图和一个 8 天前的无关文件，重启后前者没了、后者还在。
11. 修饰键 + 单击：在别的应用前台时能触发，出来时**没有**预选任何窗口（与按快捷键进入的
    画面相同）；紧接着再点一下 = 选中光标下的窗口；只按修饰键不点、不按修饰键单击、或多按
    一个修饰键单击都不触发；Windows 上这一下点击没有落到下面的应用；mac 全程没弹任何授权。
12. Windows：`ctrl+shift+0` 在装了中文输入法的机器上按得出来（否则换默认值）。
10. Windows：Claude Code 原生 Windows 版能否识别 `C:\…` 路径粘贴（未确认，读数要报）。

## 8. 已知不做 / 已知限制

- SSH 到远端时不通：文件和剪贴板都在本地。
- aider 不识别粘贴的路径（它只有 `/paste` 和 `/add`）。
- mac 上「文本与文件谁先」沿用既有的 `getOpinionatedStringContents`（逐项先取文件路径
  再取文本），本功能只决定「是否轮到图片」。
- 选区不识别窗口内的控件；不取浏览器 URL、不做文字识别、不读无障碍树。

# 第二轮（2026-10-06 用户定）

## 9. 标注工具 v2

### 9.1 工具栏（两行）

第一行，从左到右，分组之间留组间距：

`选择` ｜ `矩形` `椭圆` `直线` `箭头` `画笔` `荧光笔` `文字` `编号` `马赛克` ｜ `撤销` `重做` ｜
`长截图` `保存` ｜ `取消` `完成`

共 16 个按钮，分组 1 / 9 / 2 / 2 / 2。

- **保存**（#1196-9）：放在 `长截图` 与 `取消` 之间，与 `长截图` 同组。**保存 = 完成 + 另存一份到「下载」目录**：
  剪贴板、截图目录里的 `<name>.png` 与旁路 `.json`、粘贴时发给 CLI 的内容都与 `完成` 完全相同
  （所以粘贴与 agent 读图的链路不变），**另外**在系统「下载」目录（mac `FileManager.urls(for: .downloadsDirectory)`，
  Windows `SHGetKnownFolderPath(FOLDERID_Downloads)`；不写死 `~/Downloads`）存一份同样的 PNG，文件名沿用截图的命名规则
  （`YYYYMMDD-HHMMSS-mmm.png`），重名就加 ` 2`、` 3`（`stem 2.png`，Finder 的编法），**绝不覆盖**，也不给这份加
  owner-only 权限（它是用户自己的文件）。长截图的保存存整张长图（不存分片）。
  保存之后在屏幕下方给一条不抢焦点、不接鼠标的小浮条「已保存到「下载」：<文件名>」，约 2.4 秒后自己消失
  （不用系统通知：通知要权限）；保存失败（没有下载目录、写不进去）说「图片没能保存。」，截图本身仍照常完成。
  按下去显示按下态、**在同一个按钮上松开才生效**（与 `取消` / `完成` 同，§9.8.4）；快捷键 `cmd+S`（Windows `Ctrl+S`），
  有选区时才生效，长截图进行中也生效（等同 `完成`）。
  图标 `save`：软盘（造型是为避开 `长截图` 那个带向下箭头的页面——候选对比图（软盘 / 下载托盘 / 文件夹加箭头）
  在 `shot-ui-mock/impl-mac-v2/save-icon-candidates.png`，默认软盘，用户可改选，改的只是 JSON 里的一条路径）。

第二行是**属性栏**，内容跟着当前工具（或当前选中的标注）变：

| 当前工具 / 选中的标注 | 属性栏 |
|---|---|
| 矩形、椭圆、直线、箭头、画笔、荧光笔 | 9 个色块 + 5 档粗细 |
| 文字、编号 | 9 个色块 + 5 档字号 |
| 马赛克 | 5 档块大小 |
| 选择（没选中任何标注）、长截图 | 不显示 |

- **9 种预设颜色**（顺序即数字键 1–9）：红 `#E62828`、橙 `#F5821F`、黄 `#FFD400`、
  绿 `#2DB84D`、青 `#17B5C8`、蓝 `#2F6FED`、紫 `#8E44D6`、黑 `#1A1A1A`、白 `#FFFFFF`。
  默认红。没有自定义颜色。
- **5 档粗细**（逻辑点，乘显示器缩放得物理像素）：1、2、4、6、10。默认第 2 档。
  荧光笔的实际宽度是该档的 4 倍，颜色 40% 不透明、正片叠底式地盖在画面上。
- **5 档字号**（逻辑点）：14、18、24、32、44。默认第 2 档。编号圆的直径跟着字号。
- **字体只有一种**：随包带的 Noto Sans SC Regular（SIL OFL 1.1，许可证文本随包）。
  文字与编号都用它，输入框里也用它，两个平台画出来是同一套字形。**不许回落到系统字体
  而不出声**：字体文件缺失时记日志并在工具栏给一句提示。
  - 文件：Noto Sans SC Regular 2.004 的**简体区域子集 OTF**（notofonts/noto-cjk 的
    `Sans/SubsetOTF/SC/NotoSansSC-Regular.otf`，8,331,336 字节，原样不改）。仓里在
    `fonts/`，`zig build` 装到 `share/ghostty/polter/fonts/`，不编进二进制。
  - **宿主找它的路径：`<资源目录>/polter/fonts/NotoSansSC-Regular.otf`**，许可证在同目录的
    `OFL.txt`。资源目录就是各宿主找 skill 和插件用的那个：Windows 包里是
    `share\ghostty\polter\fonts\NotoSansSC-Regular.otf`，mac app 里是
    `Contents/Resources/ghostty/polter/fonts/NotoSansSC-Regular.otf`。
  - 「出声」只针对**文件缺失**（或加载失败）。文件在、而某个字不在子集里（谚文、只有繁体
    或日文用的字形等）时，**按字回落到系统字体，不提示**——这是正常的逐字回落，不算
    「回落而不出声」。
  - `tools/the-annotation-font-ships.py` 看住这条链：文件是钉住的那一份、许可证在旁边、
    构建会装、有构建树时产物里有。
- 当前颜色 / 粗细 / 字号**各工具分别记住**，一次截图内有效；下一次截图回到上次用过的
  值（存在宿主的状态文件里，不进配置）。
- **外观见 §9.8**：一块深色薄玻璃板装两行；每个可点的东西（按钮、色块、档位）各占一个 28 pt 的格子；
  粗细 5 档是大小不同的圆点，**字号 5 档是大小不同的 T**，马赛克 5 档是粗细不同的棋盘格；
  选中只有一种画法（强调色细环 + 光晕）。
- 每个按钮有**悬停提示**：名称 + 快捷键，走本地化。msgid 在核心 `src/input/screenshot.zig`
  定一份，两个宿主都从那里取词，不各写各的。

### 9.3 文字

- 选中文字工具后，**每点一次空白处就新建一段文字**，可以连着写很多段，不用重选工具。
- 输入框里 `Enter` 换行，`cmd/ctrl+Enter` 或点输入框外 = 提交；`Esc` = 提交已输入的内容并
  退出输入（空的就丢弃）。组字中的 `Esc` 只取消组字。
- 双击一段已有文字 = 重新进入编辑。
- **输入法组字期间（mac，#1110）。** 输入法的每次调用（`setMarkedText` / `insertText` /
  `unmarkText`）进行中不动输入框，等这次调用结束再按内容重摆一次；组字期间只动几何（框的
  位置、高度、滚动），不动文字、属性和选区；组字中点色块/字号档只改「接下来打的字」和底色，
  已在框里的字等组字结束再整段改（`ShotTextInput`）。文本视图在打开时就定在 TextKit 1 上：
  它原先在第一次按键时才被动切换，切换会丢掉组字区，空框里拼音 `nihao` 上屏成 `n你好`。
- 文字颜色、字号在输入中可以改，改的是这一整段。输入中点属性栏的色块或字号档：改这一段，
  **输入不退出**（键盘回到输入框，已输入的字和光标都在），工具的记忆值照常更新；连点两下
  （系统当成双击的第二下）也只是又点了一次。点工具栏别的按钮或画面别处仍是提交。
- **输入框多大、放哪（两个宿主同一套规则，纯函数：Windows `textbox.rs`，mac
  `ShotTextBox.swift`）。** 输入框**没有底色**（§9.8.11：黑白相间的虚线框、光标、编辑中的字带反色晕），
  底下的画面看得见；但它仍然接鼠标，盖住的东西点不到，
  所以它不许盖住工具栏和属性栏——那两行正是给这段文字改颜色、改字号的地方。
  （#1113 之前是白色不透明底，挡住后面的截图，用户否掉了。）
  - **高度跟内容走**：整数行。初始一行，每多一行长一行；行高是宿主用标注字体量出来的
    （不是字号本身：Noto Sans SC 一行约 1.45 倍字号）。
  - **不伸出选区**：长到选区底边为止，装不下的行在框内滚动，光标所在行保持可见。
    mac 上输入框是一个不带滚动条的滚动视图套着文本视图（`ShotTextScroll`）：滚动视图是
    框，文本视图保持自己的自然高度，滚动交给 AppKit（#1110 之前是手工平移文本视图的 bounds，
    真机上光标行看不见）。
    新建文字时，如果点的位置离选区底边不足一行，**起点上移到刚好放下一行**；离右缘不足
    最小宽度（4 个字宽，且不小于 40 pt）时左移到刚好放下。输入中把字号调大、一行放不下了，
    同样再上移。提交后文字就落在输入时看到的位置。
  - **宽度跟内容走**（#1196-4）：空的时候就是最小宽度（4 个字宽，且不小于 40 pt），随打字变宽，
    到选区右缘为止（选区外的文字到屏幕右缘；最小宽度压过选区右缘），再长就折行、框变高。**任何时候框都不超出选区、
    更不超出屏幕。** 之前一律伸到选区右缘，大选区里一打开就是一条横跨屏幕的虚线。规则（两个宿主逐条相同，纯函数）：
    `reach = max(selection.right − at.x, minW)`；`w = max(min(max(wanted, minW), reach, display.right − at.x), 1)`；
    `wanted = 各条「硬换行」行实测宽度的最大值 + (fontPx + 1) / 2`（半个字高的余量，让正在打的字有地方放，
    框不必等字超出才变宽）；空的时候 `wanted` 只剩余量，所以宽度就是 `minW`。文字（`text`）和编号的说明文字（`number`）都按这条。
    mac 上宽度取决于行数（折行）、行数又取决于宽度：先按「不折行」的行数摆一遍、再看实际折了几行摆第二遍，
    最多四遍收敛（宽度只在到选区右缘处才不再跟字走，折行也只发生在那里）。
  - **工具栏永远在输入框之上、点得到**。几何上：输入框到任何一条工具栏矩形的上沿为止
    （选区和屏幕一样高、工具栏只能放进选区底边内侧时，这条才起作用）。还剩一种避不开的情形：
    **重新编辑**一段已有文字，而它本来就在工具栏现在所在的位置（它不在选区里，位置是标注的，
    不能挪）——这时输入框只留一行，按在工具栏上的那一下归工具栏：Windows 把重叠部分从输入框
    窗口里挖掉（既不画也不接点击），mac 让那一处的点击穿过输入框（**mac 上那一行字仍画在
    工具栏上面**，只保证点得到）。
  - 重新编辑的文字不挪位置，只受「高度」「宽度」「到工具栏上沿为止」三条约束；
    它不在选区里时，高度的下限是屏幕底边。
  - **编号的说明文字框与圆圈垂直居中**（#1196-3）：框的上沿 = 圆心 y − (行数 × 行高) / 2，x 仍是圆右侧
    `Annotation.captionOrigin` 的 x；行数随输入变化时重新居中——与写好之后的画法（按实测的说明文字高度居中）是同一条规则。
    之前框的上沿在新建时按「字号」算、写好后按「实测行高」算，行高大于字号，所以空的时候（新建）框的底边和圆圈对不齐、
    有字（行高已知）时才对齐。
  - **编号在编辑状态下改颜色和字号，圆圈当场跟着变**（#1196-2）：圆里的数字、圆的直径、颜色都与「提交后」一样，
    不必等变回选中状态。编辑中的编号按输入框当前的颜色和字号画（`drawOrder` 对它做覆盖），**撤销步骤不变**：
    新放的编号仍与它的说明文字是一步，重新编辑已有编号的改动提交时才成一步。
  - #1104 之前两边都是「高 = 4 倍字号、只在屏幕底边截断」：144 DPI 下最大字号的输入框高
    264 px，在选区下部一开就盖住工具栏和属性栏，点色块落进输入框里。
  - 一行的高度（像素），字号 14 / 18 / 24 / 32 / 44：mac scale 1 = 21 / 27 / 35 / 47 / 64，
    scale 2 = 41 / 53 / 70 / 93 / 128（CoreText 对字体文件实测）；Windows 96 DPI = 20 / 26 /
    35 / 46 / 64，144 DPI = 30 / 39 / 52 / 70 / 96（按字体的 usWinAscent/usWinDescent 推算，
    以真机日志 `[shot] text box opened: … a line is N px` 为准）。

### 9.4 选择、移动、修改、删除

- `选择` 工具，或任何工具下**按住 `cmd/ctrl` 点击**，点中一个标注即选中它（命中判定按
  笔画，不按包围盒；从上到下取第一个）。
- 选中后：拖动 = 移动；手柄 = 改形状（矩形/椭圆/马赛克八个手柄；直线/箭头两个端点；
  文字、编号、画笔、荧光笔只有移动）；属性栏 = 改颜色/粗细/字号；`Delete` = 删除。
- 被选中的标注画成什么样——外框、手柄的三态、指针、移动中、改形状中、与选区的框怎么区分——见 §9.8.11A。
- 这些操作每一步都能撤销、重做。重做栈在出现新操作时清空。
- 标注用**定格画面坐标**保存，不相对选区。所以**有标注之后选区仍然可以挪、可以改大小**，
  标注留在原地，超出选区的部分在导出时裁掉；整个落在选区外的标注不进 `.json`。
- 右键「退一步」的顺序：结束文字输入 → 取消选中 → 放下工具 → （没有任何标注时）清选区
  → 取消截图。**有标注时右键不会清选区**，免得一下丢光。

### 9.5 马赛克

- 用法：拖一个矩形，矩形内打码。可选中、移动、改大小、删除（改动时从定格原图重算）。
- **必须真的不可还原**：
  1. 块边长 = 所选档位，五档为 `max(档值 × 缩放, 短边 / k)` 的物理像素，档值 8、12、16、
     24、32 逻辑点，`k` 依次 12、10、8、6、4——区域再大，短边上也不超过 `k` 块。
  2. 每块输出的**所有像素相同**，颜色只由该块原像素的平均值决定（再量化到每通道 5 bit）。
     落在区域边缘的不完整块按整块处理。
  3. **原图不落地**：存的文件、进剪贴板的图、长截图的分片，一律是合成后的图；不写未打码
     的副本，`.json` 里只记矩形和档位。定格原图只在内存里，截图结束即释放。
  4. 合成顺序：马赛克先于其它标注落到图上，其它标注画在它上面。
- 判据（纯函数可测）：输出里每个块内像素全等；把区域内原像素打乱重排（保持每块均值不变）
  后输出逐字节相同。

### 9.6 长截图

- 用法（#1196-1，2026-10-08 用户定）：先定选区，点 `长截图`（进入后已有标注清掉并可撤销回来；长截图的结果不再标注）。
  选区内恢复成实时画面并让鼠标滚轮穿透给下面的应用；**滚动不再由用户来，由程序滚到底**：
  程序把指针停在选区中心（鼠标滚轮到的是指针下面的窗口，不点击——点击可能点中链接），按固定步长向下注入滚轮，
  **每一步等画面稳定再抓帧**、按内容重叠接到底部，选区旁边显示缩略预览，状态行显示已接总高度与
  「正在向下滚动…回车保留已接好的部分，Esc 取消」。**到底就自动完成**（等同按 `完成`）。
  - **步长**：和 agent 的长截图同一条（`ShotAgent.Scroll`）：选区高度的 80% 分四步，换成点
    （`ShotAutoScroll.step(height:scale:)`）；这样相邻两帧的重叠远大于拼接器要的最小重叠。
  - **每步**：把指针重新停到选区中心 → 注入滚轮 → 等 120 ms → 抓帧；帧还在动（拼接器说 `moving`）就每 60 ms
    再抓、最多 10 次，仍不稳的算「接不上」。
  - **什么时候停**（纯决策机 `ShotAutoScroll`，两个宿主同一套数）：连续 **4 步没有新内容**（`unchanged` / `seen` / `back`：
    页面到底了不会动，或回弹后什么都没加）= 到底，**1–3 步不算**（慢加载的图）；连续 **4 帧接不上**（`lost` / 尺寸不对 /
    一直在动）= 跟不上这个页面；总高到 **20000 物理像素**上限；用户按 `Esc` = 取消（不留任何东西）；
    点 `完成` 或回车 = 就此打住、保留已接好的。到底和到上限都**直接完成**；「跟不上」也完成（图就是已接好的部分），
    但弹小浮条说「页面没能再跟下去，图片到此为止。」，免得用户以为是到底了。
    选区第一帧就一直在动（视频、转圈）不滚动，第一帧就是图，浮条同上。
  - **用户自己动了滚轮或鼠标：以实际位移为准，不拦截。** 拼接器按内容找重叠，不知道也不关心位移是谁造成的；
    每一步前把指针重新停回选区中心，所以挪鼠标顶多让一步落空。用户多滚的量只要小于重叠就照常接上；
    大到接不上的那几帧丢掉（计入「接不上」）。（用 `FakePage` 假页面测过：每三步额外加塞 40 px，整页仍逐像素拼对。）
  - **没有权限不许弹系统框。** mac 上注入滚轮要「辅助功能」授权，用 `AXIsProcessTrusted()` 问（**不用**带提示的那个版本）；
    没授权时状态行说「自动滚动需要「辅助功能」权限，请慢慢向下手动滚动」，**退回旧行为**（每 120 ms 抓一帧、用户自己滚、
    点 `完成` 结束）。Windows 注入滚轮（`SendInput`）不要权限，没有这一支。
  - 结束、取消、Esc、再点一次 `长截图` 退出长截图，都把指针放回原处并停掉还没回来的那一步（`autoGeneration`）。
  - **agent 的 `screenshot_long` 路径不变**（它没有覆盖窗口，自己的一套）。
- 只做**竖直向下**。往回滚不出错（已接的部分不重复、不撕裂）。
- 拼接是纯函数：给定上一帧与当前帧，求竖直位移；顶部/底部不随滚动变化的条带（固定页眉、
  页脚）识别出来只保留一份。找不到可信重叠（滚得太快、内容在动）时**丢掉这一帧并提示
  「滚慢一点」**，不许硬拼。
- 上限：总高 20000 物理像素，到顶自动停并提示。
- 产物：整张长图 `<name>.png` 进剪贴板、存文件；另存**分片** `<name>-1.png`、`-2.png`…，
  每片高度不超过 1800 px、相邻两片重叠 120 px。`.json` 的 `tiles` 列出各片文件名与在整图
  里的 `y`。
- 用户在 Polter 窗格里粘贴这张长图时发的是**分片**（每片一次粘贴，第 1 片就是这次粘贴
  本身，其后每 150 ms 一片，间隔同第二次粘贴），因为各家 CLI 会把超过约 2000 px 的图缩小，
  整张长图缩完看不清。分片超过 8 片时只发前 8 片，并在最后那行文本里说明共几片、整图路径。
  规则与 §4.2 的后续粘贴相同（发往被粘贴的那个窗格、窗格没了就停、同窗格再粘就重来）。
  完成那一刻不往窗格里送任何东西（§3.4）——原来「前台触发就逐片送」的内容与节奏原样
  挪到了粘贴键上。粘进别的应用得到的是整张图（剪贴板里就是它）。
  ⚠️ 连发多次粘贴在各 CLI 的表现没测过，是真机格。

### 9.9 放大镜与可拖动的工具栏（#1196，2026-10-08 用户定）

用户在 mac 真机上带回九条，其中几条的规则放在这里，数字都在 `screenshot-look.json`（生成名见各条）。

#### 9.9.1 放大镜（学微信截图）

指针旁悬一块玻璃小板（同 §9.8.6 的板：阴影、玻璃、着色、两道边，圆角 `plate_radius`），上半是指针周围像素的放大图，
下半两行字：第一行**坐标**（该显示器的物理像素 `x, y`，原点在这块显示器左上），第二行一个**色块**、**色值** `#RRGGBB`
（大写）、右端一个 `⌘C`（Windows `Ctrl+C`）的小键帽。

| 常量 | 值 | 生成名（Swift / Rust） |
|---|---:|---|
| 采样 | 15 × 15 个物理像素，指针所在的那个像素在正中（奇数） | `Size.magnifierCells` / `MAGNIFIER_CELLS` |
| 每个像素放大成 | 8 pt（取整成整数像素，所以各格一样大、网格在像素格线上） | `magnifierCell` |
| 板到指针的距离 | 16 pt | `magnifierOffset` |
| 板内边距 | 8 pt | `magnifierPad` |
| 放大图的圆角 | 6 pt（只裁放大图） | `magnifierImageRadius` |
| 网格线 | 每格一条，0.5 pt（至少 1 px），黑 22% | `magnifierGridLine`、`Colour.magnifierGrid` |
| 正中那一格的框 | 总宽 1.5 pt：里圈白、外圈黑 85%，各占一半（至少 1 px） | `magnifierCentreLine`、`magnifierCentreInner/Outer` |
| 屏幕外的格子 | `#202020`（指针靠边时采样窗口会伸出屏幕） | `magnifierOffScreen` |
| 行间距 / 色块 | 6 pt / 直径 12 pt | `magnifierRowGap`、`magnifierSwatch` |
| 「已复制」闪多久 | 900 ms | `TransitionMs.copiedFlash` |

- **放大是最近邻，不插值**；放大图取自**定格的原图**（`FrozenImage`），色值也是原图那个像素，**不是毛玻璃**。
- **位置（纯函数 `ShotMagnifier.place`，两个宿主同一条）**：默认在指针的右下，`x = p.x + offset`、`y = p.y + offset`；
  右边放不下（`x + w > display.right`）翻到指针左边 `p.x − offset − w`，下边放不下翻到上边 `p.y − offset − h`；
  最后夹进屏幕。所以**板永远不盖指针正下那个像素**（`offset ≥ 1`，翻面后在另一侧；屏幕比两倍 offset 加板还小才例外）。
  mac 测过：扫 4 万多个指针位置，板都在屏幕内且不含指针像素。
- **什么时候显示**：没有选区的悬停阶段、拖出选区（含按下还没过 3 pt 阈值时）、拖手柄、整体移动选区的**全过程**，
  直到框结束；**选区定下进入标注后不显示**，输入文字时、长截图进行中也不显示（编辑器的 `showsMagnifier`）。
  画在覆盖层的**最顶上**（盖过选区尺寸标签、工具栏等），只在指针所在的那块显示器上画。
- **`cmd+C`**（放大镜显示着的时候）把色值文本（如 `#1A2B3C`）写进剪贴板，并在色值那处闪「已复制」`copied_flash` 毫秒，
  **不结束截图**；放大镜没显示时 `cmd+C` 不管事（也不动剪贴板）。小键帽 `⌘C` 就是给用户的提示。色值取自指针在的那个像素；
  指针不在任何显示器上则没有可复制的。**这一刻起剪贴板里是文本；截图完成时才会重新写进图片**（§3.4）。
- 取样、网格、翻边、文字、`cmd+C` 的判断都是纯函数，带测试（`ShotMagnifier*`）。

#### 9.9.2 工具栏可拖动

- 按住玻璃板上**不是格子的地方**（边距、组间空隙、两行之间）拖动，整块板（两行一起）跟着走，指针是抓手（拖时握拳）；
  板**不能拖出屏幕**——夹的是两行的总高（`footprint`），不随第二行显隐跳；拖动时板下的玻璃逐帧重取。
- 用户拖过之后，**本次截图内**不再自动跟着选区挪位置（记住板左上角在屏幕上的位置）；**重新选区**（选区清掉再选）或
  下一次截图回到自动摆放。长截图进行中板也能拖。
- **自动摆放**不变（选区下方、右缘对齐；下方放不下放上方；上下都放不下放选区内侧底部），只改一处：**选区 = 整屏（上下都放不下）
  时，板在选区内侧底部水平居中**（原先右对齐，贴在屏幕角上）：`x = selection.x + (selection.w − bar.w) / 2`，再夹进屏幕。
  选区尺寸标签在选区内侧左上，板在底部，互不相压。

### 9.7 实现细则（两个宿主逐条相同）

Windows worker 开工时提出、总管定的（2026-10-06）。纯逻辑各自实现，但读数必须一样。

- **马赛克**：块网格以矩形左上角为锚。右/下边不满一块的：**不足半块的并进相邻的那一块**
  （免得一条 1 px 宽的边把那一列的明暗漏出去），够半块的按它实有的像素求平均。均值 = 各通道
  整数和 ÷ 像素数（向下取整）；5 bit 量化 `q = avg >> 3`，输出 `(q << 3) | (q >> 2)`。多个
  马赛克重叠时每个都从定格原图算，不叠算。`.json` 的 `block` 写档值（逻辑点），不写像素。
- **荧光笔**：一笔只混一次（自交处不加深），逐通道 `out = dst × (255 − 0.4 × (255 − c)) ÷ 255`；
  圆头；宽 = 档值 × 4 × 缩放。
- **命中**：到线段/轮廓的距离 ≤ `max(线宽 / 2, 4 点 × 缩放)`；文字、编号按包围盒；马赛克按
  整块矩形；从上往下取第一个。
- **编号**：圆直径 = 1.5 × 字号像素；说明文字起点在圆右侧 0.3 × 字号处、与圆垂直居中。
  删掉中间的编号不重排，下一个 = 现有最大 + 1。放编号并紧跟着写说明算一步撤销。
- **形状**：`shift` 时矩形/椭圆取 `max(|dx|, |dy|)`；直线/箭头保持长度吸到最近的 45°。
  丢弃：矩形/椭圆/马赛克宽或高 < 2 px、线长 0、画笔只有 1 个点。画完后工具不变，新形状
  不自动选中。
- **选择工具是进入时的默认工具。** 选择工具下：点中标注 = 选中/拖动；点选区手柄 = 改选区；
  选区内空白处拖 = 挪选区；选区外点击 = 没有标注时重新选区、有标注时无动作；空白处双击 =
  完成；双击文字 = 重新编辑。**选区的手柄和挪动只在选择工具下有效**。任何工具下
  `cmd/ctrl` + 点击 = 选中。
- **属性栏**：有选中的标注时显示它的属性（哪怕当前是别的工具）；此时数字键与 `[` `]` 只改
  这个标注，不改工具的记忆值。`[` `]` 到头不回绕。属性栏不显示时也占位，工具栏不跳。
- **文字**：`at` = 第一行左上角。点输入框外只提交，这一下不同时新建下一段。
- **导出**：部分超出选区的标注图上裁掉，`.json` 里坐标不夹（可为负、可超出尺寸）；整个在外
  的不写。
- **右键退一步**：结束文字输入 → 取消选中 → 工具回到「选择」→（无标注）清选区 → 取消；
  有标注且已无可退时无动作。
- **撤销粒度**：一次拖动、一次属性修改、一段文字提交、进长截图清标注，各算一步。
- **工具栏尺寸**：按钮 28 点、间距 4、组间距 12、内边距 6；属性栏色块 20 点。
- **悬停提示**格式：「名称 (快捷键)」。
- **记忆值**存宿主状态目录下的 `shot-tools.json`（与截图目录同级），不进配置。
- **导出只有一个出口类型**：合成图。存 PNG、写剪贴板、切分片都是它的方法；定格原图的类型
  没有任何编码或写出的方法。

补充（Windows 做完 W1、W2 后提出，总管同意，mac 照做）：

- 马赛克盖在被涂黑的屏蔽窗格上时，块的颜色按**涂黑之后**的像素算：先涂黑，再算马赛克。
- 文字提交时去掉两端空白，`\r\n` 归一成 `\n`；编辑到空 = 删除该段文字（可撤销）。
- **长截图的拼接**：重叠可信的条件是三条同时成立——重叠至少 `max(24 行, 带高 / 8)`；
  其中 97% 的行逐像素相同；重叠里至少有 4 种不同的行（全是空白不算）。多个位移都对得上时
  取最小的（周期性页面宁可少接）。固定页眉/页脚从第一对「动了」的帧里取上下两端不变的行；
  先按「不变的行都是固定带」拼，拼不上才把带的平坦内缘让给页面。页脚取最后一帧的。
- **只接稳定的帧**（2026-10-06，真机缺陷 3 之后定；两个宿主相同）：一帧只有与**紧挨着的上一次
  抓取**逐像素相同时才交给拼接；否则只记下它、等下一次（日志里记为 held back / still moving，
  不算丢帧）。第一帧同样要抓到两次相同才算。原因：有的程序滚动时先把旧内容整体上移、新露出
  的那条后画（记事本），120 ms 的抓帧会抓到「滚了但底部还没画完」的帧——空白行落在两帧对齐
  时比较的范围**之外**，所以它照样对得上、空白被当成页面接进去；空白少时留下一条盖住半行字的
  空白带，空白多时后面的真实帧再也和它对不上，整图不再增长。这条规则不调 97% 的容差。
  代价：每帧晚一个抓帧间隔才算数；区域里有一直在动的东西（视频、转圈动画）时一帧都接不上。
  agent 的长截图每滚一格后同样抓到稳定为止（至多 10 次、间隔 60 ms，仍不稳算作接不上）。
- **不随内容滚动的列不参加比较**（2026-10-06，#1096 定、#1099 扩到滚动条滑块；两个宿主相同）：
  比较一对帧（上一张接上的帧与当前帧）之前，先在滚动带的行里逐列数「这一列哪些行变了」，
  **变了的行至多连成两段、且合计不到带高的一半**的列，求行哈希时跳过；上面三条（重叠下限、
  97%、4 种不同的行）原样用在剩下的列上。每对帧各算各的，不记忆。
  - 一行都没变（0 段）：不滚动的东西——窗口边框外沿、一条窗外背景、固定侧栏；或者滚动前后
    看起来一样的页面（页边距）。一段或两段：这一列里有一样东西挪了位置而其余没动——滚动条的
    滑块（原来的位置一段、现在的位置一段），固定侧栏里「当前章节」的高亮。真正滚动的页面，
    凡是有内容的地方都会变：文字是每一行一段（很多段），图片是从上到下一整段（占满带高），
    所以留下来参加比较。
  - **按排除后一列都不剩时，只排除一行都没变的列。** 整页只有一样东西（空白页上一张图）时，
    它经过的每一列都是「一段」，而这些列正是唯一的依据。
  - 原因：行哈希原先盖整行，选区里只要有一列既不随内容滚动、竖向又不是一个颜色，对齐后每一行
    都差这一个像素，97% 变成 0%，一帧都接不上、高度停在一屏（Windows 真机，记事本与 Edge，
    选区左缘压在窗口边框上；agent 按 `window_id` 截记事本整窗，7 帧丢 6 帧）。竖向同色的静止列
    本来就不碍事（移了位还是同一个值）。
  - 图上这些列**照各帧拍到的样子留着**：第一帧的整列，下面接每一帧新增那几行里的那一段。
    所以边框、滚动条在长图里是一段段重复的屏幕内容，不是连续的页面；内容列不受影响。
  - **按「变化怎么分布」判，不按「变了多少行」判，也没有「对不上再放宽」的第二轮。** 一摞
    一模一样的文本行旁边的行号列，滚动后九成的行没变，它却是唯一能说出「滚了三行而不是一行」
    的东西——它的变化是每行一段，所以留着（判据：`a_column_that_changed_in_a_few_rows_is_still_evidence`）。
    按「多数行没变」排除它，或者在没有重叠时放宽再试，都会把图无缝地接短。
  - 会误判 / 仍接不上的情形：
    1. **滑块很长、或一步滚得很远**，使滑块那几列变了的行达到带高的一半（短文档：滑块本身就占
       半条槽）：那几列不算滑块，仍参加比较，这一帧 Lost（不是错接）。带纹理、每帧都在变的滑块
       同理。把选区收到滚动条以内，或滚小步一点。
    2. **只有一小块在滚**（选区框了整个窗口，其中一个嵌套列表在滚）：两侧不动的列被排除后能
       接上，图里那几列是重复的屏幕内容——同上「照拍到的样子留着」，不是错位。
    3. **被排除的列恰好是唯一能否定一个更小位移的证据**：其余的列在更小的位移上也有 97% 对得上
       （近似周期），而能否定它的那一列要么整列没变（以真实位移为周期），要么只在一两段里变
       （一摞几乎相同的行里唯一明显不同的那一行，只落在少数几列上）。此时取到那个更小的位移，
       接短。构造得出，没在真机见过。
    4. 排除后剩下的列很少（例如只有一两列在变）时，「4 种不同的行」是唯一的防线；一两个像素宽
       的列里凑出 4 种不同的值并在 97% 的行上对齐，理论上可能把没有重叠的两帧接上。没有设
       「至少剩多少列」的下限：窄选区（几十像素宽）是合法用法。
- **从没接上过一帧时交出第一屏**（2026-10-06，#1099，总管定；两个宿主相同）：选区里有一直在动的
  东西，直到结束没有任何一帧稳定过（「只接稳定的帧」的代价），结果是**抓到的第一帧**，原样一张、
  高 = 选区高，照常写文件、进剪贴板；不再是「0 px、什么都不写」。「第一帧」是进入长截图后的
  第一次抓取，不是最后一次。说明走三处：状态行在连续约 1 秒（8 次抓取）没有一帧稳定之后，把
  「慢慢向下滚动…」换成「画面一直在动，没能接长。」；日志在 `finished` 行之后多一行
  `long screenshot: the region never held still for two frames in a row, so nothing was joined; the picture is the first frame taken, <h> px tall`
  （`finished` 行里仍是 `0 px tall`——那个数是「接上的高度」）；agent 的 `long` 不滚动、直接返回，
  `"pages": 0, "stopped": "moving"`。只要接上过一帧就不是这种情形，之后再动照旧算 held back / Lost。
- 抓帧间隔 120 ms。长截图模式里只有 长截图（退回）/ 取消 / 完成 三个按钮和 `Enter` / `Esc`
  有效；右键或再点「长截图」退回标注状态。
- 总高不超过 1800 px（只有一片）时不存分片文件，粘贴的是整图路径。「共 n 片」那行只在有片
  没发出去时才发。触发时 Polter 在不在前台都一样：用户在窗格里粘贴时给的是分片（§9.6），
  不是整图路径。

#### 9.8.1 总则（用户定的六条）

1. 工具栏是**一块深色薄玻璃板**，装两行；只有深色一套，不跟系统外观、不跟底下画面的明暗切换。

3. 图标是 `icons.png` 那 15 个，另加 `save`（#1196），再加字号的 5 个 T。没有别的候选。「选择」是 mac 箭头光标的造型。
7. 每个可点的格子都有 常态 / 悬停 / 按下；能保持选中的另有 选中。
8. 文字输入框的框是黑白相间的虚线。
9. 被选中的标注有自己的外框和手柄，见 §9.8.11A。
4. 字号 5 档用 5 个大小不同的 T 表示。
5. 选区以外是毛玻璃：**模糊 3 pt（高斯 σ）+ 压暗 6%**；选区以内是原图。
6. 没有选区时：指针吸附到的窗口清晰，其余毛玻璃；指针换窗口，清晰区跟过去；没有窗口可吸附，整屏清晰。
   拖出选区、移动、改大小的整个过程：选区内清晰、其余毛玻璃，**逐帧实时**。标注阶段、长截图阶段相同。

#### 9.8.4 各个状态怎么画（定值）

格子里的内容分两类：**单色内容**（图标、圆点、T、棋盘格——用「墨色」画）和**色块**（有自己的颜色）。
完整的矩阵见 `states.png`。

| 状态 | 格子底（圆角 7） | 墨色 | 环 + 光晕 |
|---|---|---|---|
| 常态 | 无 | `#FFFFFF` | 无 |
| 悬停 | 白 14% + 内沿 0.5 pt 白 30% 的发丝线 | `#FFFFFF` | 无 |
| 按下（鼠标按住期间） | `#419CFF` 18% | `#419CFF`（色块不变色） | 有 |
| 选中 | 无 | `#419CFF`（色块不变色） | 有 |
| 选中 + 悬停 | 白 14%（没有发丝线，环已经在那儿了） | `#419CFF` | 有 |
| 不可用 | 无；**悬停、按下都不变** | 白 32% | 无 |

- **哪些格子能保持选中**：工具（当前工具）、色块（当前颜色）、档位（当前档位）、长截图（进行中）。
  按下 → 松开后留在「选中」，原先选中的那个回到常态。
- **一次性动作没有选中态**：撤销、重做、取消、完成。按下期间画「按下」，松开即回到悬停（指针还在上面）或常态。
- **「取消」「完成」松开时才生效**，而且要松在同一个按钮上：按下只显示按下态，滑出去再松开等于没按。
  这两个按钮一生效整个定格界面就没了，按下即生效的话它们的按下态永远看不见。其余按钮都是按下即生效
  （撤销、工具、色块……）。键盘的 `Esc` / `Enter` 不受影响。
- **悬停为什么不带蓝**：蓝色（环、光晕、墨色）只表示「选中 / 正在按」。悬停只是「指针在这儿、点得动」，
  用一片中性的亮玻璃，和选中一眼分得开，也不会在一排里同时出现两处蓝。
- **完成与取消**：两者平时与别的图标一样安静；悬停同上；**按下时**「完成」= 实心 `#419CFF` 底 + 白勾 + 光晕，
  「取消」= 通用的按下态。常态下两者没有主次之分，只靠位置（最右）和图形。
  （`states.png` 最后一行画的「读法 B」——「完成」平时就是实心强调色的主按钮——**未采用**。）

##### 9.8.4.0 状态之间的过渡

| 从 → 到 | 时长 | 说明 |
|---|---:|---|
| 常态 → 悬停 | 80 ms | 底和发丝线淡入 |
| 悬停 → 常态 | 120 ms | 淡出 |
| 任意 → 按下 | 0 | 按下必须当帧有反应 |
| 按下 → 选中（可保持选中的） | 120 ms | 只有 18% 的蓝底淡出，环和光晕不动 |
| 按下 → 悬停 / 常态（一次性动作） | 120 ms | 环、光晕、蓝底一起淡出，墨色回白 |
| 选中 → 常态（别的格子被选中了） | 100 ms | 环和光晕淡出；与新格子的按下同时开始 |
| 变成不可用 / 恢复可用 | 0 | |

线性。「减少动态效果」开着时全部为 0。提示在悬停 500 ms 后出现、离开即消失（现有行为不变）。
每个格子的悬停底、按下底、环（连光晕）、墨色是四条各自独立的过渡，所以「旧格子的环 100 ms 淡出」与「新格子按下即亮」同时进行。

**这张表和 §9.8.7 的过渡表是完整定义，mac 照此实现。Windows 有两处已知的差异，不算缺陷：**

- 「整屏清晰 ↔ 别的」直接切，不做 120 ms 过渡——每帧混合整屏，在没有显卡加速的机器上跟不上（这正是 §9.8.7 末尾写的退路）。
- 按下新格子的那一帧，旧格子的环即时消失，没有 100 ms 的淡出。

##### 9.8.4.1 选中环

##### 9.8.4.2 光晕

以格子的圆角矩形的**边**为零线，d 是一点到这条边的距离（pt，里外都算正）。光晕是 `#419CFF`，不透明度

    α(d) = 0.40 × ½ × erfc( d / (σ·√2) )，σ = 2 pt

| d (pt) | 0 | 1 | 2 | 3 | 4 | ≥ 5 |
|---|---:|---:|---:|---:|---:|---:|
| α | 0.200 | 0.123 | 0.063 | 0.027 | 0.009 | 0 |

画在环的下面、悬停底 / 按下底的上面、格子内容的下面。按下与选中用同一圈光晕。它向外最多到 4 pt，正好是格子间距，不会盖到邻格的内容。
（这等价于效果图里的 `box-shadow: 0 0 4px` 里外各一个；实现时按距离查上表即可，不必真的做一次模糊。）
「减少透明度」开着时不画光晕。

##### 9.8.4.3 属性栏三种内容

- **色块**：9 个格子，每格中心一个直径 16 的圆，填标注色，内侧 0.5 pt 白 30% 描边。
- **粗细**：5 个格子，中心圆点直径 3 / 5 / 8 / 11 / 15。
- **字号**：5 个格子，各画一个 T（§9.8.5.3）。
- **马赛克块大小**：5 个格子，两个宿主逐条相同：

##### 9.8.5.4 两个平台从同一份数据画

改前两边是各写各的形状代码，其中 5 个图标取自各自的系统字体——这是两边不一样、大小不齐的根源（`audit.md`）。
现在是**一份数据 + 生成两边的源码 + 一道闸**（#1115）：

| 文件 | 是什么 |
|---|---|
| `src/input/screenshot-look.json` | 唯一的来源：图标路径、这一节的全部尺寸、颜色与不透明度、过渡时长、玻璃与模糊的参数、虚线的实空长度 |
| `tools/gen-screenshot-look.py` | 生成器。`--write` 才写盘；不带参数只比较、不写（免得「把 `tools/` 下的脚本挨个跑一遍」时它先把树修好、闸再来看） |
| `windows/shots/src/look.rs` | 生成物，入库，不许手改 |
| `macos/Sources/Features/Screenshot/ShotLook.swift` | 生成物，入库，不许手改 |
| `tools/the-screenshot-look-is-one-set.py` | 闸：两份生成物逐字节等于数据此刻生成的结果；图标墨迹在活动区内（登记的例外按确切外框核）；五个 T 逐档变宽变高；工具栏 16 个、字号 5 个 |
| `windows/shots/src/icon.rs`、`macos/Sources/Features/Screenshot/ShotIconRaster.swift` | 两边各一份「把一个图标画进格子」的纯函数，同一条规则 |

改外观的步骤：改 JSON → `python3 tools/gen-screenshot-look.py --write` → 三个文件一起提交。

- 生成时把每条路径**展开成只含「移到 / 直线 / 三次贝塞尔 / 闭合」的绝对坐标序列**（圆弧、圆角矩形、椭圆都在
  生成时化成贝塞尔，坐标取 5 位小数）。两个宿主不实现 SVG 路径语法和圆弧——那正是最容易各自走样的地方。
- **栅格化规则（三处同一条：生成器的 Python、Rust、Swift，算术顺序相同）**：24 单位的画板是 `20 pt × 缩放` 像素见方，
  在格子里居中；每个像素取 4 × 4 个采样点，采样点在填充内（奇偶规则）、或到路径的距离不超过半个线宽，就算被这一部分
  盖住——「到路径的距离 ≤ 半线宽」正是圆端、圆角连接的描边；一段贝塞尔折成 16 段直线；各部分按顺序叠
  （`a ← a + 覆盖率 × 不透明度 × (1 − a)`）；出来的是 0–255 的覆盖率，不是颜色，调用方自己上色。
  不用 CoreGraphics / GDI 的描边：两者画出来只是相似，不是相同。
- **两边一致靠什么证**：生成器用自己的实现把每个图标在缩放 1 / 1.5 / 2 下画进 28 / 42 / 56 px 的格子，把墨迹外框
  （覆盖率 ≥ 50% 的像素的外框与个数）写进两份生成物；两边各有一条测试，断言自己画出来的外框就是这一张表。
  容差：每条边 ±1 px、像素个数 ±2%（留给浮点舍入不同的平台）；2026-10-07 在这台 Mac 上 Rust 与 Swift 的
  60 个外框都与表**逐像素相同**，测试同时断言了这一点。
- 不在运行时去资源目录读数据文件：多一种「文件缺失」的失败，而它的症状是工具栏空白。
- 这一步**只到底座**：两个宿主现有的工具栏还在用旧的绘制代码，接线是各自的下一步。

#### 9.8.6 玻璃各层的做法与顺序（定值）

所有玻璃都从进入定格时算好的图里取，不靠系统合成器。进入定格时每块屏备三样（§9.8.9.1）：
定格原图 **F**、缩小的原图 **D**、选区外用的模糊图 **O**。

##### 9.8.6.1 选区外

`O` = 对 F 做高斯模糊 σ = 3 pt，再乘 0.94（即叠 6% 的黑）。不调饱和度。整屏一张，进入定格时算一次。

##### 9.8.6.2 工具栏的板（提示、状态行、尺寸标签同一套）

对板的圆角矩形（抗锯齿的覆盖率作遮罩），自下而上：

1. **投影**（板外）：板的形状向下偏 4 pt，高斯 σ = 7 pt，黑 30%。
2. **外沿线**：贴着板外侧 0.5 pt，黑 35%。
3. **底**：取 **D**（不是 O）在板矩形里的那一块，做高斯模糊 σ = 12 pt，放大到板的大小。
4. **饱和度 × 1.5**：`c' = L + (c − L) × 1.5`，`L = 0.2126 R + 0.7152 G + 0.0722 B`；然后**亮度 × 0.5**。结果夹到 0–255。
5. **染色**：叠 `#1D1F20` 66%。
6. **行间分隔线**（属性栏显示时）：白 18%，0.5 pt。
7. **内沿线**：贴着板内侧 0.5 pt，白 22%。
8. 格子：悬停底 → 光晕 → 环 → 内容。

没有高光渐变、没有折射（那是方案一的东西）。

工具栏的模糊比选区外的重（12 pt 对 3 pt），所以**另算**，但只算板那一小块、而且是在缩小的 D 上算：
板 520 × 80 pt 在 2x、缩小 4 倍后是 260 × 40 像素，三趟盒式模糊是几万次加法（估：远小于 1 ms）。
只在板的位置或大小变了的时候重算；悬停、选中只重画第 8 步。提示、状态行、尺寸标签各自同样处理。

##### 9.8.6.3 高斯模糊的实现（两边同一算法）

「缩小 k 倍 → 三趟盒式模糊（横竖各三次，半径 r）→ 双线性放大」。三趟宽 `2r + 1` 的盒式叠起来的
σ² = `((2r + 1)² − 1) / 4`（缩小图上的像素）。

| 缩放 | k | 选区外 σ = 3 pt 的 r | 实得 σ（原图像素 / pt） | 板 σ = 12 pt 的 r |
|---|---:|---:|---|---:|
| 1x | 2 | 1 | 2.8 px / 2.8 pt | 6 |
| 1.5x | 2 | 2 | 4.9 px / 3.3 pt | 9 |
| 2x | 4 | 1 | 5.7 px / 2.8 pt | 6 |
| 其它 | 缩放 ≥ 1.75 取 4，否则 2 | `round((√(4s² + 1) − 1) / 2)`，至少 1，其中 s = σ(pt) × 缩放 / k | | 同式 |

缩小是每 k × k 像素取平均；边缘取最近的像素。参考实现是 `bench/blur_bench.c` 的 `downsample`、`box_blur`、`upsample`。
缩小和放大本身还会带来一点模糊，所以「实得 σ」是下限；验收按 §9.8.13 的取样判据，不按这张表。

#### 9.8.7 各阶段的画面与规则（定值）

记号：**F** 原图，**O** 选区外的模糊图，「洞」= 画成 F 的那个矩形，其余画成 O。

| 阶段 | 洞 | 说明 |
|---|---|---|
| 没有选区，指针吸附到一个窗口 | 那个窗口的矩形（与本屏求交） | 另描 2 pt 强调色边 |
| 没有选区，没有窗口可吸附（指针在桌面上、或吸附到的就是整屏） | 整屏 | 这块屏不画 O |
| 正在拖出选区 / 拖手柄 / 整体移动 | 当前的选区矩形 | 逐帧，见 §9.8.8 |
| 选区定了、画标注 | 选区矩形 | 画面静止 |
| 长截图进行中 | 选区矩形，洞里是活的画面 | 洞外仍是进入定格时的 O |

多显示器：每块屏各有自己的 F / D / O；指针不在的屏没有吸附窗口，按「没有窗口可吸附」之外的另一条——
**指针不在的屏整屏画 O**（它不是指针所在处，也不是选区）。选区只在一块屏上，别的屏整屏 O。

过渡（都是 F 与 O 两张现成的图按比例混合，**不重新模糊**）：

| 什么时候 | 做什么 | 时长 |
|---|---|---:|
| 进入定格 | 第一帧就按上表画，不做淡入 | 0 |
| 吸附的窗口换了（A → B） | A 的矩形从 F 淡到 O，B 的矩形从 O 淡到 F，线性；描边立刻换到 B | 120 ms |
| 从有窗口变成没有窗口，或反过来 | 变化的那部分同样线性混合 | 120 ms |
| 按下鼠标、还没动 | 不变 | — |
| 按下后移动超过 3 pt（开始拖出选区） | **这一帧起洞就是拖出来的矩形**；原先清晰的区域（窗口矩形，或整屏）里洞以外的部分从 F 淡到 O | 120 ms |
| 按下没拖就松开（选中吸附的窗口） | 洞不变（就是那个窗口），描边换成选区边线 + 手柄，工具栏出现 | 0 |
| 松手、选区落定 | 工具栏直接出现，不做动画 | 0 |

淡入淡出期间洞的位置仍然逐帧跟框，混合只发生在洞以外。过渡是可以被打断的：新的过渡从当前的混合比例接着走。
系统开了「减少动态效果」（mac `accessibilityDisplayShouldReduceMotion`，Windows `SPI_GETCLIENTAREAANIMATION` 为假）时，
所有 120 ms 都改成一帧切换。

「从整屏清晰开始拖」那 120 ms 要整屏混合，每帧 840 万像素（3600 × 2338）——耗时没量过；跟不上时的退路是
这一种情形不做过渡，直接切。

#### 9.8.8 拖动时逐帧的实现约束

**约束：拖动期间每一帧只做合成，不重新模糊。** 一帧 = 「O 铺底 → 洞里贴 F → 标注 → 边线和手柄 →
尺寸标签 → 工具栏」。洞的矩形和边线的矩形取自**同一次鼠标事件算出的同一个值**，在同一帧里画、一起上屏；
不许出现框到了新位置而洞还在旧位置的帧，也不许松手才补。

**脏矩形。** 记上一帧的洞 H₀、这一帧的洞 H₁（像素）。

    e      = px(5)                       // 盖住手柄（半径 3.5 pt）和 1 pt 边线
    dirty₁ = (H₀ ∪ H₁ 的外接矩形) 向四周扩 e
    dirty₂ = 上一帧和这一帧的尺寸标签矩形
    dirty₃ = 上一帧和这一帧的工具栏、提示、状态行矩形，各向左右扩 px(14)、向上 px(10)、向下 px(18)（投影）

对每个脏矩形：拷 O → 与 H₁ 的交集拷 F → 重画与它相交的标注和界面。上屏也只上这些矩形。
拖出选区的过程中工具栏不显示（现有行为），所以通常只有 dirty₁ 和 dirty₂。

按 3600 × 2338、120 Hz（每帧 8.33 ms）：

| 重画范围 | 像素 | 字节 | 本机拷贝（实测，§9.8.9.2） |
|---|---:|---:|---:|
| 整屏 | 8,416,800 | 33.7 MB | 0.79 ms |
| 脏矩形（例：1600 × 1000 的选区一帧挪 24 px，扩 8 px → 1640 × 1040） | 1,705,600 | 6.8 MB | 0.38 ms |

#### 9.8.9 开销

##### 9.8.9.1 进入定格时备什么（每块屏）

| 图 | 大小（3600 × 2338） | 用处 |
|---|---:|---|
| F 定格原图 | 33.7 MB | 本来就有 |
| D 缩小 k 倍的原图 | 2.1 MB（k = 4） | 工具栏等玻璃的底 |
| O 选区外的模糊图，**全分辨率** | 33.7 MB | 每帧铺底 |

**进入定格时最多等模糊图 50 ms**（数据里的 `glass.wait_ms`，两个宿主同值）：等到了第一帧就是毛玻璃；
没等到就先画压暗 43%，算好后整屏换成毛玻璃。优化构建在 3600 × 2338 上约 33 ms，赶得上；调试构建约 1.7 s，赶不上。

O 存全分辨率而不是只存小图：只存小图的话每帧要把脏矩形现放大，按 §9.8.9.2 的 3.7 ns/像素，1640 × 1040 要约 6.3 ms，
吃掉 120 Hz 一帧的大半（算的）。退出定格时 D、O 一起释放。内存吃紧时的退路是不存 O、选区外退回压暗。

##### 9.8.9.2 实测（原文在 `bench/result.txt`，程序是 `bench/blur_bench.c`）

机器：Apple M5；Apple clang 21.0.0，`cc -O2`；**单线程**，纯 C、没有手写 SIMD。位图 3600 × 2338 RGBA
（8,416,800 像素；程序打印的 32.1 MB 是 MiB，即 33.7 MB）。中位数。

    A  downsample 4x -> 3 box passes r=2 -> bilinear up (+sat,dim) median   39.70 ms  (min 39.09, max 41.26, n=9)
    A' same, heavy: 3 box passes r=6 at 1/4 size               median   39.48 ms  (min 39.07, max 39.86, n=9)
    A1   of which: downsample only                             median    0.80 ms  (min 0.76, max 0.92, n=9)
    A2   of which: 3 box passes at 900x584                     median    7.43 ms  (min 7.22, max 7.54, n=9)
    A3   of which: bilinear upsample + sat + dim               median   31.06 ms  (min 30.75, max 31.39, n=9)
    B  full-resolution 3 box passes r=9 (no downsample)        median  306.51 ms  (min 306.02, max 313.48, n=5)
    C  per-frame, whole screen: memcpy blur + copy selection   median    0.79 ms  (min 0.77, max 1.25, n=15)
    D  per-frame, dirty rect (union of old/new + 8 px ring)    median    0.38 ms  (min 0.37, max 0.42, n=15)

读法：
- **这次跑的是半径 2 和 6，不是定稿的半径 1。** 盒式模糊用滑动窗口，耗时与半径无关（A 与 A′ 相差 0.2 ms 就是证据），
  所以定稿档的一次性耗时也在 40 ms 上下；没有为半径 1 另跑一遍。
- A 里放大那一步带了饱和度；定稿的 O 不调饱和度，只会更快，没另量。
- 大头是放大（31 ms），不是模糊（7 ms）。它可以按行分给多个线程，这里没做。
- **这些数只代表这台 M5。** Windows 测试机是没有显卡加速的虚拟机，我没有在它上面量；接线前在测试机上跑同一份
  `blur_bench.c`。按经验慢 3–8 倍（估），即一次性 120–320 ms——那就把算 O 放到后台线程，第一帧先画压暗，算好了换上。

#### 9.8.10 两个平台怎么落地

**都不用系统的玻璃。** mac 的 Liquid Glass 控件只在 macOS 26 以后有，而部署目标是 13.0
（`macos/Ghostty.xcodeproj` 的 `MACOSX_DEPLOYMENT_TARGET = 13.0`）；Windows 的 Mica / Acrylic 各版本样子不同。
两者模糊的都是「窗口后面的东西」，在这里就是我们自己那张定格图——自己算结果一样，还能两边同值。

| | mac | Windows |
|---|---|---|
| 现在怎么画 | `ShotOverlayView.draw` → `ShotSession.draw`：每次把整张定格图画进 `CGContext` 再画压暗 | `compose_overlay` 每次重建整张画布（DIB），`paint` 里 `BitBlt`（`windows/host/src/shot.rs`） |
| 算 O、D | 同一份 C 逻辑的 Swift 版，直接算像素数组；或 vImage 的盒式卷积（结果要按 §9.8.13 验） | 同一份逻辑的 Rust 版 |
| 逐帧 | F 和 O 各做成一个 `CGImage`，`setNeedsDisplay(_:)` 传脏矩形，在 `draw` 里按 §9.8.8 画；或两个 `CALayer`（下 O 上 F，F 带矩形遮罩），拖动只改遮罩，合成交给窗口服务器 | 画布常驻；每帧只改脏矩形、只 `BitBlt` 脏矩形（`shot.rs` 里已有按矩形贴的路径） |
| 抗锯齿的圆角、环、图标 | CoreGraphics 自带 | **GDI 没有抗锯齿**，要带一个光栅器把路径直接画进 DIB 的像素：纯 Rust 的 `tiny-skia`（BSD-3）或自己写覆盖率扫描线；GDI+ / Direct2D 也行。现在 Windows 的图标是 GDI 的非抗锯齿形状 + Segoe UI 字形，这一步绕不开 |
| 半透明叠加 | CoreGraphics | 自己做预乘 alpha 的 over；GDI 的 `AlphaBlend` 只能整块等透明度 |
| 透明底的输入框 | `NSTextView.drawsBackground = false`，字晕用 `NSShadow` | 现在是 EDIT 子窗口，透明底不是改个颜色的事（§9.8.11 末） |

**Windows 能不能跟上屏幕刷新。** CPU 这边的合成按 §9.8.8 是亚毫秒级（在 M5 上；测试机上没量）。不确定的是把 DIB
贴到窗口：整屏 33.7 MB 的 `BitBlt` 在有显卡的机器上通常几毫秒，在没有加速的远程会话里可能超过一帧——**没量**。
降级按顺序：
1. 只改、只贴脏矩形（上面已经是默认做法）；
2. 还跟不上就丢帧不排队：`WM_PAINT` 本来就是合并的，只画最新的鼠标位置。帧率会低于屏幕刷新，但每一帧里
   洞和框是同一个矩形，仍然没有滞后和撕裂；
3. 最后只重画新旧洞的对称差（几条边带）。

**「减少透明度」开着时**（mac `accessibilityDisplayShouldReduceTransparency`；Windows 设置里「透明效果」关，
即 `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\EnableTransparency = 0`）：
- 不算 D、O；选区外 = F 上叠黑 43%（改前的样子）。
- 板、提示、状态行、尺寸标签：不透明底 `#3D3F40`，1 pt 描边 `#8E8F90`，没有投影以外的效果，没有光晕。
- 布局、图标、选中环不变。见 `scheme.png` 最后一格、`outside.png` 下排。

**Windows 高对比度模式**（`theme::high_contrast()`）：按 `theme.rs` 的既有约定让位给系统色——板底 `COLOR_BTNFACE`、
图标 `COLOR_BTNTEXT`、选中环 `COLOR_HIGHLIGHT`、不可用 `COLOR_GRAYTEXT`，不模糊。这一条照的是 `theme.rs` 的既有约定。

#### 9.8.11 透明文字输入框（定值）

输入框**没有底色**，底下的画面完全看得见。设输入框的矩形为 B（§9.3 的几何规则不变），字色为 C，
C 的相对亮度 ≥ 0.5 时「反色」是黑，否则是白（九个标注色里只有黄和白的反色是黑）。

| 部件 | 画法 |
|---|---|
| 虚线框 | B 向外扩 2 pt 的矩形，**直角**，线宽 1 pt；沿线一段深一段浅首尾相接：深 = 黑 72%，浅 = 白 95%，各长 4 pt，从左上角起顺时针排，不动 |
| 角标 | **没有**（v4 有左上 / 右下两个强调色直角，去掉了：比虚线抢眼，而且蓝色留给「选中」。`textbox.png` 最后一格是带角标的对照） |
| 光标 | 宽 2 pt、高 1.08 × 字号（不超过行高，在行内上下居中），颜色 C；外包 1 pt 的反色描边（反色是黑时 60%，是白时 75%）。有选中的字时没有光标。按系统的闪烁周期闪，位置一变就从「亮」重新开始 |
| 编辑中的字 | 颜色 C；带两层反色的晕：σ = 0.5 pt、85%，和 σ = 1.25 pt、55% |
| 组字中的一段 | 字同上；下面一条 2 pt 粗的 C 色下划线，紧贴这一行的底，同样带晕 |
| 选中的字（拖选、shift + 方向键、全选） | 选中的那一段字**下面**铺 `#419CFF` 35%（数据里的 `text_box.selection_alpha`），字照常画在上面。两个平台相同，**不用系统的选中色**——系统色跟着用户的强调色和外观变，而且在透明底上各家画法不同 |
| 提交后的字 | 颜色 C，**没有框、没有晕**——就是最终图片里的样子 |

虚线的尺寸：

| | pt | 1x | 1.5x | 2x |
|---|---:|---:|---:|---:|
| 线宽 | 1 | 1 | 2 | 2 |
| 深色段 / 浅色段的长度 | 各 4 | 各 4 | 各 6 | 各 8 |
| 框离输入框矩形 | 2 | 2 | 3 | 4 |

白底上读到的是深色段、浅色段隐去；深底上相反；节奏相同，所以**任何底色上读出来都是虚线**（用户看 v4 时
白底上只剩一圈灰色实线，就是因为那一版是「黑实线 + 白虚线」两圈）。压在明暗交界上时，同一圈线左半读深、右半读浅。
实现：先整圈画深色实线，再用浅色画 `4 实 4 空`、起点错开 4 pt 的虚线，两者同一条路径。像素要对齐，不要抗锯齿。

**谁画什么（mac）。** 输入框仍是一个真的文本视图（输入法、选区、撤销都是它自己的），从一开始就建在 TextKit 1 上，
没有底色：字、字晕、组字下划线、选区高亮是它画的（字晕和下划线在它的布局管理器里，和字一起画）；虚线框和光标是
覆盖层画的——系统自己的光标设成透明，不然会有两个。「反色」按相对亮度算（各通道先做 sRGB 的线性化再加权），
不是直接拿 0–255 的值加权：橙色直接加权是 0.58、会被当成浅色，线性化后是 0.355。

**组字期间点色块 / 字号档，键盘不离开输入框（mac，#1117；真机 #1112 带回的现状 A6）。** AppKit 在把按下交给被点的视图之前，
先让它成为 first responder；输入框于是先交出键盘、片刻后再被交还——而文本视图一交出键盘，输入法的组字就结束了：
候选框消失，之后按空格上屏的是拼音字母。现在覆盖层在这一下（正在输入、且点的是色块或字号档）回答「不接键盘」，
输入框从头到尾没有失去键盘，组字和候选框都留着（`ShotTextInput.overlayTakesKeyboard`）。**这是按机制改的，
候选框是否真的留着只能真机看。**

**与「被选中的文字标注」怎么区分**：输入中 = 黑白虚线 + 光标（中性色，表示「正在打字」）；选中 = 蓝白虚线 + 蓝色光晕、
没有光标（§9.8.11A）。一个是黑白的，一个是蓝的。

⚠️ **字晕只在编辑时有。** 白底上的白字，编辑时靠晕看得见，提交后看不见——那是用户选的颜色。这等于
「编辑时看到的」和「最后得到的」在最坏情形下不一样；这是定下来的取舍——不这样的话，白底白字在编辑中就只剩
虚线框和光标。

输入框仍然接鼠标：它盖住的地方点不到下面，所以「不许盖住工具栏」的几何规则照旧。

**Windows。** 现在输入框是一个 EDIT 子窗口，画不出透明底。要么换成「自己画字 + 一个不可见的输入接收者」
（组字区、候选框位置都要自己报给输入法），要么用带逐像素 alpha 的分层子窗口。这是 Windows 侧最大的一块，
而且碰输入法——建议单独立项先做可行性，不要和工具栏的重画捆在一起交。

#### 9.8.11A 标注的选中与编辑（效果图 `annotations.png`）

行为照 §9.4 不变（选择工具或 cmd/ctrl + 点击选中；拖动 = 移动；手柄 = 改形状）。这里只定**画成什么样**。
改前：手柄是 8 pt 的强调色实心方块，选区的手柄和标注的手柄长得一样；只能移动的标注画一圈 1 px 的强调色实线；
能改形状的标注**没有外框**；指针只有十字和箭头两种（`ShotSession.draw`、`ShotSession.cursor(at:)`，
Windows `shot.rs` 的 `compose_overlay`）。

##### 9.8.11A.1 三类标注

| 标注 | 外框 | 手柄 |
|---|---|---|
| 矩形、椭圆、马赛克 | 有 | 8 个：外框的四角和四边中点 |
| 直线、箭头 | **无** | 2 个：两个端点上 |
| 文字、编号、画笔、荧光笔 | 有 | **无** |

「只能移动、不能拉伸」靠的就是**有外框而没有手柄**，加上指针在它上面只会变成「移动」。不另加记号。

##### 9.8.11A.2 外框（定值）

- 位置：标注的**墨迹外框**（含线宽；文字是排版外框）向四周扩 4 pt 的矩形，圆角 2 pt。
  扩出去是为了不压在标注自己的线上——蓝色的矩形被选中时，外框和它之间隔着 4 pt 的画面。
- 线：1 pt 宽。先画一圈白 85% 的实线，再在同一条路径上画 `#419CFF` 的虚线，**4 pt 实、3 pt 空**。
  读出来是蓝白相间；白底上白段隐去剩蓝虚线，蓝底上蓝段隐去剩白虚线。
- 光晕：与工具栏选中态同一层——`#419CFF`，σ = 2 pt，沿线两侧，峰值按 §9.8.4.2 的表。
- 外框画在**所有标注之上**、工具栏之下。

| | pt | 1x | 1.5x | 2x |
|---|---:|---:|---:|---:|
| 外框离墨迹 | 4 | 4 | 6 | 8 |
| 线宽 | 1 | 1 | 2 | 2 |
| 蓝段 / 白段 | 4 / 3 | 4 / 3 | 6 / 5 | 8 / 6 |
| 圆角 | 2 | 2 | 3 | 4 |

##### 9.8.11A.3 手柄（定值）

| 状态 | 画法 |
|---|---|
| 常态 | 7 × 7 pt 的方块，圆角 1.5；底 `#FFFFFF`；描边 1 pt `#419CFF`；外面一圈 0.6 pt 的黑 60% 细影（白底上托出白方块） |
| 悬停 | 放大到 9 × 9 pt；加 §9.8.4.2 的光晕 |
| 按下 / 拖动中 | 9 × 9 pt；底 `#419CFF`，描边 1 pt `#FFFFFF`；光晕 |

| | pt | 1x | 1.5x | 2x |
|---|---:|---:|---:|---:|
| 常态边长 | 7 | 7 | 11 | 14 |
| 悬停 / 按下边长 | 9 | 9 | 14 | 18 |
| 命中范围（中心四周） | ±6 | ±6 | ±9 | ±12 |

八个手柄的中心在**外框**的四角和四边中点（不是标注本身的角）；**命中也按画出来的位置算**（手柄中心四周 ±6 pt），
抓住以后被它带动的那个角 / 边按指针的位移量走，与指针保持按下那一刻的距离——形状不会在按下时跳到指针底下。
两个宿主的编辑器里是同一段逻辑（`ShotEditor.gripUnder` / `editor.rs` 的 `grip_under`，`reshapeItem` 带 `offset`）。
直线、箭头的两个手柄中心就在端点上。过渡：常态 ↔ 悬停 80 ms；按下 0。

##### 9.8.11A.4 指针

| 指针在哪 | 样式 | mac | Windows |
|---|---|---|---|
| 被选中标注的内部（或它的线上） | 移动 | `openHand`，按下后 `closedHand` | `IDC_SIZEALL` |
| 上 / 下边中点的手柄 | 上下 | `resizeUpDown` | `IDC_SIZENS` |

| 右上 / 左下角的手柄 | 斜向 ↗↙ | 同上 | `IDC_SIZENESW` |

| 别处 | 当前工具的指针（现有：十字） | | |

选区自己的手柄用同一套方向光标。mac 13–14 上斜向用十字是退路，没有试过别的办法。

##### 9.8.11A.5 移动中

- 标注跟着指针走，**外框跟着走，手柄收起**（松手后再出现）。
- **原位置不留影子。** 想回去按 Esc 以外的撤销（cmd/ctrl+Z）；留影会和别的标注混在一起。
- 伸出选区的部分：§9.4 说标注按定格画面坐标保存、超出选区的部分导出时裁掉。画法是
  **照常画在毛玻璃上面，但不透明度降到 40%**；选区内的部分 100%。这样拖的时候不会觉得东西被吃掉了，
  又看得出这一半不会进图。松手后维持这个画法（不是只在拖的时候）。
  马赛克是直接改在画面像素里的，伸出选区的那部分**不画**（选区外是另一张图，没有可打码的清晰像素）。
  外框整圈照常画。

##### 9.8.11A.6 改形状中

- 被拖的那个手柄是「按下」态，其余七个是常态；外框实时跟着新的形状。
- 指针右下方 12 pt 处一块小牌（与尺寸标签同一种玻璃，§9.8.2），内容：矩形 / 椭圆 / 马赛克报
  `宽 × 高`（像素）；直线 / 箭头报与水平线的夹角（整数度）。小牌只有这两种内容。
- **不在本轮**：按住 shift 约束时在牌上加词（` · 1:1`、` · 吸附`）。效果图 `annotations.png` ④ 里画了，没有做；
  shift 约束本身（§9.2）照旧，只是牌上不提。没有辅助线。

##### 9.8.11A.7 与选区的框区分

| | 选区 | 被选中的标注 |
|---|---|---|
| 线 | 1 pt `#419CFF` **实线**，没有光晕 | 1 pt 蓝白**虚线**，有光晕 |
| 手柄 | 直径 7 pt 的**圆**，白底蓝边 | 7 pt 的**方块**，白底蓝边 |
| 何时有手柄 | 选择工具、且没有选中任何标注时（现有规则） | 选中时 |

两套手柄**不会同时出现**（现有规则，保留）；同时在屏上的只有选区的实线和标注的虚线。

##### 9.8.11A.8 叠在一起

选中的那个标注自己的层次不变（不提到最上面——提上去就改了导出的结果）；它的外框和手柄画在所有标注之上。
别的标注不变淡。

#### 9.8.12 多显示器

每块屏各自：自己的缩放、自己的 F / D / O（按自己的缩放选 k 和 r）、自己的覆盖窗口。工具栏、选区只在一块屏上。
三块 3600 × 2338 的屏 = 多占 3 × (33.7 + 2.1) ≈ 107 MB，定格期间；一次性耗时也是三份（可各用一个线程）。

（调产品自己的绘制函数，数 alpha ≥ 128 的像素）；它现在量的是改前的实现，接线后换成新的入口重跑。

| 矩形 | 14.8 × 13.1 | 重做 | 14.4 × 14.0 |
| 椭圆 | 16.5 × 14.4 | 长截图 | 14.8 × 15.6 |
| 直线 | 13.1 × 13.1 | 取消 | 12.3 × 12.3 |
| 箭头 | 13.1 × 13.1 | 完成 | 14.0 × 10.6 |
| 画笔 | 15.3 × 15.3 | T 第 1 档 | 6.9 × 7.3 |
| 荧光笔 | 16.3 × 16.3 | T 第 2 档 | 8.5 × 9.4 |
| 文字 | 13.1 × 13.1 | T 第 3 档 | 10.6 × 11.5 |
| 编号 | 16.5 × 16.5 | T 第 4 档 | 12.7 × 13.5 |
| 马赛克 | 14.2 × 14.2 | T 第 5 档 | 14.8 × 15.6 |

外加：16 个按钮图标的墨迹长边「最大 ÷ 最小」≤ 1.4（设计值 16.5 ÷ 12.3 = 1.34；改前 1.90）；
「选择」是实心的：它的外框里墨迹占比 ≥ 45%（别的图标是线，占比低得多）；
每个图标的墨迹中心离格子中心 ≤ 0.5 pt（改前最大 2.0）；五个 T 的高度严格递增且相邻两档至少差 1.5 pt；
没有任何图标取自系统字体（改前 5 个）；**mac 与 Windows 同一图标的外框相差 ≤ 1 px**。

**B. 网格**（2x 像素；这些是算术，应当分毫不差）

- 第一行 16 个格子的上沿 y 全相等，下沿全相等，格子 56 × 56；组内相邻格子左沿相差 64，跨组相差 80。
- 属性栏的格子：上沿全相等；相邻色块格子左沿相差 64；最后一个色块到第一个档位相差 80；档位之间 64。
- 第一行第一个格子与属性栏第一个格子的左沿相等（都是板左沿 + 12）。
- 板宽 1104（552 pt × 2）；一行时高 80，两行时高 160；属性栏第一个格子的上沿 = 第一行格子的下沿 + 24。
- 色块圆的直径 32，圆心 = 格子中心（±0.5 px）。

**C. 选中态**

- 环：从格子的边往里量，强调色的宽度 3 px（±1）；环中线上取一点 = `#419CFF`（每通道 ±8）。
- 光晕：格子边外 2 px 处的颜色比同一位置未选中时更蓝，外 10 px 处与未选中时相同（每通道 ±3）。
- 工具、色块、粗细、字号、马赛克五类各选一个，量出的环宽、环色相同。
- 悬停（未选中的格子）：格子内空白处比常态亮（每通道 +20 到 +40），且 R、G、B 三个通道的增量彼此相差 ≤ 6——即**没有偏蓝**；格子边外 2 px 处与常态相同（没有光晕）。
- 按下：鼠标按住不放时截图，格子有环、有光晕，格子内空白处偏蓝（B 的增量比 R 的大 ≥ 15）。松开 200 ms 后：一次性动作的格子回到悬停的读数；工具 / 色块 / 档位留下环与光晕、蓝底消失。
- 不可用的格子悬停、按下前后截图逐像素相同。
- 「完成」「取消」常态下格子内空白处与相邻的普通格子相同。
- 选中白、黑、蓝三个色块：环与色块之间有 ≥ 8 px 既不是环色也不是色块色的像素。

**D. 玻璃与选区外**（准备一张测试画面：左半纯白、右半纯黑，中间一条竖直的硬边；以及一大片纯白、一大片纯黑）

- 选区内任取 100 个点：与定格原图逐像素相同（差 = 0）。**这一条不许有容差。**
- 选区外、离硬边和选区都远的纯白处 = 240（255 × 0.94，±2）；纯黑处 = 0（+2）。
- 选区外横穿那条硬边取一行：亮度从 10% 到 90% 的过渡宽度应为 2.56 σ = 7.7 pt = 15 px（接受 12–20 px）。
  小于 8 px 说明没模糊够，大于 30 px 说明用成了别的档。
- 板落在纯白上：板内空白处 ≈ `#3E4041`；落在纯黑上 ≈ `#131415`（每通道 ±6）。
- 拖动选区时录屏逐帧看：每一帧里清晰区的四条边都与选区边线重合（差 ≤ 1 px）；没有哪一帧清晰区落后于边线。
- 「减少透明度」打开后重进定格：选区外纯白处 = 145（255 × 0.57，±2），横穿硬边的过渡宽度 ≤ 2 px；板内空白处 = `#3D3F40`（±2）。

**E. 文字与输入框**

- 提示、状态行、尺寸标签的字号 = 系统菜单字号（量大写字母高度，与系统菜单里同一个字母比，差 ≤ 1 px）。
- 输入框的框：沿上边取一行像素，是深、浅两种颜色交替，每段 8 px（2x；±1），深段约为黑 72%、浅段约为白 95% 叠在底图上；纯白底上数得到深色段、纯黑底上数得到浅色段，段数相同（±1）。没有蓝色的像素（没有角标）。
- 白画面上用白色打字：编辑中，框线、光标、字都看得见（各取一点，与背景的亮度差 ≥ 40 / 255）；
  提交后那一处与提交前的画面只差字本身（字是白的，所以差 ≈ 0）。
- 深画面上用黑色打字：同上。
- 输入框范围内、没有字的地方：与定格原图相同（差 = 0）。

**G. 标注的选中**（2x）

- 选中一个红色矩形：它外面有一圈虚线，虚线到矩形墨迹外沿的距离 8 px（±1）；沿虚线取一行，蓝 `#419CFF` 与白交替，蓝段 8 px、白段 6 px（±1）。
- 八个手柄：白底、蓝边、方形，边长 14 px（±1），中心在虚线的四角和四边中点（±1 px）。
- 选中一个蓝色（`#2F6FED`）矩形：虚线与矩形之间有 ≥ 6 px 既不是虚线也不是矩形的像素。
- 选中直线 / 箭头：没有虚线框；两个端点各一个手柄。选中文字 / 编号 / 画笔 / 荧光笔：有虚线框、**手柄数为 0**。
- 指针放到一个手柄上：手柄边长变成 18 px（±1）；按住：手柄内部 = `#419CFF`。
- 选中标注时选区没有手柄；取消选中、换到选择工具后选区有 8 个**圆**手柄（直径 14 px）。
- 把一个标注拖到一半在选区外：选区外那一半的墨迹颜色 = 标注色 × 0.4 + 玻璃底 × 0.6（每通道 ±8）；导出的图里没有那一半。
- 拖动标注时逐帧看：外框与标注的相对位置每一帧都相同（没有外框落后一拍的帧）。

**F. 两个平台对照**

同一张测试画面、同一个选区、同一个工具状态，mac（2x）与 Windows（200% 缩放）各截一张：
板、格子、环的几何逐项相等（B、C 的读数相同）；板内空白处颜色每通道相差 ≤ 6。

## 10. 给 agent 的 MCP 工具

用户定：截图开放给 agent——能帮用户截图，能用全部工具、全部功能，并能查元信息。
配置项 `screenshot-agent-access`：`allow`（默认）/ `deny`。`deny` 时下面的工具都回
`NotPermitted` 并说明是哪个配置项。每次 agent 截图在宿主日志里记一行（谁、截了什么）。

| 工具 | 作用 |
|---|---|
| `screenshot_windows` | 列出可截的窗口：`window_id`、应用、标题、边界（物理像素）、所在显示器；以及显示器列表 |
| `screenshot_capture` | 不出界面直接截。`target`：`display`（给序号）/ `window`（给 `window_id`）/ `region`（给矩形）/ `terminal`（给 Polter 终端 id，截它所在的窗口）。可带 `annotations`（同 §11 的模式，含马赛克）一次画好。返回图片路径、`.json` 路径、尺寸 |
| `screenshot_annotate` | 给一张已有的本机截图加标注，写成**新文件**（原文件不动）。参数 `path` + `annotations` |
| `screenshot_long` | 长截图：`window_id` 或 `region` + `pages`（滚几屏）。由宿主注入滚轮。⚠️ mac 上注入滚轮要「辅助功能」授权，没授权时回明确的错误，不弹授权框 |
| `screenshot_interactive` | 替用户按一次截图键：弹出定格界面，由用户自己框选和标注。立即返回，不等结果 |
| `screenshot_info` | 查元信息：给 `path`，或 `latest: true`，返回 §11 的 `.json` 全文 |
| `screenshot_list` | 截图目录里最近 n 张：路径、时间、尺寸、来源、标注数 |

- 路径只认截图目录里、命名符合 §5 模式的文件；别的路径一律拒绝（不许拿它读任意文件）。
- agent 截的图**不进剪贴板、不自动粘贴**——剪贴板是用户的；agent 拿到路径自己读。
- `screenshot_interactive` 走的是用户自己的那条路（同一个触发、同一个完成），所以结果进
  剪贴板、存文件，**完成后同样不往任何窗格里送东西**（§3.4；以前若 agent 所在的窗格正好
  聚焦，路径会被送进去）。agent 要看这张图，等用户粘贴给它，或事后 `screenshot_info`
  取 `latest`。
- mac 没授「屏幕录制」时返回明确的错误文本，不触发系统授权弹窗（那个弹窗只在用户自己
  触发截图时出现）。
- 合成与马赛克走与界面同一份代码，不另写一套。

### 10.1 核心 ↔ 宿主契约

七个工具在 `src/cli/mcp.zig` 定义，请求经 `rpc.zig` 到 app 线程。**核心做的**：权限
（`screenshot-agent-access`）、终端 id → surface、路径校验、标注校验与规范化、
`screenshot_info` / `screenshot_list`（纯读文件）、`screenshot_interactive`（直接发既有的
`screenshot` 动作，宿主不用新写）。**宿主做的**：列窗口、截、给已有图加标注、长截图、报
截图目录。

#### 动作与 C ABI

一个新的 apprt 动作，追加在 `Action.Key` 末尾：`poltergeist_screenshot`
（`GHOSTTY_ACTION_POLTERGEIST_SCREENSHOT`，`ffi.rs` 的序号 = 77）。负载两个指针，形状与
`poltergeist_layout` 相同：

```c
typedef enum {
  GHOSTTY_ACTION_POLTERGEIST_SCREENSHOT_UNSUPPORTED,  // 0：宿主什么都没写
  GHOSTTY_ACTION_POLTERGEIST_SCREENSHOT_DONE,         // buf 里是结果 JSON
  GHOSTTY_ACTION_POLTERGEIST_SCREENSHOT_REFUSED,      // buf 里是 {"code","message"}
  GHOSTTY_ACTION_POLTERGEIST_SCREENSHOT_PENDING,      // 稍后用 token 回
} ghostty_action_poltergeist_screenshot_result_e;

typedef struct {
  ghostty_action_poltergeist_screenshot_result_e result;
  uint64_t token;   // 核心填；PENDING 时宿主记下，回的时候带上
  char* buf;        // 核心的缓冲区
  size_t cap;       // 64 KiB
  size_t len;       // 宿主写了多少
} ghostty_action_poltergeist_screenshot_out_s;

typedef struct {
  const char* spec;                                    // 请求 JSON，调用期间有效
  ghostty_action_poltergeist_screenshot_out_s* out;
} ghostty_action_poltergeist_screenshot_s;

// 仅在答了 PENDING 之后调用，恰好一次，**必须在 app（UI）线程上**。
// result 只能是 DONE 或 REFUSED。json 由核心在返回前拷走。
GHOSTTY_API void ghostty_app_poltergeist_screenshot_complete(
    ghostty_app_t, uint64_t token,
    ghostty_action_poltergeist_screenshot_result_e result,
    const char* json, uintptr_t len);
```

- 动作的 target：`capture` 的 `terminal` 目标是 `.surface`（那个终端的 surface，宿主截它
  所在的窗口）；其余都是 `.app`。
- **同步还是异步由宿主定**：能当场答的（`directory`、`windows`，以及 Windows 上的
  `capture`/`annotate`）答 `DONE`；做不到的（mac 14+ 的截屏接口是异步的、长截图要滚好几屏）
  答 `PENDING` 后尽快返回，**不许在 UI 线程上等**。工作线程做完要回到 UI 线程再调
  `…_complete`。
- 核心对 `PENDING` 设时限：`capture`/`annotate` 15 秒，`long` 为 10 秒 + 每屏 3 秒。超时回
  `Timeout`；之后迟到的 `…_complete` 按未知 token 丢弃（记一行日志）。
- 结果放不进 64 KiB（窗口极多）时宿主截断列表并在 JSON 里加 `"truncated": true`，不许写
  半截 JSON。异步回的 JSON 不受这个上限。

#### 坐标

一律**某个显示器内的物理像素**，原点在该显示器左上角，配一个 `display` 序号。不用全局
坐标：两个显示器缩放不同时 mac 没有「全局物理像素」这种空间。`display` 序号就是
`windows` 答复里 `displays` 数组的下标，主显示器是 0。

#### 请求（核心 → 宿主，`spec`）

| `op` | 其余字段 | `DONE` 的 JSON |
|---|---|---|
| `directory` | — | `{"directory": "<绝对路径>"}`。宿主实际写截图的目录（配置 + 默认值 + `~` 展开之后）。核心不自己解析目录，只认这个答复 |
| `windows` | — | `{"displays": [{"index": 0, "size": [w, h], "scale": 2.0, "primary": true}], "windows": [{"window_id": 123, "app": "…", "title": "…", "pid": 4242, "display": 0, "rect": [x, y, w, h]}]}`。窗口从前到后；只列普通应用窗口（与界面里悬停能选中的同一批）；`app`/`title`/`pid` 取不到就省略；跨显示器的窗口记在中心点所在的那个上，`rect` 可以超出该显示器 |
| `capture` | `target`、`annotations`、`meta` | `{"path": "…png", "json": "…json", "size": [w, h]}` |
| `annotate` | `path`（核心已校验的绝对路径）、`annotations`、`meta` | 同上，是**新文件**。原图旁路文件里的 `redacted` 原样抄过去 |
| `long` | `target`（只能是 `window` 或 `region`）、`pages`（1–20）、`meta` | `{"path", "json", "size", "tiles": [{"image": "…-1.png", "y": 0, "height": 1800}], "pages": 实际滚了几屏, "stopped": "pages" \| "bottom" \| "limit" \| "moving"}`。`tiles[].image` 是**文件名**（不带目录，与 `.json` 里的 `tiles` 相同，文件在 `path` 旁边）；写成路径的话核心把整个应答当 `HostFault` 拒掉（Windows 宿主曾这样，#1099）。`moving`：区域从没稳定过，没滚动，图是第一帧（§9.7）|

`target`：`{"kind": "display", "index": 0}` ｜ `{"kind": "window", "window_id": 123}` ｜
`{"kind": "region", "display": 0, "rect": [x, y, w, h]}` ｜ `{"kind": "terminal"}`。

`meta`（核心填，宿主原样写进 `.json` 并用于日志）：
`{"by": "agent", "agent_terminal": "0x…", "terminal": {"id": "0x…", "cwd": "/…"}}`。
`terminal` 是调用者自己的终端；`cwd` 取不到就省略。`git` 仍由宿主在该 `cwd` 下取（§11）。

`annotations`：核心**已校验并规范化**，宿主拿到的每一项都带齐字段、不用再判缺省；坐标是
**结果图的像素**（与 `.json` 里的一致）：

| `type` | 字段 |
|---|---|
| `rect`、`ellipse` | `rect` `[x,y,w,h]`、`color`、`width` |
| `line`、`arrow` | `from` `[x,y]`、`to` `[x,y]`、`color`、`width` |
| `pen`、`highlighter` | `points` `[[x,y],…]`（至少 2 个）、`color`、`width` |
| `text` | `at` `[x,y]`、`text`、`color`、`font_size` |
| `number` | `n`、`at` `[x,y]`、`text`（可空）、`color`、`font_size` |
| `mosaic` | `rect`、`block` |

- `color` 是 `#RRGGBB`（大写），agent 可以给任意颜色，缺省 `#E62828`。
- `width`、`font_size`、`block` 是**逻辑点**，必须是 §9.1 / §9.5 的档值之一（`width` 1/2/4/6/10，
  `font_size` 14/18/24/32/44，`block` 8/12/16/24/32），缺省各取第 2 档。给了别的值核心回
  `BadAnnotations`，不就近取整。
- `number` 缺 `n` 时核心按出现顺序从 1 编。
- 上限：200 项；每段 `text` 2000 字节；`points` 每项 5000 个点。
- ⚠️ `pen`/`highlighter` 作为**输入**带 `points`；写进 `.json` 的仍只有 `bbox`（§11）。所以
  `screenshot_info` 读回来的画笔不能原样再喂给 `screenshot_annotate`——工具说明里写明。

`annotate` 的新文件：`.json` 的 `source`/`display`/`appearance`/`redacted` 抄原图旁路文件的
——这些说的是**原图是在什么环境下截的**，在图上再画几笔不改变它；原图没有旁路文件、或
它没有其中某个键，就省略，不拿「现在」的值顶替。`annotations` = 原有的 + 新加的，`by` = `agent`，`previous` = 原图文件名。

#### 宿主的拒绝码（`REFUSED` 的 `code`）

| `code` | 何时 |
|---|---|
| `ScreenRecordingRequired` | mac 没授屏幕录制。**不许因此弹系统授权框** |
| `AccessibilityRequired` | mac 的 `long` 没授辅助功能。同样不弹 |
| `NoSuchWindow` / `NoSuchDisplay` | `window_id` / `index` 不存在（窗口可能刚关） |
| `BadRegion` | 矩形与该显示器没有交集，或宽高为 0 |
| `Busy` | 用户的定格界面正开着，或另一次 agent 截图还没完 |
| `BadImage` | `annotate` 的文件读不出来 |
| `CaptureFailed` / `WriteFailed` | 截不到 / 写不进目录，`message` 里带系统给的原因 |

`message` 是给 agent 读的一句英文，说清楚是什么、能做什么。未知的 `code` 核心原样透传。

#### 核心自己答的错误

`NotPermitted`（`screenshot-agent-access = deny`，文案点名这个配置项）、`Unsupported`
（宿主答 0，例如 GTK）、`UnknownTerminal`、`BadPath`（不在截图目录里，或名字不符合模式）、
`NotFound`、`BadAnnotations`（文案说是第几项、哪个字段）、`Timeout`、`HostFault`（宿主回的
路径不在它自己报的目录里，或 JSON 解不开——这是宿主的 bug，不是 agent 的）。

#### 路径与命名

- 模式在第二轮扩成 `YYYYMMDD-HHMMSS-mmm` + 可选的 `-<1 到 3 位数字>` + `.png` / `.json`
  （后缀是长截图的分片）。**两个宿主的 7 天清理也要认这个扩展后的模式**，否则分片永远
  不会被清。
- 校验在核心（`src/poltergeist/` 下的纯函数，有测试）：取宿主报的目录，路径必须是它的
  **直接子项**（不许子目录、不许 `..`、不许符号链接指到外面——按解析后的真实路径比），
  文件名符合上面的模式。`screenshot_info`、`screenshot_annotate` 的 `path` 和宿主回来的
  每一个路径都过这道。
- agent 截的图不进剪贴板、不粘贴；宿主对 `by = agent` 的请求不许碰剪贴板，也不许更新
  「上一张粘贴的图」那份缓存。
- 每次 `capture` / `annotate` / `long` 宿主记一行日志：`agent_terminal`、`op`、目标、结果
  路径或拒绝码。

#### 屏蔽的终端（shielded）

被用户屏蔽的终端禁止任何 agent 读，截图不许成为绕过它的路：

1. `capture` 的 `target = terminal` 且该终端 shielded → **核心**拒绝，`NotPermitted`，动作
   不发给宿主。
2. `by = agent` 的任何截图（`capture` 的 display / window / region / terminal，以及 `long`）：
   **宿主在合成前把画面里 shielded 窗格的矩形涂成纯黑**，原像素不出去——与马赛克同一条
   「原图不落地」，而且先于马赛克和其它标注落到图上。`.json` 里记
   `"redacted": [[x, y, w, h], …]`（结果图像素；没有就省略这个键）。用户自己触发的截图不涂。
3. 宿主怎么知道哪些窗格 shielded：既有的 `poltergeist_mark` 动作已经把每个 surface 的
   `shielded` 送到宿主（`ghostty_action_poltergeist_mark_s.shielded`，标签页的锁就是它），
   宿主按 surface 记着最后一次的值，不用新接口。**按 surface（窗格），不按标签页**：一个标签页里
   两个窗格只屏蔽一个时，只涂那一个——Windows 宿主曾把这个值只记在标签页上，于是同页没屏蔽的
   窗格（包括调用者自己）也被涂黑（#1099）。
4. 矩形怎么算：对每个 shielded 且**所在窗口此刻在屏幕上**（没最小化、没隐藏、在当前桌面）
   的窗格，取它的终端视图在所截显示器内的物理像素矩形，与所截区域求交，平移到结果图坐标。
   **不判遮挡**：窗格被别的窗口盖住时也照涂——宁可多涂，判遮挡判错一次就是泄露。
   长截图里每一帧各算各的，拼接前就涂。
5. 纯函数（两个宿主各自实现、各有测试）：输入「窗格矩形列表 + 所截区域矩形」，输出结果图
   坐标下要涂的矩形列表；空交集的不出现，超出的裁到图内。

#### MCP 工具的参数（agent 看到的）

| 工具 | 参数 |
|---|---|
| `screenshot_windows` | 无 |
| `screenshot_capture` | `target`: `"display"` \| `"window"` \| `"region"` \| `"terminal"`；`display`: 整数（`display`/`region` 用，缺省 0）；`window_id`: 整数；`rect`: `[x,y,w,h]`；`terminal`: 终端 id（`terminal` 目标用，缺省是自己）；`annotations`: 数组，可省。每种目标只收自己的参数，多给别的目标的参数回 `BadParams` |
| `screenshot_annotate` | `path`、`annotations` |
| `screenshot_long` | `window_id`，或 `display` + `rect`；`pages`: 1–20 |
| `screenshot_interactive` | 无。返回 `{"started": true}`，不等用户 |
| `screenshot_info` | `path`，或 `latest: true` |
| `screenshot_list` | `limit`: 1–50，缺省 10。每条：`path`、`time`（文件名里的时间）、`size`、`source`、`annotations`（条数）、`by`；没有旁路文件的（粘贴存下的图）只有 `path`、`time`、`size`（读 PNG 头） |

## 11. 旁路文件 v2

`version` 升到 2。新增（取不到的键省略，不写空值）：

```json
{
  "version": 2,
  "by": "user",
  "display": {"index": 0, "size": [2560, 1440], "scale": 2.0},
  "appearance": "dark",
  "source": {"kind": "window", "app": "Google Chrome", "title": "…", "pid": 4242,
             "window_rect": [120, 80, 1280, 800], "selection_rect": [120, 80, 1280, 800]},
  "terminal": {"id": "0x…", "cwd": "/…/proj", "git": {"head": "3d65ad0", "dirty": true}},
  "previous": "20261006-152233-101.png",
  "tiles": [{"image": "…-1.png", "y": 0, "height": 1800}]
}
```

- `by`：`user` 或 `agent`（agent 时另有 `agent_terminal`）。
- `source.window_rect`：**窗口本身的矩形，不裁**——窗口有一部分在屏幕外时，它照样是整个
  窗口，可以超出 `display.size`、可以有负的起点。`source.selection_rect`：**实际截到的**
  那一块，总在显示器之内。两者坐标同 §10.1「坐标」。界面截图和 agent 截图记的是同一对
  数：同一个窗口，不论哪条路截，`window_rect` 相同。
- `appearance`：`light` 或 `dark`，**写文件那一刻系统要求应用用的明暗**，不是 Polter 自己窗口的
  配色。macOS：应用的生效外观（`NSApp.effectiveAppearance`）。Windows：注册表
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` 的 `AppsUseLightTheme`
  （0 = `dark`，其余或读不到 = `light`）；不看 `SystemUsesLightTheme`（那是任务栏）。Windows 宿主
  曾按自己窗口的底色算，而它的窗口恒为深色，所以恒为 `dark`（#1099）。
- `terminal`：用户从 Polter 前台触发时是聚焦的窗格；agent 触发时是它自己的终端。
  只是记录——截图不会被送进这个窗格（§3.4）。
  `git` 在该 `cwd` 下取，不是仓库就省略；取 git 不许拖慢截图（异步，超时 300 ms 就省略）。
- `previous`：截图目录里上一张 `source.app` + `source.title` 相同的截图。
- 标注条目新增：`color`（`#RRGGBB`）、`width` 或 `font_size`（逻辑点）、新类型 `ellipse`
  （`rect`）、`line`（`from`/`to`）、`highlighter`（`bbox`）、`mosaic`（`rect`、`block`）。
  单行文本（§4.2）里对应加「圆」「线」「荧光笔」「马赛克」四个词，马赛克只写位置。
- 仍不做：浏览器 URL、文字识别、无障碍元素、窗口属于哪个窗格启动的进程。

## 12. 设置窗口

### 12.1 「截图」分组

通用栏目新增分组「截图」，放在「快捷键」之前：

| 项 | 控件 | 配置键 |
|---|---|---|
| 粘贴图片时存成文件并粘贴路径 | 开关 | `clipboard-paste-image` |
| 截图保存位置 | 路径框 + 「选择…」+ 「在文件管理器中显示」 | `screenshot-directory` |

| 允许 agent 截图 | 开关 | `screenshot-agent-access` |
| 截图快捷键 | 只读，显示当前绑定；旁边一句「在配置文件的 keybind 里修改」和跳到快捷键页的链接 | — |

快捷键页本轮仍只读。

### 12.2 搜索到最子项

现状：搜索框只过滤侧栏和分组名，搜不到具体的设置项。改成：

- 搜索框有内容时，详情区换成**结果列表，只列最子项**：每条是一个可直接操作的设置行
  （与它在原分组里的同一个控件），上方一行小字面包屑「通用 › 截图」，点面包屑跳到原处。
  侧栏与中栏此时不参与筛选、置灰。清空搜索框回到原来停留的位置。
- 匹配范围：项的本地化名称、说明、配置键名、枚举选项的本地化名称、**所在分组的本地化
  名称**，以及每项可选的**别名词**（核心表里给，例如「截图」项带 `screenshot`、`截屏`、
  `capture`；`font-size` 带 `大小`、`字体大小`、`size`）。不分大小写，中英文都按子串；
  多个词是「且」，每个词各自在任一处命中即可——「字体 大小」找到「字号」（#1100：真机上
  这两个词都不在那一行的名称和键名里，读数是 0）。
- **面包屑和行下的链接用链接色，不用次要文字的灰。** mac 是系统链接色
  （`.buttonStyle(.link)`）；Windows 是 `theme::link()`：深色界面 `#419CFF`（即 mac 深色
  下的系统链接色），高对比度下取系统的 `COLOR_HOTLIGHT`。适用于：搜索结果的面包屑、
  「截图快捷键」行下的「快捷键」、行下的「更多…/收起」、角色页的链接式按钮。#1100 之前
  Windows 借用了焦点框的灰 `#8E8F90`，与上一行说明文字分不开。
- 除通用栏目的表单项外，也收：角色名、项目名、插件名及插件自己的表单项、快捷键页的
  每个动作（名称 + 当前绑定）。这几类点了跳到所在位置。
- 排序：名称命中 > 别名命中 > 键名命中 > 说明命中；同级按原有顺序。
- 没有结果时显示一句话，不留空白页。
- 匹配与排序是核心里的纯函数（`form.zig` 一侧），两个宿主只管画；字号、网格照 §2.3a/§2.3b
  （settings.md）。

### 12.3 核心给宿主的东西（契约）

表单 JSON（`ghostty_app_config_form`，形状见 `src/config/form.zig` 的 `writeJson`）第二轮
多了这些，**老字段一个没动**，不认识新字段的宿主照旧能画前五组：

- `sections` 末尾多一组 `"group": "screenshot"`，`keys` 依次是 `clipboard-paste-image`、
  `screenshot-directory`、`screenshot-mouse-trigger`、`screenshot-agent-access`。宿主把这一
  组画在「快捷键」之前。
- 每个 section 多一个 `shortcuts` 数组（只有截图组非空）：
  `{"action": "screenshot", "label", "summary", "aliases"}`——就是 §12.1 表里最后那一行。
  `label`/`summary` 是 msgid；当前绑定由宿主用 `ghostty_config_trigger(action)` 取了自己
  格式化，没绑定时显示本地化的「未设置」。
- 每个 item 多五个字段：
  - `aliases`：字符串数组，搜索用的别名词（**不是 msgid，不翻译**，原样参与匹配）。
  - `on` / `off`：`toggle` 控件写入的值；`null` 表示写 `true` / `false`。
    `screenshot-agent-access` 是 `"allow"` / `"deny"`。**宿主的开关控件必须读这两个字段**，
    对它写 `true` 会被核心以 `invalid_value` 拒绝。
  - `choice_template`：带一个 `%s` 的 msgid。`choice_labels` 里为 `null` 的那些取值由宿主
    拼：把取值里的修饰键按本平台写快捷键的方式写出来（mac `⌘⇧`，Windows `Ctrl+Shift`），
    代入翻译后的模板。只有 `screenshot-mouse-trigger` 用到，模板是 `%s + Click`（2026-10-07 之前是
    `%s + Double-Click`；msgid 跟着改，译文「%s + 单击」）。
- 新控件名 `directory`：路径框 + 「选择…」+ 「在文件管理器中显示」，写入方式同 `text`
  （空 = 还原默认）。
- `screenshot-mouse-trigger` 是 `choice`，但它的键不是枚举：`choices` 是核心表里列的七个
  （`none`、`super+shift`、`ctrl+shift`、`alt+shift`、`super+alt`、`ctrl+alt`、`super+ctrl`），
  第一个的名字是 msgid `Off`。**配置文件里写了不在表里的组合**（如三个修饰键）时，宿主把
  当前值作为额外一项显示在下拉里并选中它，不许显示成第一项。

搜索（`ghostty_app_config_form_search(app, entries, entries_len, query, query_len, buf, cap)`，
纯函数，实现是 `form.zig` 的 `search`）：

- `entries` 是 JSON 数组，**一项对应一个可被搜到的最子项，顺序 = 结果里「同级按原有顺序」
  的那个顺序**。每项 `{"name", "aliases", "key", "summary", "choices", "group"}`，全部可省。
  `group`（#1100 加）是所在分组的本地化名称，即面包屑的最后一段；只有通用表单项和快捷键行
  给，「全部选项」里的键、角色/项目/插件、快捷键页的动作都不给（给了的话搜「快捷键」会
  列出每一个动作）：

  | 条目 | `name` | `aliases` | `key` | `summary` | `choices` |
  |---|---|---|---|---|---|
  | 通用表单项 | 本地化名称 | 表里的 `aliases`；界面不是英文时再加英文原名 | 配置键 | 本地化说明 | 各取值的本地化名 |
  | 快捷键行（§12.1 末行） | 本地化 `label` | 表里的 `aliases` | `action` | 本地化 `summary` | — |
  | 角色 / 项目 / 插件 | 它的名字 | — | — | 有说明就放 | — |
  | 插件自己的表单项 | 该项名称 | — | 该项的键 | 该项说明 | 有就放 |
  | 快捷键页的动作 | 动作的本地化名称 | — | 动作名 | 当前绑定的文本 | — |

- 答复 `{"hits": [{"index": 在 entries 里的下标, "rank": "name" | "alias" | "key" | "summary"}]}`，
  已排好序。宿主按下标找回自己的条目；它是什么类型、点了跳哪，核心不知道也不管。
- 规则（有测试）：查询按空白（含全角空格）切成词，**每个词都要命中**；一个词的级别是它
  命中的最强字段（名称 > 别名 > 键名 > 说明 = 取值名 = 分组名），一个条目的级别是它各词里
  **最弱**的那个；同级按 `entries` 的顺序。空查询没有结果（宿主显示原页面）。
- 真机读数做成了核心的测试（`form.zig`「the readings the test machine took still hold」）：
  `截图` 6、`screenshot` 6、`capture` 3、`SCREENSHOT-DIR` 1、`总管` 4、`claude` 3、`粘贴` 4
  且名称命中的在前、`zzzz-nothing` 0。通用表单项取自核心自己的表；角色、插件、快捷键页的
  动作是按真机上的个数放的替身。
- 不分大小写的范围：ASCII、带重音的拉丁字母（À–Þ）、希腊字母、西里尔字母。**不是完整的
  Unicode 大小写折叠**：这些范围之外的字母（拉丁扩展、带重音的希腊大写等）只按原样匹配。
- 「取值名命中」规格 §12.2 没给级别，定为与说明同级（最弱）；「分组名命中」同。

## 13. 第一轮留下、这一轮清掉的
