# 角色界面（Windows）：给人看的核对清单

> 任务 571。对应代码 `windows/host/src/personas.rs` 和 `personas_ui.rs`，
> 自动化部分是那两个文件里的 40 条测试。
> **测试钉不住的三样在这里**：菜单真的弹不弹出来、长中文有没有被截断、
> 以及点下去之后 agent 手上的东西有没有真的变。
> 写给谁：坐在 Windows 那台机器前、能看见屏幕的人。

## 为什么要有这张纸

「看看对不对」会换回一句「还行」，那等于没验。下面每条都是
**点哪里 → 该看到什么 → 什么样算不对**，逐条答「对 / 不对 / 看不到」。
不对的那条把屏幕拍下来。

## 开始之前：确认你看的是新构建

⚠️ **不许用「有没有角色菜单」来判断这是不是新版**——那正是要验的东西，
拿它当前提就是绕圈。判据用这两条：

1. `polter-host.exe` 的时间戳是今天，且和你刚拷过去的那个文件同 SHA256。
2. 日志里有 `[persona] reading the core` 这一行。**这一行没有 gate 挡着**，
   所以它不出现就意味着启动根本没走到那儿，而不是「角色功能关着」。

# 第一部分：不需要 `personas.json` 就能做

## 1. 终端里右键，菜单底部有没有「角色」

**做**：在终端内容区域点右键。
**该看到**：菜单里有一行 **「角色」**，带子菜单箭头。
**算不对**：没有这一行；或者有字但展不开。

## 2. 子菜单的内容

**该看到**（从上到下）：
1. 灰色不可点：**「可能要 agent 重启之后才生效」**
2. 灰色不可点：**「还没有人报上来有哪些角色」**（没有 `personas.json` 时）
3. 分隔线
4. **「角色编辑器...」**

**算不对**（任何一条）：
- 有**英文**出现 —— 中文没命中，这是真缺陷，不是语言设置问题。
- 第 2 行写的是**「还没有定义任何角色」** —— 两句意思不同，串了就是缺陷。
- 第 1 行写的是**「下次启动 agent 时生效」** —— 那是冷 agent 那句，今天不该出现。
- 灰的那两行能点。

> 这两句的职责就是**不许让「还没生效」看起来像「已经生效」**。
> 它们出错的样子是「看起来很正常」。

## 3. 长句有没有把菜单撑坏

**该看到**：两条长中文各占一行，完整，没有 `…`。
**算不对**：被截断；或菜单宽得离谱。

## 4. 主菜单（标签栏左端那个按钮）里也有

**做**：点菜单按钮 →「Agents」那一组。
**该看到**：同样有「角色」子菜单，展开后与第 2 步**逐行相同**；
另外底部多一行 **「角色编辑器...」**。
**算不对**：两处内容不一样（它们是同一份代码建的）。

## 5. 编辑器窗口

**做**：点「角色编辑器...」。
**该看到**：一个独立窗口；从上到下是
「选一个角色」/「这个终端交出去的东西」/「这台机器上已经装了的」三区；
第三区**紧跟一句小字**「列在这里，是为了让你看见角色没有覆盖到哪里。Polter 不会动这些。」
**算不对**：
- 第三区**少了那句小字** —— 没有它用户会去找开关，而这一区是故意只读的。
- 任何一区显示成**空列表** —— 空列表会被读成「什么都没装」。
- 三处「还没有人报上来…」**用了同一句话** —— 它们说的是三件不同的事
  （有哪些角色 / 这个终端交出去了什么 / 这台机器装了什么）。

## 6. 护盾把开关关掉

**做**：右键 →「不让 agent 碰此终端」；再右键 → 展开「角色」。
**该看到**：子菜单顶部多一条灰色的
**「不让 agent 碰此终端，所以它的角色也不能改」**；角色各行变灰点不动；
而 **「角色编辑器...」仍然可以点**（看不是改）。
**做完**：把护盾关掉。

# 第三部分：端到端，这一条是这轮真正要演示的

## 先选对 agent，这一步会决定第 17 条的意思

这台机器上装了三家：`claude` (claude-code 2.1.272)、`codex` (0.154.0)、
`qwen` (qwen-code 0.23.3)。**用 `claude`。** 理由不是偏好：

- roles.md §6 里只有 claude-code 和 gemini 是**热**的——工具面在 agent 跑着的时候
  当场换。这台机器上没有 gemini。
- **codex 是冷的**，qwen 是温的。拿 codex 做这个演示，正确的结果就是「什么都没变，
  要重启才生效」——那是另一个演示，而且它和「坏了」长得一模一样。

⚠️ **热换装那条读数不是从这台机器上的二进制取的。** 实测用的是 claude-code
**2.1.274**，这台机器上装的是 **2.1.272**。两个 patch 版本大概率没事，但
roles.md §1.1 自己写着：宿主行为会随版本静默变化，而「一条说不支持的 issue」
和「今天真的不支持」长得一样。

**所以：第 17 条如果红了，先怀疑版本差异，不要先怀疑实现。** 分辨的办法是去看
服务器侧的日志有没有第二条 `tools/list`——那是 roles.md 附录 A.1 的判据，
它落在服务端，不落在 agent 的回答上。


| # | 做 | 该看到 | 算不对 |
| --- | --- | --- | --- |
| 15 | 在一个终端里起 `claude`，等它连上 Polter；问它有哪些 Polter 工具 | 它能列出来 | 连不上 |
| 16 | 右键给这个终端选一个**限制了工具的角色** | 菜单上打勾 | 没反应 |
| 17 | **再问一次同一个 agent**，并且**让它真去调用**一个被角色拿掉的工具 | 调不到 | 还调得到 |

⚠️ **第 17 条的问法是判据的一部分，不要改成「你还有那个工具吗」。**
每一轮都会注入一份新清单，但**上一轮那份还留在对话历史里**，所以
「你还有吗」会读到旧清单答「有」——于是「没生效」和「生效了但它还记得」
长得一模一样。**必须让它真去调。**

# 已经不用人看的

这些跑 `mine-tests.exe` 就有答案，别再用眼睛验一遍：
子菜单的项数与顺序、勾选落在哪一项、护盾时哪些行禁用哪些不禁用、
冷 / unknown 两句各自出现与不出现、「没有 agent 连着时父项不声称角色」、
「已改」的名字处处不同于没改的、三句「还没有人报上来」互不相同、
四个 slot 状态里只有 `broken` 和 `transparent` 出声、
**`transparent` 在编辑器里画成警告**、以及没有 `id` 的行被丢掉而不是被编一个。
