# 总控台在 Windows 宿主里放哪、用什么画（方案）

这是方案，不是已经做成的东西。总控台是什么见 [../poltergeist/control-room.md](../poltergeist/control-room.md)；
它的纯逻辑层已经有了（`windows/control-room`，见本文末尾「已经有的」）。下面每一条判断都写了依据是
读代码还是量过；**没有一条在 Windows 上跑过**。

## 1. 宿主现在的界面是怎么做的

读 `windows/host/src/` 得到的，按「总控台会借用哪一种」排：

| 界面 | 文件 | 怎么画 | 和总控台的关系 |
|---|---|---|---|
| 标签栏 | `strip.rs` | 宿主自绘：GDI 画进内存 DC 再贴到窗口；每次重画都从模型取快照（`tabs::strip_snapshot`），不留第二份标签列表；鼠标一律解析成 `TabId` | 总控台如果是一个标签页，就画在这里面 |
| 标签页的内容 | `tabs.rs` | 一个 `Tab` 就是一棵分屏树加一组 `Pane`，每个 pane 是一个 libghostty surface（OpenGL 子窗口） | **没有「不含终端的标签页」这个概念** |
| 设置窗口 | `settings_win.rs` + `roles_ui.rs`、`general_ui.rs`、`plugins_ui.rs`、`projects_ui.rs` | 一个**不属于任何终端窗口**的顶层窗口，启动时建一次，关掉是隐藏；内容是 GDI 自绘加标准控件；规则全在 `polter-settings-shell` 里，能在 mac 上测 | 结构上最像总控台 |
| 截图工具栏与覆盖层 | `shot.rs` | GDI；每显示器 DPI；圆角用 `CreateRoundRectRgn`；规则在 `polter-shots` | 圆角、亮暗的现成做法 |
| 四个小牌子 | `hud.rs` | 不抢焦点的小窗口，画核心给的东西，不自己判断 | 「只画核心说的」的现成例子 |
| 快速终端 | `quick.rs` | 滑入滑出用 `SetTimer` 16 ms 一帧加一条缓动曲线 | 动画的现成做法 |
| 命令面板 | `palette.rs` | 输入框用原生 `EDIT`，因为它自带输入法文档 | 「回一句」的输入框照此 |
| 插件自己的页 | `plugin_page.rs` | WebView2，运行库可能不在机器上，所以按路径延迟加载 | 不用它，见 §3 |
| 群聊页 | `tabs.rs` 的 `NewTabWith` | **是一个终端**：新开一个标签页，里面跑 `polter +chat`（一个 TUI） | 总控台第一期右栏的群聊、任务页签可以先借它 |

几条和选型直接有关的事实：

- **没有 Direct2D / DirectWrite。** `windows/host/Cargo.toml` 的图形特性只有 `Win32_Graphics_Gdi`、
  `Win32_Graphics_Dwm`、`Win32_Graphics_OpenGL`。所有文字是 GDI 的 ClearType。
- **进程是每显示器 DPI 感知的**（`DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2`），窗口各自处理
  `WM_DPICHANGED`。
- **亮暗**：标题栏用 `DWMWA_USE_IMMERSIVE_DARK_MODE`（`shell.rs`），截图工具读注册表的
  `AppsUseLightTheme`。没有一处统一的「现在是亮还是暗」。
- **通知**走通知区图标的气泡（`notify.rs`，写明了为什么不用 WinRT 的 toast）。任务栏按钮上的数字
  还没有任何代码。
- **宿主的测试只能在 Windows 上跑**，所以能出错而看不出来的规则都被搬到了旁边的 crate 里。

## 2. 推荐：先做成一个独立的顶层窗口，标签页留到后面

### 2.1 推荐做法

**照设置窗口的结构：一个不属于任何终端窗口的顶层窗口，启动时建一次，关掉是隐藏。** 左栏群列表
自绘（GDI，内存 DC，照 `strip.rs` 的三条规矩），规则全部来自 `polter-control-room`。右栏第一期不放
真终端，放选中那个群的详情（停因全文、最后一轮的话、动作按钮），「进终端」跳到那个终端所在的窗口和
标签页。

为什么不一上来就做成标签页：

1. **`Tab` 的定义就是一棵终端的分屏树。** `tabs.rs` 里按 pane 或分屏树取东西的地方有 70 处（数的是
   `.panes` / `.tree` 的出现次数），另外 `uia.rs` 4 处、`main.rs` 1 处。让一个标签页没有 pane，这些
   地方每一处都要回答「没有终端时怎么办」，而且答错的表现多半是静默的——焦点落空、关窗口不问、
   会话保存少一页。这是一次对标签页模型的改造，不是加一个界面。
2. **设置窗口已经证明独立顶层窗口这条路走得通**，包括它为什么不能被某个终端窗口拥有（拥有者关掉时
   它跟着被销毁，而这边还拿着句柄）。
3. **文档 §3.4 原本就是这么写的**（「总控台是又一个顶层窗口」）。视觉定稿把它画成第一个标签页，是
   mac 的图；§3.1 的对照表把这一条标成了暂定。

这和 mac 侧不一样：mac 采用「独立控制器、同一种窗口、并进标签组」（`ControlRoomController.swift`），
因为 mac 的每个标签页本来就是一个独立窗口，由系统并成一组，放一个没有终端的窗口进去不动标签页模型。
Windows 的标签栏是宿主自己画的，标签页是宿主自己的数据结构，没有这个便宜可占。

### 2.2 退路与后续

- **如果用户坚持第一期就要它在标签栏里**：做「标签栏上一个固定的入口，点了切到总控台窗口」——标签栏
  最左多画一粒不属于 `tabs` 的按钮，带状态图形。它在视觉上是第一个标签，在模型里不是标签页，不动
  那 70 处。代价是它不能被拖动、不参与「第 N 个标签页」的快捷键。这是一个看起来像但不是的东西，要
  用户点头。
- **真做成标签页**（第二步，等独立窗口稳定以后）：给 `Tab` 的内容加一种「不是终端」的变体，然后把
  §4 列的每一处过一遍。做之前先用一道检查把「按 pane 取东西」的地方穷举出来，逐处写明没有 pane 时
  的答案；不要靠运行时发现。

## 3. 用什么画

**GDI，和宿主其它界面一样；不引入 Direct2D，不用 WebView2。**

- **WebView2 不行**：`plugin_page.rs` 写明运行库在 Server 2022 上默认没有，那边的做法是「没有就在页
  签里说没有」。总控台是头号功能，不能在一部分机器上是一句「安装不完整」。而且那样判断就会跑进
  页面脚本里，「宿主不比较类别」的检查够不着。
- **Direct2D 的好处是真的**（抗锯齿的圆角、半透明、亚像素定位），但它是这个宿主的第二套绘图栈：
  新的特性开关、新的设备丢失处理、新的 DPI 换算，而截图工具已经用 GDI 把圆角和亮暗做出来了。
  **如果 §5 的动画在 GDI 下达不到帧率，再只为总控台这一个窗口引入**，这是有读数以后的决定。
- **图形**（气泡、三角、圆点、转圈）：mac 用系统图标。Windows 上自己画四个 14 单位的路径，按 DPI
  放大；GDI 的多边形和弧没有抗锯齿，办法是先以 4 倍大小画进内存位图再缩小（`StretchBlt` 配
  `HALFTONE`），每个 DPI、每种颜色缓存一份。**这一条没验**：小尺寸下缩出来的边好不好看要上测试机看。
- **文字**：GDI + ClearType，字体走 `uifont.rs`。群名用等宽字体、数字用等宽数字（§3.5 第 8 条），
  GDI 没有「等宽数字」这个开关，要选一款数字等宽的字体或者按位画；这一条是已知的出入。
- **最小字号**：系统菜单字号，`look::font::MIN` 已经守着 13。

## 4. 没有终端的标签页冲击在哪（真做成标签页时）

只在走 §2.2 第二步时才需要。按「错了会怎样」排：

| 哪里 | 现在的假设 | 没有终端时要定的 |
|---|---|---|
| 焦点 | 切到一个标签页 = 把键盘给它的 `focused` pane | 键盘给谁；输入法文档交还给谁（`palette.rs` 写过这份契约） |
| 关闭 | 关标签页会问「里面有进程在跑吗」 | 总控台没有进程，不问；但关整个窗口时别的标签页照问（mac 的 `ControlRoomRules.closeRequest` 就是这件事） |
| 分屏类动作 | 新建分屏、缩放、均分都作用在 pane 上 | 在总控台标签页上按这些键什么都不做，还是转给最近的终端 |
| 「第 N 个标签页」 | 绑定由核心发给一个 surface | 总控台没有 surface，这个键到不了（mac 的 `ControlRoomRules.tabIndex` 为此单独处理了） |
| `poltergeist_grouping` / `terminal_list` | 每个 surface 回答自己在哪个窗口哪个标签页 | 总控台不是终端，不出现在 `terminal_list` 里；但标签页的编号不能因为它而错位 |
| 会话保存与恢复、重开已关的标签页 | 每个标签页存 cwd 和标题 | 存不存它；恢复时它在不在；位置 |
| 项目文件 | 一个项目 = 一组标签页的布局 | 总控台不属于项目，保存时跳过 |
| 拖标签页到别的窗口、拖出成新窗口 | 搬的是 pane 的窗口 | 允不允许；只有一个总控台时拖出去的那个窗口还剩什么 |
| UIA | 标签页下面是终端的文档节点 | 总控台要有自己的提供者（列表、行、按钮），不然读屏软件看到一个空标签页 |
| 标签页上的标记（角色、被护住、被按住） | 取自 `Tab` 的字段，来自它的终端 | 总控台标签页右边画的是整个应用的状态图形，另一条来源 |

## 5. 动画

| 效果 | 定稿 | Windows 上怎么做 | 风险 |
|---|---|---|---|
| 选中片滑动 | 弹簧，周期 0.36 秒、阻尼比 0.72，冲过头约 4% | `layout::spring::progress(t)` 已经在 crate 里（和 mac 同一条曲线）；宿主用 `SetTimer` 16 ms 一帧，只重画新旧两行之间的那一条 | GDI 重画一条 300 宽的带足够快，**没量** |
| 选中片的折射 | 贴边一圈折射它压到的字 | **第一期不做。** GDI 没有便宜的办法；mac 侧这一条也标着「能不能实时做到没验」 | 需要用户接受两边不一样 |
| 等你的图形明暗 | 2.4 秒一轮，100% → 50% → 100%，一个窗口只有一个 | 哪一个明暗由 `pulse::pulsing` 给；宿主用一个 100 ms 的定时器改图形的不透明度（预先缩好的位图配 `AlphaBlend`），只重画那 14 单位见方 | 定时器只在有东西明暗时开着 |
| 在干活的转圈 | 1.2 秒一圈，一格一格跳 | 12 帧位图，100 ms 换一帧 | 同上 |
| 出问题的晃动 | 进入时晃一次，0.3 秒 | 一次性的 16 ms 定时器 | — |

**定时器与「什么都没变时不醒」**（§13.2 第一行）：那一条说的是「不定时取快照」。上面的定时器只在有
图形在动的时候存在，停下来就 `KillTimer`；窗口被遮住或最小化时也停。系统设置关了动画
（`SPI_GETCLIENTAREAANIMATION`）时一个都不开，靠形状和颜色分。验收时要量的是：没有任何群在等、没有
任何群在干活时，60 秒里宿主为这个窗口醒了几次——应当是 0。

## 6. DPI 与亮暗

- **DPI**：`look.rs` 和 `layout.rs` 的数全是设计稿的单位。宿主在画的那一刻乘 `GetDpiForWindow / 96`，
  别处不乘。0.5 的线在 100% 缩放下是半个像素，GDI 画不出来：**100% 下画 1 像素、用更淡的颜色**
  （把线的透明度折进颜色里），150% 以上按四舍五入的像素画。这一条是 Windows 特有的出入，要在
  100% / 125% / 150% / 200% 各看一次。`WM_DPICHANGED` 时丢掉缓存的图形位图和字体重建。
- **亮暗**：`look::theme(dark)` 给整套颜色。「现在是暗吗」读 `AppsUseLightTheme`（截图工具已有读法）
  并在 `WM_SETTINGCHANGE` 时重读；配置里指定了窗口主题的以配置为准。标题栏照 `shell.rs` 的做法设
  `DWMWA_USE_IMMERSIVE_DARK_MODE`。暗色版红字改白字的那几处已经在表里（`problem_text_on_*`），宿主只读
  字段。
- **高对比度模式**没有设计，第一期照系统颜色画、不用自己的色板；这是一条待定。

## 7. 数据怎么来、动作怎么去

- 收到核心的 `CONTROL_ROOM_CHANGED`（`ffi::ACTION_CONTROL_ROOM_CHANGED`，`cb_action` 里现在是一条
  `owed` 分支）→ 调 `ghostty_app_control_snapshot` 取 JSON → `snapshot::decode` → `List::from_snapshot`
  → 重画。解码失败（未知图形、缺字段）**画一行错误，不画空表**。
- 窗口隐藏时收到通知只记下「有新的」，显示时再取。
- 用户的动作 → `act::encode` → `ghostty_app_control_act`；返回假时把错误名交给 `Refusal::parse`，
  用 `message()` 的英文过一遍 `i18n::tr` 显示在那一行上；`means_look_again()` 为真时不等通知，立刻
  重取一次快照。
- 任务栏按钮上的数字：`needs_me`（终端数）。用 `ITaskbarList3::SetOverlayIcon` 画一个带数字的小
  图标，需要给 `windows` crate 加 `Win32_UI_Shell` 里对应的接口；宿主里现在没有任何任务栏代码。
- 通知：第一期不含（主文档 §13.1）。

## 9. 必须上测试机才能验的

mac 上能验的只有 `polter-control-room` 的测试、两道闸和交叉编译；下面每一条都只能在 Windows 上看：

1. 窗口真的开出来、能关、再开是同一个；多显示器下记住的位置还在屏幕上。
2. 四个图形在 100% / 125% / 150% / 200% 下的样子；0.5 的线怎么落像素。
3. 亮暗切换（系统设置里切，窗口开着）。
4. 选中片滑动的帧率，和它是否闪。
5. 没有东西在动时 60 秒里的唤醒次数（§5）。
6. 从 hook 事件到画面的时间（主文档 §13.2）。
7. 批准发的回车、拒绝发的 Esc 真的到了那个终端；提示换了以后点批准被拒绝且没有键发出去。
8. `UserPresent` 与 `DraftInLine` 两种拒绝各造一次，看那一行上写的是什么。
9. 中文输入法在「回一句」的输入框里能用。
10. 读屏软件（讲述人）能读出行和状态。
11. 任务栏数字出现、归零时消失。
12. 测试机是 Server 2022：没有显卡驱动时走的软件渲染对这个窗口没有影响（它不用 OpenGL），但要确认。

## 已经有的

`windows/control-room`（零依赖，`cargo test -p polter-control-room` 在任何机器上都能跑）：

| 模块 | 内容 |
|---|---|
| `look` | 外观表（生成的） |
| `snapshot` | 读核心的快照；未知的图形是错误，不画成空白；不读核心的类别 |
| `list` | 两段、每行说什么、选中怎么移动、重启后的选中 |
| `layout` | 面板里每样东西在哪；时间带的每一段；选中片的弹簧 |
| `pulse` | 哪个等你的图形在明暗；一个窗口标签页带哪个图形、画不画（「在干活」按外观表的暂定项不画） |
| `act` | 用户动作编成请求；每种拒绝说什么 |

两道闸（仓根 `tools/`）：

- `control-room-hosts-agree.py`：同一份夹具，mac 的 `ControlRoomList.swift` 与这个 crate 各算一遍，逐行
  比较，含哪一行/哪个终端在呼吸（`pulses`）、时间带的每一条泳道与每一段的 x 和宽、每一行的 `unseen` 与
  「看了多久算看过」、每个窗口标签页带哪个图形/画不画/呼不呼吸（`tabs`）。没比的：快照顶层的 `now_ms`
  （mac 的列表不留它）、缺 `unseen` 或 `tabs` 的旧快照（mac 当作没有，这个 crate 报错）、「看过」被
  取消的那几种情形（各自的测试管）。
- `control-room-hosts-do-not-decide.py`：两边的源码里不许读核心的类别、不许数行、不许排序。
