# 工具面

Polter 全部四十个 MCP 工具：每个做什么、拒绝什么、哪些是总管专属。这是一份**查阅
材料**，想知道某个调用到底干了什么的时候来看。[README](../README_CN.md#总管能做什么)
里用五段话讲了它的形状，那些足够把东西用起来了。

标 🔑 的是只有总管能调的。

### 看和驱动终端

上面那条可达性规则贯穿这一整组：没标记的终端人人可碰，被监督的和总管本身只有总管
能碰，被用户屏蔽的谁也碰不了。

| 工具               | 说明                                                                                                                                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `terminal_list`    | Polter 已知的所有终端：每块屏幕静止了多久、是否在岗。只给时长 —— 要看内容得 `terminal_read`。                                                                                                                              |
| `terminal_read`    | 读另一个终端的可见屏幕。没有 scrollback，当前这一屏就是全部。                                                                                                                                                              |
| `terminal_send`    | 像键盘前的人一样往终端里打字。控制字符在进来的路上就被剥掉了，所以它按不了 `ctrl+c`。`submit` 默认为 true（自动回车）。                                                                                                    |
| `terminal_key`     | 按一个键，用 Ghostty keybinding 的写法：`ctrl+c`、`escape`、`f2`、`arrow_down`。这是唯一的打断手段。普通字符 `a` 在这里会被拒 —— 那是 `terminal_send` 的活。                                                                |
| `terminal_keys`    | `terminal_key` 接受的完整词汇表（所有修饰键名和键名）。别猜名字，读这个。                                                                                                                                                  |
| `terminal_action`  | 做菜单栏能做的事：`new_tab`、`close_surface`、`toggle_fullscreen`、`copy_to_clipboard`、`increase_font_size:1`、`goto_split:left`、`new_split:right`、`inspector:toggle`。`close_surface` 可能返回 `AwaitingConfirmation` —— 一个没标记、里面还跑着东西的终端，会跟人点关闭时一样弹确认，而这里谁也按不了那个按钮。你自己在盯的终端则直接关。 |
| `terminal_actions` | `terminal_action` 全部可用的动作，以及哪些需要在冒号后面带值。                                                                                                                                                             |
| `terminal_open` 🔑 | 在本窗口开一个新终端，起始目录由你指定（`cwd` 必须是存在的绝对路径；不存在直接拒，而不是悄悄开到别处去）。比 `new_tab` 强：后者只能继承发起者所在的目录，四份工作在四个目录里根本没法那样铺开。`watch: true` 可以从它诞生的那一刻就纳入监管。回包里带 `id` 说明终端在调用返回前就已就绪；没有 `id` 则稍后它会出现在 `terminal_list` 里。 |

### 说话和留痕

| 工具                 | 说明                                                                                                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `group_create` 🔑    | 建一个终端们说话的群（名字用小写字母、数字、短横）。建群的人自动是成员。                                                                                                                      |
| `group_destroy` 🔑   | 把群从名单上拿掉。磁盘上的日志一天不少地留着，走的只是群、成员和任务。群里还有终端开着时返回 `GroupActive` —— 先 `group_remove` 把人挪出去，包括你自己。                                       |
| `group_add` 🔑       | 把一个终端拉进群。`history: none` 表示从此刻开始，`all` 表示把日志里还留着的全给它。                                                                                                          |
| `group_remove` 🔑    | 把一个终端移出群。                                                                                                                                                                            |
| `group_members`      | 群里有谁、各自当前叫什么。派活前值得先看一眼：不在群里的终端，这个群够不着。                                                                                                                  |
| `group_post`         | 在你所在的群里发言。别人只被告知「有消息」，什么时候读由它自己决定。                                                                                                                          |
| `group_read`         | 读你还没看过的消息。把上次的 `seq` 传给 `since` 续读。标着 `summary` 的那条，代表被压缩掉的一批旧消息。                                                                                       |
| `group_list`         | 你在哪些群里。                                                                                                                                                                                |
| `group_history`      | 翻比内存里更早的记录（从磁盘日志读）。用 `before_seq` 传你见过的最小 `log_seq` 来翻页；`more: false` 表示已经到底。这里的群内 `seq` 恒为 0 —— 日志不记它。**可检索**：`match` 按正文子串匹配（ASCII 大小写不敏感），`since_ms` / `until_ms` 按墙上时间划范围。这是被压缩掉的内容唯一的取回路径 —— 没有它，为找昨夜的一句话就得把整夜翻一遍，翻进的正是压缩本来要省出来的 context。 |
| `group_compact` 🔑   | 把 `through` 之前的消息替换成你写的一段摘要。相当于给一场对话做 `/compact`。                                                                                                                  |
| `group_set_brief` 🔑 | 用自己的话写清「这个群是干嘛的」。建完群立刻写 —— 八小时后 `group_list` 只剩一个你认不出的名字，而那正是你要判断它还要不要盯的时刻。只有你和键盘前的人看得到，成员看不到。                    |

### 任务面板

面板是唯一能扛过重启、上下文压缩和整个夜晚的东西。派活是四步：`task_create` →
`group_post` 留档 → `terminal_send` 下达真正的指令 → `task_assign`。

| 工具              | 说明                                                                                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `task_create` 🔑  | 往一个群的面板上放一行字，返回任务号。验收标准和细节写进你发给工人的那条消息里，不写在这儿。只能在你自己建的群里建。                                                            |
| `task_assign` 🔑  | 指定哪个终端负责。**会往那个终端打一行字说这个任务归它了，然后面板才记下来** —— 一次没人被告知的指派，是只有你自己看得见的状态，而群也替你捎不到：被监管的终端不被群消息唤醒。**要读回包**：终端没被告知到，就什么都没指派。活**是什么**仍然由你自己 `terminal_send`，Polter 打的那行只说任务号和标题。id 传 `0` 表示收回，没有人要告知，所以不打字。 |
| `task_close` 🔑   | 活干完了、而且你查过了。不会向工人发送任何东西：它做完、它报告，这只是你点头。关闭后仍留在面板上供早上回看，但从工人自己的 `task_list` 里消失。                                  |
| `task_cancel` 🔑  | 撤销一个任务。**会往工人终端里打一行字让它停下，然后任务才离开它的列表** —— 否则它没有理由再去看面板，会一直做着没人要的东西。**要读回包**：它告诉你工人是否真的被通知到。终端已经没了则直接拒绝、任务保持开启，而不是假装成功。 |
| `task_progress`   | 推进自己的任务：`queued` / `working` / `blocked` / `done`。只能动自己的，且只在开启状态 —— 已关闭或已取消的会拒，这正是你发现自己漏掉一次取消的方式。一 `blocked` 就立刻标上，那是总管唯一在等的信号。`done` 只表示你认为完成了，「关闭」是总管查完之后的用词。同时在群里报一声，带上任务号。 |
| `task_list`       | 群里的任务。看到什么取决于你是谁：总管拿到整个面板（含已关闭、已取消），其他人只拿到自己还开着的任务。这不是限制，而是重点 —— 同僚在干嘛不该占你的 context。                    |
| `task_history`    | 不是面板现在写着什么，而是**它什么时候变成这样的**：每一次创建、指派、进度、关闭、取消，各自带时间。`task_list` 回答「现在到哪了」，这个回答「昨晚发生了什么」—— 问错一次之后，该用哪个通常就清楚了。翻页方式和群消息一样。 |

### 身份与在岗

| 工具                | 说明                                                                                                                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `me`                | 你在哪个终端里，以及你是在监管别人还是被监管。                                                                                                                                          |
| `become_supervisor` | 自荐当总管 —— 看见有活需要人协调而没人在做的时候用。无参数，因为它说的是你自己。没人盯着你时允许；正被 watch 时拒绝 —— 你已经有总管了，而且流进一个被监管终端的文字，绝不能重排谁能够到谁。这时该问你的总管或者用户。 |
| `stand_down` 🔑     | 卸任，在你盯的活干完之后。先用 `set_watch(id, false)` 逐个把终端放掉；还盯着任何一个就会被拒。动手前先在群里说明你要收工以及原因，因为之后你无法自我任命，只有用户能再任命你。如果用户声明过这个资格只能由他撤销，这里会返回 `StandingInstruction` —— 正确做法是把这句话说出来，而不是另找路子。 |
| `clock_out` 🔑      | 标记某个终端今天收工，它安静下来就不再被上报。用户正按住不许它下班的终端会拒。                                                                                                          |
| `clock_in` 🔑       | 让一个终端重新上岗。                                                                                                                                                                    |

### 监视与通知

| 工具                          | 说明                                                                                                                                                                        |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `set_watch` 🔑                | 把一个终端纳入监管，或者放掉。watch 会让它的静止期进入你的 `notices`，同时给这个终端打上标记 —— 那才是非总管从此够不到它的原因。注意 watch **不是**你能读它的原因：任何总管都能读写任意终端。`watch` 参数必填、且必须原样拼写；写错的参数会被拒而不是被忽略，因为两个方向的可撤销难度并不对等。 |
| `set_quiescence_threshold` 🔑 | 某个终端要静止多久才算「安静」并被上报（毫秒）。                                                                                                                            |
| `notices` 🔑                  | 还没给你看过的事：谁安静了、安静了多久，谁又回来干活了。读了即清，同一件不会推第二次。系统也会定时塞给你，但更好的做法是每做完一件事就自己调一次，而不是等着被打断。       |
| `notify_user` 🔑              | 请求通知真人。`reason: authorisation` 用于终端卡在权限确认上 —— 那种问题没人能替它回答，所以任何时间都发。`reason: scheduling` 用于你本可以自己决定的问题（继续 / 换方向 / 放弃），这类在用户设定的免打扰时段会被压下并交还给你自己决定。**要读回包**：它说明消息是否真的发出去了。 |

### 插件与配置

| 工具                  | 说明                                                                                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plugin_list` 🔑      | 装了哪些插件、是否开启、各自吃什么参数。已配置的值不会明文回传：写成引用（`env:`、`file:`、`keychain:`、`cmd:`）的按用户原样显示 —— 秘密存在哪儿本身不是秘密 —— 明文填进去的只报告「已设置」。常驻运行的聊天存档还会给出进度和健康度。 |
| `plugin_configure` 🔑 | 开启插件并设置参数。凭据只能给引用；插件标为 secret 的参数会拒收明文，并且会告诉你。`cmd:` 引用一律拒绝：那是 Polter 日后自行执行的一条命令，跑在授权你此刻行为的范围之外，所以你只描述那行命令，让用户自己写。**关闭**插件同样被拒 —— 那是用户听消息的通道。读回包看改动是即时生效还是要重启。 |
| `plugin_test` 🔑      | 在真正需要它的那个夜晚之前先验证插件。通知类插件会真的发出一条（用 Polter 自己的措辞，不管当时几点）—— 所以只刻意用一次。聊天存档不会被启动第二份，回来的是正在运行那份的近况，而那通常正是「为什么什么都没归档」的答案。 |
| `config_get` 🔑       | 读用户的配置 —— `poltergeist-notice-interval`、`poltergeist-notify-window`、`poltergeist-supervisor-stand-down`，不传 key 则全给（很长，按对话预算截断）。只读。值得在被拒之前先读一遍：不可打扰的时段、以及你能否自行卸任，都写在这儿。 |

### 跨重启恢复，以及 skill

| 工具                | 说明                                                                                                                                                                                |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session_recall` 🔑 | 重启前写下的昨夜安排：有哪些群、各自是干嘛的、每个终端在哪个目录工作、叫什么名字。重启后第一件事读它，然后对照现在开着的终端，自己判断谁是谁 —— 这里没有任何东西替你做这个匹配，猜错会把 A 的监管悄无声息地挂到 B 头上。 |
| `skill_read`        | 按 `name` 读 Polter 自带 skill 的正文。从 `supervising` 开始。                                                                                                                       |

### 随构建装的三份 skill

判断力写在 Markdown 里，不写在二进制里。一共三份，都能用 `skill_read` 读到：

| Skill                  | 什么时候用                                                                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `supervising`          | 当总管：建群分派任务、按屏幕静止时长判断谁卡住了、决定该催还是该等、把安排写下来以便重启后恢复。从这份开始读。                                                     |
| `reading-a-terminal`   | 从终端屏幕上的内容判断里面的 agent 处于什么状态 —— 在想、卡在提示上、等授权、已经做完、还是真的死了。收到「某终端已静止」的报告、准备决定要不要打扰它时用，配合 `terminal_read`。 |
| `operating-a-terminal` | 给不是总管、但要碰同窗口另一个终端的 agent：先看 `terminal_list` 里的标记再动手，怎么打字、怎么用 `ctrl+c` 打断、怎么把一个服务停掉再起来，以及被拒绝了是为什么。   |

`$XDG_CONFIG_HOME/polter/skills/<name>.md` 下的副本会优先于随装的那份被读取，所以
改一个文件就是改 Polter 怎么当总管，不用动安装目录。`claude-code` 插件还会把它们
镜像到 `~/.claude/skills/polter-*` —— 那才是 Claude Code 能按名字用上它们的原因。
